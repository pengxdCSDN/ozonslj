# PostgreSQL SQL 编写与注释规范

本目录是 ozonslj 运行时数据库结构的唯一事实来源，也是后续 RAG 检索的重要知识源。

每个新增或修改的迁移必须使用简体中文说明：

1. 表的业务职责、数据所有者、工作区隔离边界和生命周期。
2. 主键、业务唯一键、UPSERT 冲突键及选择原因。
3. 外键删除策略、允许为空的原因及跨工作区约束。
4. 状态、金额、时间、JSON、计数等字段的业务语义和单位。
5. 同步水位、分页游标、快照软失效以及失败时不得发生的状态变化。
6. 索引服务的查询形态、列顺序原因和可能的写入成本。
7. 敏感字段、脱敏规则，以及明确禁止写入 SQL、日志、RAG 和 API 的内容。
8. 迁移兼容性、回滚边界和大表操作风险。

优先使用 PostgreSQL `COMMENT ON TABLE/COLUMN/CONSTRAINT/FUNCTION`，使说明随结构进入数据库，
可通过系统目录检索。复杂的不变量、迁移步骤和设计背景再使用相邻块注释补充。

注释必须解释“业务含义和设计原因”，避免只把字段名翻译成中文，也不得包含真实凭据、
客户个人信息、服务器密码或其他秘密。
