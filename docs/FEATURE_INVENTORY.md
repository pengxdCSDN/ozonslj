# ozonslj 全功能点与开发状态清单

> 文档版本：V1  
> 盘点日期：2026-08-07  
> 盘点依据：当前仓库代码、自动化测试、`REQUIREMENTS.md`、`ARCHITECTURE.md`、`API.md` 与 `PROJECT_PLAN.md`  
> 用途：作为产品功能、页面建设和后续开发排期的统一清单；状态以实际代码闭环为准。

## 1. 状态口径

| 状态 | 判定标准 |
|---|---|
| 已开发 | 前后端或运行组件已形成当前阶段可用闭环，并有相应自动化测试或构建验证 |
| 部分开发 | 仅完成接口、数据库、领域规则、Stub、单层 UI 或基础设施，尚未形成用户可用闭环 |
| 未开发 | 当前仓库没有对应实现，或只有需求描述 |

页面按用户可独立进入并完成一类任务的“一级功能视图”统计。弹窗、抽屉、列表详情和同页标签不重复计页；当前 React 应用虽然没有路由文件，六个顶层视图仍分别计为六个页面。

### 5.3 卖家工作区

### 5.4 运营事实

已并行接入库存仓位、客户订单和 FBO/FBS 履约三个 PostgreSQL 查询接口，提供数量摘要和最近事实列表。当前三个领域合并为一个一级页面；后续数据量和操作复杂度达到拆页条件时，再拆为独立页面。

## 6. 建议的后续开发顺序

1. 完成真实 Seller 商品/库存同步处理器，并在云端验证 Scheduler、Worker 进程。
2. 将库存仓位、订单、FBO/FBS 履约、同步任务和审计接口接入前端，先把已有后端能力变成可用页面。
3. 完成数据质量规则和搜索词导入，为选品数据可信度打底。

6. 最后建设人工审核、价格受控写入、回读和审计闭环。
