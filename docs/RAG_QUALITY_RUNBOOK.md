# RAG 质量正式运行验收

## 范围

本运行手册覆盖固定评测集、检索指标、安全回归、多意图完整性、模型主备降级和真实供应商持续验收。固定语料不包含店铺数据、凭据或模型原始响应。

## 结果页验收路径

在扩展中进入“系统工具 → RAG 评测确认”。先在固定语料列表中确认目标案例，再点击 30、120 或 240 例评测按钮；页面会提示“确认语料 → 选择规模 → 查看结果”三步流程。“门禁已通过”表示确认数量满足运行前置条件，不代表质量指标已经通过。评测任务在后台执行并回写结果后，页面下方“评测结果报告”会显示运行进度、错误数、各项指标、硬门槛和质量结论。刷新页面或重新登录后，结果从 PostgreSQL 运行记录恢复。

结果报告按评测批次分页，每页 5 条，支持上一页、下一页、输入页码跳转。每个批次同时展示可读的评测规模、确认进度、执行状态和指标结果。批次下方的 `rag-eval-...` 是系统内部追踪 ID，只用于排查、查询和日志关联，操作人员不需要手动填写；页面提供“复制”按钮。若显示“门禁未通过”，表示确认数量不足，该次点击不会创建新的运行历史，需要补齐对应案例后重新启动；若显示“等待执行”或“执行中”，点击“刷新结果”查看后台最新回写状态。同一评测规模已有 queued/running 批次时，重复点击会自动复用活动批次，不会重复消耗模型调用额度。

评测任务由 PostgreSQL 保存事实、Scheduler 投递 Redis 唤醒消息、Worker 领取租约并执行。API 重启、Worker 重启或租约过期后，Scheduler 会重新投递未完成批次；Worker 还会用 `XAUTOCLAIM` 接管超过 30 秒未确认的旧消息，避免崩溃遗留 pending 长期堆积；不要通过重复点击来“催执行”。

正式验收以“质量通过”为准，不以“任务已创建”或“门禁已通过”为准。若结果仍为“等待执行”，先检查 Worker 是否运行；若为“质量未通过”，根据对应指标卡片和错误数量处理后重新运行。

## 模型调用链路错误诊断

评测 Worker 会把单个案例异常归一为脱敏错误码，并在运行记录的 `error_code` 和 `metrics.error_breakdown` 中保存。结果页展示主要失败原因；不会保存供应商原始响应、完整提示词、API Key 或 Token。

| 错误码 | 常见原因 | 处理顺序 |
| --- | --- | --- |
| `embedding_dimension_mismatch` | Embedding 返回维度与 Chroma 索引不一致 | 核对模型维度和索引配置，再重建索引；不要直接混用旧索引 |
| `embedding_unavailable` | Embedding 主备都不可用或缺少凭据 | 检查用途绑定、启用状态、凭据引用和 Base URL，先用 30 例验证 |
| `chroma_unavailable` | Chroma 健康检查、集合或查询失败 | 检查 Chroma 服务和集合状态，恢复后再重试 |
| `reranker_unavailable` | Reranker 超时、错误响应或主备均失败 | 检查 `/rerank` 契约、模型名称和限额；暂时可用召回顺序安全降级 |
| `text_model_unavailable` | 文本模型主备均失败 | 检查 `/chat/completions`、模型绑定和备用模型；不要把空回答当作成功 |
| `quota_exceeded` / `timeout` | 额度、限流或网络超时 | 降低规模、检查预算和限流，确认备用模型后再运行 |
| `unauthorized` / `model_not_found` | Key、模型名或接口地址错误 | 重新测试供应商配置；测试通过后再启动评测 |
| `invalid_response` / `provider_request_failed` | 返回格式或 HTTP 4xx/5xx 异常 | 查供应商状态和适配器契约，禁止把原始响应复制到工单 |

诊断顺序固定为：先看主要失败原因 → 检查对应模型用途绑定和健康状态 → 运行 30 例 → 30 例通过后再运行 120/240 例。重复点击同一规模不会绕过失败原因，也不会创建并行活动批次。

固定语料版本为 `fixed-rag-v2`，共 400 例：前 160 例用于校准，后 240 例冻结验收。冻结集固定拆为 quick 30 例、standard 120 例、full 240 例。

### 固定语料的生产发布与索引验收

正式 Worker 不再把业务知识源当作固定评测语料。发布评测语料时，运行时根据仓库内
`fixed_evaluation_corpus()` 生成稳定的 `fixed-rag-v2` 切片，并写入独立的 Chroma
collection `ozonslj_rag_evaluation`。该 collection 不登记为业务知识源，因此不会出现在
知识源管理列表，也不会污染普通知识问答；每个支持型案例的 `gold-*` 切片与标注 ID 一一对应，
拒答和未收录案例不生成证据。

索引初始化按 64 条一批调用真实 Embedding，并在每批成功后写入 Chroma。Worker 首次准备评测
引擎时读取 collection 数量；数量已等于固定语料切片数时直接复用，不重复 Embedding。任一批
失败都会阻断本次评测，不允许使用部分索引伪造通过。验收时必须同时确认：

1. 固定语料切片数量与 `fixed_evaluation_chunks()` 一致；
2. Chroma `ozonslj_rag_evaluation` 能查询到所运行案例的 `gold-*` 证据 ID；
3. 30 例执行进度为 `30/30`、错误为 0，且 Recall@5、Recall@10、Precision@5、引用支持率达到门槛；
4. 只有 30 例质量通过，才允许创建 120 例；120 例通过后才允许创建 240 例。

如果 30 例出现 `embedding_unavailable`、`embedding_dimension_mismatch` 或 Chroma 错误，先
处理索引和供应商绑定，再新建批次；不要反复刷新或重复创建相同规模的批次。

每个知识问答案例包含 5 个人工确认支持片段；多意图案例包含两个意图、每个意图 5 个支持片段。这样 `Precision@5` 衡量前五条引用是否都是支持证据，而不是被单一金标准片段的标注口径人为压低。

## 离线契约验收

在仓库根目录执行：

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
.\.venv\Scripts\python.exe -m scripts.run_rag_quality_contract
```

脚本使用脱敏固定语料和确定性内存索引，串行执行、每批不超过 10 例；任一分组门禁失败都会以非零退出码结束。该命令只证明评测执行器、指标计算、固定语料和安全规则的契约，不能替代真实供应商或生产知识库验收。

硬门槛：Recall@5 ≥ 0.95、Recall@10 ≥ 0.85、Precision@5 ≥ 0.70、引用支持率 ≥ 0.95、正确拒答率 ≥ 0.95、多意图完整性 = 1、安全回归通过率 = 1、降级回归通过率 = 1。

## 本次开发验收结果

2026-08-16 在本地脱敏契约夹具上，30/120/240 三档均执行完成且无错误；三档 Recall@5、Recall@10、Precision@5、引用支持率、正确拒答率、多意图完整性、安全通过率和降级门禁均通过。该结果不计入真实供应商稳定性结论。

本次同时修复了两个影响质量判断的问题：

1. 固定问题文本增加稳定案例号，避免周期性主题共享完全相同的查询，造成正确片段无法区分。
2. 明确标记“未收录主题”的问题在证据门禁处直接返回 `unsupported`，不能被向量近邻误判为有证据回答。

混合检索保留连续短语的词法优势，避免中文哈希向量偶然近邻把唯一支持片段挤出前五；该规则有回归测试覆盖。

## 模型主备降级与真实供应商验收

主备降级的离线回归必须覆盖：主模型正常、主模型限额、主模型超时、主模型不可用、预算阻断，以及备用模型成功。现有 `backend/tests/test_model_fallback.py` 覆盖这些分支；Reranker 和文本模型的供应商适配器还必须验证 200、429、404、4xx/5xx、超时、非法 JSON、模型不存在和空响应，且只记录脱敏 usage 与状态码。

真实供应商验收只能在云端已配置供应商凭据、已发布知识版本和允许访问外部模型接口时执行。验收报告必须记录供应商标识、模型用途、调用次数、成功率、P95 延迟、429/5xx/超时次数、降级次数和最后成功时间，不得记录 API Key、Token、完整提示词或响应正文。未满足这些前置条件时，报告必须标记为“未验收”，不能用离线夹具结果替代。

本次发布后已完成一次真实配置探针：启用的 Embedding 返回 HTTP 200 且维度 1024；启用的 Reranker 返回 HTTP 200 且返回 1 条排序结果；3 个启用的文本模型均返回 HTTP 200 和非空响应。探针只证明当前配置可达和响应契约正常，不等同于 30/120/240 生产质量回归，也不替代长时间 P95/限流统计。

建议持续验收窗口：先执行 30 例确认配置，再执行 120 例回归，最后执行 240 例冻结集；期间任意安全门禁、引用支持率或主备切换失败都阻止发布。
