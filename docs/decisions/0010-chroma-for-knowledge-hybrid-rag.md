# ADR-0010：使用独立 Chroma 服务建设知识型混合 RAG

- 状态：已接受
- 日期：2026-08-11
- 关联：[RAG 需求](../RAG_REQUIREMENTS.md)、[RAG 技术架构](../RAG_ARCHITECTURE.md)

## 背景

首个智能运营能力需要先建立可引用、可拒答的知识底座。仅使用 PostgreSQL 中文注释或关键词检索不能覆盖跨语言、近义表达和长篇 SOP 的语义召回；把实时经营事实向量化又会破坏时效、权限和事实口径。旧 V6 因 2 核 2GB 资源约束规定首期不引入向量数据库，但新的产品决定将向量检索列为首期硬性要求。

## 决策

知识型混合 RAG 使用 PostgreSQL 精确/全文检索与 Chroma 语义向量检索。PostgreSQL 是知识文档、版本、切片目录、发布状态、权限、引用和索引任务的唯一治理事实来源；Chroma 只保存允许检索的非敏感切片向量和最少过滤元数据，不保存唯一业务或知识事实。

开发服务器运行固定版本、单副本、仅内网可访问的独立 Chroma 容器，使用独立持久化卷，初始内存上限 256MB。服务器只拉取镜像，不在 2GB 节点本地构建。Chroma 数据不纳入 PostgreSQL 一致性备份；索引丢失、漂移或版本变化时，从 PostgreSQL 已发布知识版本幂等重建。

## 后果

- V6 的“首期不引入向量数据库”约束被本 ADR 针对知识型 RAG 明确替代；Kubernetes、微服务集群和独立业务数据库仍不在首期范围。
- API 和 RAG 索引 Worker 通过内网服务访问 Chroma，不能让多个进程直接共享嵌入式索引文件。
- Chroma 不提供 PostgreSQL RLS，权限和状态必须在摄取、检索候选过滤及最终引用校验多层执行。
- Chroma 不可用时可以明确降级为 PostgreSQL 精确检索，但不得宣称已执行完整混合检索。
- 上线前必须在现有服务器总内存预算内压测；持续 Swap、OOM 或影响核心 API/数据库时停止上线并重新分配资源或迁移 Chroma。
