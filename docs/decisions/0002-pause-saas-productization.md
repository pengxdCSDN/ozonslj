# ADR-0002：暂停 SaaS 产品化，回归运营功能主线

- 状态：已接受
- 日期：2026-08-04
- 关联：[需求](../REQUIREMENTS.md)、[架构](../ARCHITECTURE.md)、[项目计划](../PROJECT_PLAN.md)

## 背景

ozonslj 当前服务同一运营团队。此前按多组织 SaaS 推演出的组织注册、切换、邀请、成员目录和复杂授权管理，已经超出当前运营系统的实际需要，并挤占商品、库存、订单、履约、选品和广告分析的开发进度。

## 决策

当前产品按单组织运营系统交付，暂停 SaaS 产品化。登录只使用邮箱和密码，部署通过 `DEFAULT_ORGANIZATION_ID` 绑定内部组织；客户端不显示或选择组织。

不开发组织注册、组织切换、成员邀请、组织目录、组织套餐、复杂工作区成员管理及其 API/UI。已有 PostgreSQL `organization_id`、成员关系、约束和 RLS 作为内部纵深隔离基础保留，不把它们解释为当前产品功能，也不继续扩展组织管理适配器。

开发资源回到运营主线：Seller 商品、库存、订单、FBO/FBS 履约、同步恢复、选品、Listing、广告诊断、报告和只读 Agent。

## 后果

- 运营人员无需理解或维护组织概念，登录和日常操作更简单。
- 已有数据库隔离结构不做破坏性回退，避免无业务收益的迁移风险。
- 任何 SaaS 产品化需求必须重新提出、单独确认并重新排期，不能从内部 `organization_id` 自动派生。
- 代码评审和计划评审应拒绝与当前运营主线无关的组织管理扩张。
