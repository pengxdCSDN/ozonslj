# ADR-0008：同步任务操作返回后续轮询提示

## 状态

已采用。

## 决策

创建、取消和重试同步任务的响应统一返回 `Retry-After: 2`。重试成功时额外返回任务资源的 `Location`。

## 原因

扩展端采用短轮询读取 PostgreSQL 中的任务事实，不直接读取 Redis。统一响应头可以让前端、桌面端和后续其他客户端遵循同一轮询节奏，避免在任务尚未完成时产生无边界请求。

## 边界

- 响应头只描述建议轮询间隔，不代表任务已经执行或完成。
- 任务最终状态仍以 `GET /v1/sync-jobs/{id}` 返回的 PostgreSQL 事实为准。
- 失败、部分成功和取消不会自动重试；人工重试必须再次调用受控接口。
