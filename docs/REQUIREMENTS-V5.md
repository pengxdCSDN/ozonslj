# ozonslj 产品需求文档 V5

> 版本：V5.1  
> 日期：2026-08-04  
> 状态：已确认  
> 适用范围：Web、Chrome 扩展、FastAPI、Worker、Scheduler、PostgreSQL、Redis、Ozon Seller API、Ozon Performance API、运营资料导入、合规公开采样及后期智能体

## 1. 版本说明

V5 在 V4 已确认的工作区、可信数据、日常运营闭环和受控写入原则上，将产品扩展为供当前运营团队使用的 Ozon 智能运营工作台。当前版本不建设多组织 SaaS 产品。

本版主要变化：

1. 引入 Seller API、Performance API、运营资料导入和合规公开采样四类数据入口。
2. 将选品 Skill、Listing Skill、广告 Skill 和多 Agent 协同确定为 V5 重点。
3. 允许建设合规、限速、可关闭的公开页面采样层，替代 V4“完全不建设公开网页采集”的决定。
4. 明确不引入付费第三方市场数据订阅作为核心依赖。
5. AI 与 Agent 永久只读，只能生成分析、草稿、报告、建议、告警和待审核请求。
6. 所有外部写入统一经过数据新鲜度校验、差异预览、风险限制、人工确认、幂等执行、回读和审计。
7. 模块三仅预留 ERP 适配端口，首期不接入领星或其他具体 ERP；采购、成本和在途资料先通过 CSV/XLSX 导入。

除本文明确替换的决定外，V4 已确认的经营驾驶舱、异常待办、账户与工作区、同步、商品、库存、订单、履约、售后、利润、规则、通知、知识和智能体安全要求继续有效。

## 2. 产品定位、目标与指标

ozonslj 连接卖家自有 Ozon 店铺事实、广告数据、运营资料和合规公开样本，通过“发现问题或机会—分析影响—生成建议—人工审核—受控执行—回读结果—效果复盘”形成运营闭环。

产品原则：

- 只服务 Ozon，不把跨平台 ERP 或付费市场数据服务作为首期依赖。
- 用可信数据替代人工抄录，用异常和机会排序替代无目标巡店。
- 用贡献利润而非单一销售额约束选品、价格、广告和促销。
- 所有结论携带工作区、时间范围、币种、数据来源、计算口径和不确定性。
- 官方事实、人工导入、公开样本和系统估算在存储、接口和界面中明确区分。
- 模型输出不构成授权，提示词不能改变权限、隔离和审核边界。

首批产品指标：

| 目标 | 指标口径 | 首批目标 |
|---|---|---:|
| 降低巡店成本 | 每日人工巡店耗时 | 下降 50% |
| 提高异常响应 | 严重异常从同步完成到生成待办 | 不超过 5 分钟 |
| 提高数据可信度 | 业务结论含来源、时间和口径的覆盖率 | 100% |
| 提高选品效率 | 搜索词与竞品资料齐备后生成决策书草稿 | 不超过 10 分钟，不含外部采集等待 |
| 保证操作安全 | 高风险写入完成预览、确认、幂等、回读和审计 | 100% |
| 控制采集风险 | 禁止策略生效后继续发出的请求 | 0 |
| 控制资源占用 | 核心服务在既定云服务器预算内稳定运行 | 无持续 Swap 压力或 OOM |

目标值支持按部署或工作区配置，不写死为不可调整常量。

## 3. 用户与权限

### 3.1 当前用户范围

- 当前系统只服务同一运营团队，部署绑定一个内部组织，用户无须创建、选择或切换组织。
- 登录只需要邮箱和密码；组织标识由服务端配置，客户端不能提交或覆盖。
- 一个部署可以连接多个 Ozon 卖家账户，并以店铺工作区区分商品、库存、订单、履约、报告和操作记录。
- 当前不开发组织注册、组织切换、成员邀请、成员目录、组织套餐、组织设置或复杂工作区成员授权 API/UI。
- 工作区停用后禁止新同步、采集、Agent 运行和外部写入，历史事实、报告、任务和审计继续保留。
- PostgreSQL 中已有的 `organization_id`、成员关系与 RLS 仅作为内部数据隔离和未来迁移保护保留，不构成当前产品功能或开发任务。

### 3.2 当前权限范围

- 当前只保留登录、运营功能访问、卖家凭据管理和高风险操作审核所必需的权限判断。
- 运营人员可以查看商品、库存、订单、履约、选品、Listing、广告分析、报告和待办。
- 卖家凭据只允许受信任的管理员维护，浏览器端不得保存凭据。
- 价格、库存、广告等外部写入仍必须经过预览、风险检查、人工确认、幂等执行、回读和审计。
- 智能运营助手继承当前登录用户的只读数据范围，无 SQL、无凭据、无独立超级权限、无写适配器。
- 如未来确需多组织 SaaS、复杂角色或成员管理，必须重新形成需求、确认范围并单独排期，不能从内部数据库结构自动派生。

## 4. 数据底座与可信度

### 4.1 数据来源

| 来源 | 数据范围 | 来源标签 | 使用边界 |
|---|---|---|---|
| Ozon Seller API | 自有商品、价格、库存、订单、履约、财务和销售分析 | `official_private` | 店铺运营事实 |
| Ozon Performance API | 广告活动、关键词、否定词和效果报表 | `official_private` | 广告分析 |
| 运营资料导入 | 搜索词、成本、采购、在途、目标和词表 | `operator_imported` | 补充业务事实 |
| 公开页面采样 | 标题、价格、评分、评价数、主图和公开属性 | `public_sample` | 竞品与类目样本 |
| 系统计算 | 市场估算、利润、机会评分和建议 | `derived_estimate` | 决策辅助 |

### 4.2 可信度与数据时间

- 官方事实、人工导入、公开样本和推导结果分开存储，不用公开估算静默覆盖官方事实。
- 系统不得宣称零成本获得全市场精确历史销量、损失销售额或完整搜索排名历史。
- 公开样本显示采样时间、样本数量、覆盖范围和估算属性。
- 数据不足时显示缺失项和置信限制，不用隐藏默认值输出精确结论。
- 金额使用最小货币单位整数，币种使用 ISO 4217 三位大写代码，外部编号按文本保存。
- 业务时间使用 UTC `timestamptz`，界面按用户时区显示；首批经营报表默认 `Asia/Shanghai`。
- 每个数据域显示统计窗口、最后成功同步时间、延迟、记录数和错误摘要。
- 研究、建议和审核请求冻结所引用的数据版本；数据过期后重新计算或重新确认。

### 4.3 数据质量

数据质量中心覆盖：

- 缺失字段、未知枚举、孤儿关系和跨来源不一致。
- 币种异常、负库存、时间倒退和价格异常。
- 评分为 0 但存在评价、未来时间和非法 URL。
- 页面结构变化、响应类型异常、解析失败和字段缺失。
- 公开样本价格偏离样本中位数超过 10 倍时标记异常，不直接进入聚合结论。

异常数据进入隔离或质量中心，不静默参与分析。

## 5. 七模块总览（SOP 映射）

| 模块 | 原 SOP 做法 | Ozon 改造 | V5 状态 |

| 二·数据接入 | 第三方运营工具/MCP | Seller API、Performance API、搜索词导入和公开采样 | 地基 |
| 三·店铺打通 | ERP / SP-API | Seller API 为主，预留 ERP 适配端口 | 必需 |
| 四·选品 Skill | explore / validate / expand | 搜索词报告、公开样本和自有分析三源融合 | V5 重点 |
| 五·Listing Skill | 关键词分层、FABE、五点 | 俄语 SEO、Smart Search 和风险词检测 | V5 重点 |
| 六·广告 Skill | SP 广告、否定词、预算日历 | 搜索广告、模板广告、登上顶端和 Performance API | V5 重点 |
| 七·多 Agent 协同 | 销售、库存、广告 Agent | Ozon 监控 Agent、竞品/选品 Agent、汇总与通知 | V5 重点 |

## 6. 模块一至三：基础能力

### 6.1 模块一：基础环境

- Web 与 Chrome 扩展共享 React 组件、API 类型和业务状态。
- 后端采用 FastAPI 模块化单体；API、Worker、Scheduler 使用同一代码库的不同进程入口。
- PostgreSQL 是唯一业务数据库；Redis 只保存队列、锁、限流和可恢复短期状态。
- Stub/Mock 是本地开发和自动化测试的默认外部数据源。
- Ozon 凭据只在后端短暂解密和使用，不进入浏览器、任务消息、日志、审计或响应。

### 6.2 模块二：数据接入

- Seller API 与 Performance API 使用独立凭据、认证流程、服务域名、限流桶和错误映射。
- 搜索词、采购、成本和在途资料支持 CSV/XLSX 导入。
- 公开采样只处理获准的竞品种子，不接受任意 URL 透传。
- 上游传输模型先映射为内部模型，不直接暴露给领域层或前端。
- 每个真实适配器实施前复核官方路径、版本、权限、请求、响应、分页、限流和错误语义。

### 6.3 模块三：店铺打通

- 真实同步顺序为“商品/价格 → 库存 → 订单 → FBO/FBS 履约”。
- 同步采用首次有限全量、时间窗口增量、状态快照和周期性对账。
- 任务支持持久化、幂等、租约、心跳、取消、恢复、重试和部分失败。
- PostgreSQL 保存任务事实、水位和结果；Redis 丢失后可恢复排队和超时任务。
- 失败或部分成功不推进长期水位，完整快照成功后才允许软失效缺失记录。
- ERP 仅预留适配端口，不阻塞 Seller 数据闭环。

## 7. 模块四：选品 Skill

### 7.1 Explore：类目与关键词探索

适用于没有明确商品方向时的机会扫描。

输入：

- 俄语搜索词报告。
- 受控类目或竞品公开样本。
- 自有商品销售、库存和退款摘要。

分析：

- 搜索词热度和关联词。
- 样本价格带、评分和评价数分布。
- 样本品牌或卖家集中度。
- 自有店铺覆盖缺口和周转情况。

输出候选机会清单，不输出全市场精确销量。

### 7.2 Validate：目标 SKU 深入验证

输入：

- 目标商品、采购和物流成本假设。
- 3～5 个核心竞品快照。
- 自有相似商品销售、库存和退款摘要。
- FBO/FBS 成本参数。

分析：

- 竞品价格、评分、评价数、公开属性和卖点。
- 自有销售覆盖缺口。
- 贡献利润、ROI 和盈亏平衡销量。
- 认证、季节、退货和竞争集中风险。

### 7.3 Expand：种子扩展

输入种子商品、核心关键词、搜索词关联词和公开样本，输出：

- 核心词、属性词、场景词和长尾词。
- 同类规格、颜色、材料、容量和场景变体。
- 可进入 Validate 的候选 SKU。

### 7.4 指标与利润模型

- 市场容量：搜索词报告和明确范围的公开样本。
- 竞争度：评分、评价数、品牌/卖家集中度和价格带。
- 利润空间：售价、采购、头尾程、平台佣金、支付费、广告和退货损耗。
- 周转健康：自有销量窗口、可售、在途、可售天数和滞销状态。
- 所有公开市场指标标记为采样估算。

FBO 与 FBS 分别计算：

- 单件贡献利润和贡献利润率。
- ROI 与盈亏平衡销量。
- 广告占比、采购成本和物流成本敏感性。

所有输入假设版本化；资料不完整时结果标记为“不完整估算”。

### 7.5 《商品立项决策书》

固定包含：

1. 机会摘要、目标客户和使用场景。
2. 搜索词与市场样本。
3. 3～5 个竞品快照。
4. FBO/FBS 利润和敏感性测算。
5. 认证、季节、退货和竞争风险。
6. 建议售价区间和首批备货建议。
7. 核心、属性、场景和长尾种子词。
8. 数据来源、时间、样本范围、假设和不确定性。
9. 人工确认状态。

选品模块不得自动采购、上架、调价或投放广告。

### 7.6 公开采样约束

- 首期只维护运营人员手工录入的 10～50 个核心竞品种子。
- 不做全站、全类目或搜索结果页自动遍历。
- 只访问公开 HTTPS 页面并遵守 robots、服务条款和采集启停策略。
- 不绕过登录、验证码和访问限制，不轮换代理或 User-Agent 规避限流。
- 默认每域名并发 1、全局并发 2；429/503 遵守 `Retry-After` 或指数退避。
- 只保存标题、价格、评分、评价数、主图 URL、公开属性和可验证时间等展示字段。
- 规范化快照保留 180 天；原始 HTML 默认不落库，只保存内容指纹、解析版本和脱敏诊断摘要。

## 8. 模块五：Listing Skill

### 8.1 关键词分层

- 核心词：表达商品主需求，优先进入标题前半部分。
- 属性词：型号、规格、材料和关键能力。
- 场景词：用途、人群和使用环境。
- 长尾词：进入 Search Attributes 和描述，避免与标题机械重复。
- 每个词保存来源、统计时间、语言、层级和适用商品范围。

### 8.2 Listing 草稿

生成：

- 俄语标题。
- Search Attributes。
- FABE 卖点。
- 长描述。
- 主图卖点建议。
- 类目建议和关键词覆盖报告。

### 8.3 Smart Search 与风险检测

检查：

- 核心词覆盖、重复和关键词堆砌。
- 标题、类目和商品属性一致性。
- 俄语语法、本地化和可读性。
- 绝对化、虚假疗效和误导性表达。
- 未经授权品牌词和商标风险。
- EAC、GOST-R 等认证风险。
- 图片和内容字段完整度。

系统只高亮问题、展示证据并给出修改建议，不自动删除用户文本。

### 8.4 版本与发布

流程为：

`生成草稿 → 人工修改 → 风险检测 → 差异预览 → 审核 → 受控发布 → 回读 → 版本效果复盘`

草稿不直接改变 Ozon 商品。具体 Seller API 写入方法实施前重新核对官方契约。

## 9. 模块六：广告 Skill

### 9.1 Performance API

- 使用独立 OAuth 凭据，访问令牌短期保存并提前刷新。
- 不与 Seller Api-Key、Client-Id 假设或限流状态混用。
- 读取账号实际有权限的活动、关键词、否定词、报表和统计。
- 交付文档中的路径只表示能力范围，不作为实现时的唯一接口证据。

### 9.2 广告类型与指标

产品概念覆盖搜索广告、模板广告和登上顶端；具体类型、计费模式和字段以账号权限和最新官方文档为准。

指标包括：

- 展示、点击、订单、广告销售额和花费。
- ACOS、TACOS、CPC、CTR、CVR 和 ROI。

每个指标显示公式、统计窗口、币种、数据完整度和更新时间。

### 9.3 关键词诊断

- 明星词：高量、高转化和强相关。
- 高 CVR 词：流量中等但转化较高。
- 潜力词：趋势上升或竞争较低。
- 高费无转化词：点击或花费较高但没有有效转化。

阈值按部署或工作区配置并版本化，诊断结果只生成预算、出价和否定词建议。

### 9.4 新品前 30 天建议模板

- 第 1～7 天：测试长尾词、CTR 和加购表现。
- 第 8～14 天：积累数据并筛选高质量词。
- 第 15～21 天：对高转化词提出放量和排名建议。
- 第 22～30 天：识别高费无转化词并生成否定词和预算倾斜建议。

广告日历只生成建议，不自动变更预算、出价或否定词。

## 10. 模块七：多 Agent 协同

### 10.1 Agent 角色

| Agent | 数据来源 | 输出 |
|---|---|---|
| 销售 Agent | Seller API、脱敏订单和销售事实 | 销售日报、退款和客单价异常 |
| 库存 Agent | FBO/FBS 库存、销量和在途 | 缺货、补货、滞销和清理建议 |
| 广告 Agent | Performance API | 广告日报、关键词和预算建议 |
| 竞品 Agent | 手工种子公开快照 | 价格、评分、评价和内容变化 |
| 选品 Agent | 搜索词、公开样本和自有分析 | 候选机会和研究任务草稿 |
| 汇总 Agent | 各 Agent 报告和配置 | 日报、周报、月报和统一告警 |

### 10.2 触发与输出

- 定时触发：日报、周报和月报。
- 事件触发：库存安全线、广告异常、竞品变化和退款异常。
- 手动触发：运营人员在授权工作区主动运行指定 Agent。
- 输出包括站内待办、报告、告警、候选选品清单、竞品变化和广告诊断建议。

### 10.3 权限边界

- Agent 永久只读，不持有 SQL、凭据、文件系统或外部写适配器。
- Agent 只能调用参数化业务工具，只能创建建议、报告、待办和待审核请求。
- 外部写入由独立审核与执行服务完成。
- 提示词不能改变权限、内部数据隔离、数据范围或审核规则。
- 每次运行记录用户或服务主体、工作区、时间窗、数据版本、工具摘要、模型版本和输出。

### 10.4 通知路线

- P0/P1 仅提供站内通知。
- 飞书、钉钉、企微和邮件列入 P2。
- 企业 IM 接入前单独确认渠道、凭据、消息模板、失败重试、退订和敏感数据边界。

## 11. 人工审核与受控写入

统一流程：

`选择目标 → 校验数据新鲜度 → 生成差异预览 → 风险限制 → 人工批准 → 创建幂等命令 → 分项执行 → 回读核对 → 审计 → 效果复盘`

首个受控写入能力为商品价格：

- 每批最多 20 个商品。
- 单次涨跌不超过 10%。
- 不得低于已确认利润线。
- 未授权、未确认、数据过期或风险校验失败时拒绝执行。
- 部分失败必须展示分项结果，不能报告为整体成功。
- 执行完成后必须回读 Ozon 实际结果并写入脱敏审计。

Agent、规则和模型只能创建待审核请求，不能自行批准或执行。

## 12. 云端运行与非功能需求

### 12.1 已确认服务器约束

运行环境为 Linux 云服务器，2 核 CPU、2GB 内存、约 4GB Swap，使用 Docker Compose。Swap 只作为突发保护，不计入正常容量。

| 服务 | 资源上限 | 运行要求 |
|---|---:|---|
| PostgreSQL 16 | 512MB | `max_connections=30`，`shared_buffers=128MB`；唯一业务数据库 |
| Redis 7.4 | 128MB | 数据上限 96MB，`noeviction`；不保存唯一业务事实 |
| API | 320MB | 单 Uvicorn Worker |
| Worker | 192MB | 单进程，全局业务并发初始上限 2 |
| Nginx/Web | 64MB | 静态资源和反向代理，公网唯一入口 |

- PostgreSQL 与 Redis 只在 Compose 内部网络；PostgreSQL 宿主机回环端口仅供 SSH 隧道，Redis 不映射宿主机端口。
- 数据库密码和 Ozon 加密主密钥使用相互独立的 Compose Secret，不进入 Git、镜像、普通环境变量或日志。
- 镜像由阿里云 ACR 构建，服务器只拉取，不在 2GB 节点本地构建。
- 当前开发节点使用公网 IP + HTTP；内部试用或正式数据进入前配置域名、HTTPS 和正式认证。
- PostgreSQL 每天 03:15（Asia/Shanghai）备份，开发阶段保留 14 天；结构升级前执行备份和隔离恢复验证。
- P0 不引入 ClickHouse、向量数据库、独立爬虫集群、Kubernetes 或微服务集群。

### 12.2 非功能要求

| 编号 | 要求 |
|---|---|
| NFR-001 来源透明 | 每条快照和结论记录来源、采样时间、统计窗口、估算属性和版本 |
| NFR-002 数据隔离 | 工作区访问约束与 PostgreSQL RLS 双重保护；内部组织字段由服务端固定，不形成 SaaS 功能 |
| NFR-003 凭据隔离 | Seller、Performance、应用会话和数据库凭据分别保护、轮换和审计 |
| NFR-004 数据最小化 | 买家 PII 不进入选品、竞品、广告、通知、Agent 或 RAG 数据集 |
| NFR-005 合规采集 | 遵守 robots、服务条款和限流，禁止绕过访问控制和验证码 |
| NFR-006 可靠性 | 外部读取按错误类型退避并遵守 `Retry-After`；写入不做无边界自动重试 |
| NFR-007 可恢复 | PostgreSQL 保存业务和任务事实；Redis 丢失后可恢复；备份可在隔离库验证 |
| NFR-008 可测试 | 自动化测试只使用 Stub、Mock、脱敏夹具和本地静态页面 |
| NFR-009 可访问性 | 关键流程支持键盘、明确标签和非颜色状态提示 |
| NFR-010 可观测性 | 监测健康、队列、任务年龄、限流、连接池、磁盘、备份和采集失败 |
| NFR-011 资源预算 | 核心服务不得持续使用 Swap、发生 OOM 或超出既定容器资源上限 |
| NFR-012 智能体安全 | 模型不能执行任意 SQL、读取凭据、跨工作区访问或绕过审核 |

## 13. 版本路线图与退出条件

### V5.1 可信 Seller 数据（P0）

完成单组织运营登录、Seller 凭据、商品/价格、库存、订单、履约同步、任务恢复和数据质量。多组织 SaaS 产品化不属于本阶段任务。

退出条件：运营用户能在云端稳定查看真实、可追溯的 Seller 数据；容器重建、Redis 丢失和 Worker 重启不会造成业务事实丢失或跨工作区串读。

### V5.2 选品 MVP（P0）

完成搜索词报告导入、竞品种子、合规公开采样、三种研究模式、利润测算和决策书草稿。

退出条件：一份脱敏搜索词报告和一组人工竞品种子可生成可复现决策书；公开样本明确标记范围和估算属性。

### V5.3 Listing 与广告诊断（P1）

完成俄语关键词库、Listing 草稿、风险检测、Performance OAuth 和只读广告诊断。

退出条件：Listing 与广告建议可追溯到词表、报表、规则和版本，且不会触发真实外部写入。

### V5.4 审核与受控写入（P1/P2）

完成人工审核队列、价格小批量写入、幂等、回读、部分失败和审计。

退出条件：未授权、未确认、数据过期、超批量、超涨跌幅或低于利润线的请求全部被拒绝；批准后分项执行并完成回读。

### V5.5 多 Agent 协同（P2）

完成只读 Agent、定时报告、告警、汇总和外部通知扩展。

退出条件：Agent 通过跨工作区、提示注入、任意 SQL、凭据访问和写入绕过测试；报告可追溯到事实快照和模型版本。

## 14. 核心验收场景

1. 用户只能访问当前部署允许的工作区；客户端不能改变内部组织边界，API 与 RLS 共同阻止数据串读。
2. Seller 与 Performance 凭据无法互换，且不进入浏览器、日志、任务消息或审计详情。
3. Redis 清空后排队和超时任务能从 PostgreSQL 恢复。
4. 搜索词报告可预览、校验、定位错误并幂等导入。
5. 被 robots 或采集策略禁止的页面不会发出采集请求，并显示停止原因。
6. 公开样本明确标记采样时间、范围和估算属性，不显示为官方精确销量。
7. Explore、Validate、Expand 均能生成可追溯结果，决策书可复现。
8. FBO/FBS 利润结果能回溯到成本、汇率、物流、广告和退货假设版本。
9. Listing 风险检测保留原始草稿和人工版本，只给建议不自动删除内容。
10. 广告建议不会自动修改预算、出价或否定词。
11. Agent 尝试执行 SQL、读取凭据、跨工作区或调用写适配器时被拒绝并审计。
12. 未确认、过期、超批量、超涨跌幅或低于利润线的改价请求被拒绝。
13. 工作区停用后，新同步、采集、Agent 和写入被拒绝，历史数据仍可按权限查询。
14. 数据权限不足显示“无权限”，不能伪装为“暂无数据”。
15. 容器重建后业务事实仍存在，备份可恢复到隔离数据库而不覆盖运行库。
16. 自动化测试不访问真实 Ozon 账号或真实公开页面。

## 15. 当前完成度与非目标

### 15.1 已完成或已部署

- PostgreSQL、Redis、API、Worker、Nginx/Web 的云端 Docker Compose 基础节点。
- API 存活/就绪检查、PostgreSQL 备份和隔离恢复演练基础。
- 卖家账号创建、加密凭据、工作区连接界面和基础商品查询已有阶段性实现与测试证据。
- Web 与 Chrome 扩展共享 React 前端基础骨架。

### 15.2 部分完成

- 卖家账号与商品功能存在分支/工作树差异，需要统一到实际云端部署基线。
- 商品数据仍以 Stub 或早期适配器为主，真实 Seller 同步闭环未完成。
- Worker 有运行骨架，持久化任务、Redis 投递、租约、心跳和恢复尚未形成完整闭环。
- 登录、固定部署组织上下文和 RLS 基础已经实现；真实 PostgreSQL 端到端部署验证仍需完成。多组织、成员管理和复杂授权不在当前开发范围。

### 15.3 未开始

- 搜索词报告导入、公开采样、三种选品研究和决策书。
- Listing 草稿、俄语风险检测、Performance API 和广告诊断。
- 人工审核队列、受控写入、多 Agent、外部通知和完整效果复盘。

### 15.4 当前明确非目标

- 多组织 SaaS 产品化。
- 组织注册、切换、邀请、成员目录、组织套餐和组织设置。
- 面向多个客户组织的自助租户管理。
- 复杂角色配置器和工作区成员授权后台。

上述能力只有在重新提出需求、确认业务价值和单独排期后才能进入开发。内部 PostgreSQL 组织字段、成员表或 RLS 的存在不能作为启动这些任务的依据。

### 15.4 当前非目标

- Ozon 之外的平台、具体 ERP API 接入和付费第三方市场数据订阅。
- 全站、全类目、搜索结果页遍历或绕过限制的网页爬取。
- 自动采购、自动上架、自动改价、自动广告写入和无人审批 Agent。
- Kubernetes、微服务集群、ClickHouse、独立爬虫集群和服务器本地镜像构建。
- 持久化非业务必要的买家完整姓名、电话、邮箱或地址。

## 16. 已确认产品决策

1. 允许建设合规、限速、可关闭的公开页面采样层。
2. 首期公开采样仅支持运营人员手工维护的 10～50 个竞品种子，不做全站、全类目或搜索结果页遍历。
3. P0 顺序为“可信 Seller 数据 → 搜索词报告导入 → 竞品种子采样 → 选品研究”。
4. Performance API 放在选品 MVP 之后，不阻塞 P0。
5. 所有 Agent 永久只读，外部写入只能由独立审核与执行服务完成。
6. 首个受控写入为价格小批量修改：每批最多 20 个商品、涨跌不超过 10%、不得低于利润线。
7. 公开字段快照保留 180 天，原始 HTML 默认不落库。
8. P0/P1 仅提供站内通知，飞书、钉钉、企微和邮件推迟到 P2。
9. 模块三只预留 ERP 适配端口，首期不接入领星或其他具体 ERP。
