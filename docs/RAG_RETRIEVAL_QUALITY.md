# RAG 查询、检索、证据与质量设计

> 状态：已定档待开发。本文定义从用户问题到有引用回答的执行契约、降级规则、评测方法和发布门槛。

## 1. 目标与原则

系统的目标不是尽可能回答，而是在知识边界内提供可追溯、可复盘、可拒答的答案。以下是不变量：

1. 不知道是有效终态。
2. 一条结论必须由实际证据支持，引用数量不能替代引用质量。
3. 实时经营事实和写操作不得由知识 RAG 猜测或执行。
4. 任何模型组件失败都必须进入显式、确定性的降级路径。
5. 多意图问题按片段处理，局部失败或受限不吞掉安全片段。
6. 检索和回答必须固定模型、策略、提示词和索引版本，保证可复盘。

## 2. 查询执行对象

### `KnowledgeQueryRequest`

包含原始问题、会话引用、登录主体、允许知识范围、语言、客户端能力和追踪 ID。客户端不能提交来源等级、跳过安全检查或指定任意 Collection。

会话引用由服务端解析为最近6轮的脱敏 `ConversationContextSnapshot`，仅包含已确认实体、适用条件和通过证据门禁的声明引用。对话文本本身不构成证据；每轮必须重新校验主体、权限、知识版本、生效期和撤回状态。跨用户、跨工作区或跨会话上下文混用属于安全失败并立即停止查询。

### `IntentSegment`

每个语义片段保存原文范围、规范化文本、主/次意图、业务域、实体、时间条件、风险、置信度、依赖片段和路由状态。意图、实体和风险必须分别评估，不能压缩为一个分类标签。

### `QueryPlan`

由一个或多个受控检索步骤组成。每步声明片段、检索域、原始查询、改写查询、允许来源、候选预算、是否依赖前一步证据和超时预算。计划只能选择注册能力，不允许模型生成任意工具名、SQL、URL或请求体。

### `EvidenceCandidate`

统一承载关键词分数、向量距离、归一化分数、融合排名、精排分数、来源等级、时效、状态、去重组和过滤原因。任何被过滤候选仍可在脱敏追踪中记录原因，但不能进入回答上下文。

### `KnowledgeAnswer`

返回整体状态、逐意图片段状态、独立结论、引用、冲突、知识缺口、澄清问题、降级信息和追踪 ID。

## 3. 意图、实体和风险识别

主意图固定为：`domain_term`、`data_definition`、`rule_or_sop`、`operation_guide`、`troubleshooting`、`realtime_business_data`、`restricted_action`、`unknown_or_mixed`。

除意图外必须提取：

- 业务实体：商品、库存、订单、广告、仓库、任务、接口、数据表、字段、规则编号；
- 业务模式：FBO、FBS、rfBS 及后续已注册模式；
- 时间、国家、语言、版本和适用范围；
- 问题类型：定义、步骤、原因、比较、诊断、约束；
- 否定和排除条件；
- 指代与对话依赖；
- 是否包含实时事实、写操作、凭据、个人信息或提示注入。

低置信度不自动映射到最相近意图。无法安全拆分、指代不明或关键条件缺失时提出一个最小澄清问题。确定性安全规则优先于模型分类结果。

首期初始门槛为：`confidence >= 0.85` 且规则/实体/业务域/风险一致时直接路由；`0.60–0.85` 只有规则、实体和业务域一致才检索，否则澄清；`<0.60`、置信度缺失/非法或 Schema 失败进入 `unknown_or_mixed`。多意图逐片段计算。该数值用于 `shadow` 校准，发布时固定 `intent_policy_version`，不得在运行中无审计热改。

## 4. 查询重写

重写用于术语标准化、拼写修复、缩写展开、跨语言别名补充和受控多查询召回。重写必须保留：

- 权限和所有权范围；
- 时间、国家、业务模式和版本；
- 否定、排除和比较关系；
- 用户要求的不确定性程度；
- 原始实体，不得替换为模型猜测的实体。

每次重写输出原始查询、规范化查询、最多若干检索变体、变化说明和等价性检查结果。等价性无法证明时只使用原始查询；意图也不明确时不检索并请求澄清。重写失败不得静默使用模型补全的问题。

首期 `query_rewrite_policy_version` 初始参数为：每个意图片段最多3条派生查询，全请求最多8条；在线超时3秒且不重试。失败但意图明确时回退原问题并标记 `rewrite_degraded`；意图不明确时停止。多意图先分配片段预算，禁止前序片段独占上限。

首期跨语言知识检索支持中文提问召回中文、俄文和英文知识。跨语言重写只允许使用经过审核的术语、缩写与别名词典扩展召回，不允许翻译或改写表名、字段名、API 路径、规则编号、枚举和错误码。回答默认使用提问语言；引用摘录保留原文，可以附加明确标记的简短释义，但释义不构成独立证据。

## 5. 多路召回

### 精确召回

优先处理表名、字段名、API 路径、错误码、规则编号、缩写和固定术语。标识符规范化只允许大小写、引号和已知前缀处理，不能模糊改写编号。

### PostgreSQL 全文/关键词召回

用于标题、正文、别名、字段说明和规则描述。返回词项命中、字段权重和来源过滤信息。不同语言的配置通过评测选择。

### Chroma 向量召回

用于近义表达、跨语言语义和自然语言问题。查询必须携带服务端生成的允许范围过滤条件；召回后仍需用 PostgreSQL 重新验证状态、权限、有效期和版本。

### 父子与邻接扩展

精确子切片命中后可补充父定义、标题上下文或有限相邻切片。扩展内容必须有独立 ID 和引用定位，不能将整份文档无界加入上下文。

## 6. 候选融合与去重

PostgreSQL 分数和 Chroma 距离尺度不同，禁止直接相加。首期建议以 Reciprocal Rank Fusion 作为可复现基线，并增加以下确定性信号：

- 标识符完全匹配加权；
- 来源等级和当前有效版本加权；
- 意图与业务域一致性加权；
- 标题路径、实体和适用范围一致性加权；
- 过期、范围不明和冲突候选不进入确定性结论；
- 相同内容哈希、同一父节点或高度重叠切片去重；
- 通过最大边际相关性或每文档配额控制结果多样性。

融合日志保存每条候选来自哪些通道、原始名次、融合贡献和去重结果。具体权重只能通过固定评测集调整。

`shadow` 初始策略固定为：精确标识符最多20条、PostgreSQL全文最多30条、Chroma向量最多30条；合并去重后最多60条，RRF `k=60`。标识符完全匹配增加独立确定性信号，但不绕过治理过滤。相同内容哈希去重，同一父文档默认最多保留5条，避免单一来源淹没候选。

## 7. 重排序精排

精排输入是已完成权限、状态、时效和去重校验的有限候选。精排考虑问题—切片相关性、意图匹配、实体覆盖、答案潜力和来源可靠性，不负责解除过滤或修改来源等级。

精排模型超时、不可用或输出不符合 Schema 时，降级到可复现的融合排序，并收紧证据门槛。系统必须返回 `rerank_degraded=true`，不能声称执行了完整精排。

候选预算需要分层控制，例如召回较宽、融合后收窄、精排后仅保留满足上下文预算的证据。具体数量在评测后定档，不能写死为所有业务通用常量。

首期初始预算为融合后最多20条进入精排、精排后最多8条进入证据检查，并同时受模型上下文token预算限制。精排失败时使用RRF顺序、显式标记降级并收紧为最多5条证据。多意图按片段分配配额。上述数值写入 `retrieval_policy_version`，不是领域常量，可在冻结评测后产生新版本。

## 8. 多跳问题

需要多个知识点才能回答时生成有向无环查询计划：

1. 将问题拆分为最小可验证子问题。
2. 标记独立步骤和依赖步骤。
3. 每个步骤独立召回和证据判定。
4. 后续步骤只能使用已验证的实体或结论作为输入。
5. 最终聚合逐项展示证据、不确定性和未完成部分。

首期 `query_plan_policy_version` 最多3个子问题/3个检索步骤，最大依赖深度2。计划模型最多调用1次，Schema失败只允许一次确定性格式修复，不允许重新自由规划。全请求融合前候选最多120条、精排最多30条、最终证据最多10条，并受token与总时间预算限制。

达到任一预算即停止并返回已完成部分、未完成子问题和原因。无证据、冲突、低置信度或被拒绝节点不能作为后续事实。并列多意图不伪装为多跳依赖，多跳计划必须保持有向无环且可追踪。

## 9. 证据充分性与冲突

证据进入回答前必须通过：

- 状态、权限、业务域、生效期和来源等级校验；
- 与查询实体、条件和意图的一致性检查；
- 证据是否包含支持结论所需的主语、条件、动作和结果；
- 数字、日期、枚举、规则编号和操作步骤的逐项核验；
- 多来源是否存在版本、适用范围或结论冲突。

冲突资料不能由模型自行择一。系统并列展示来源、版本、适用范围和冲突点，并请求人工确认。来源过期或范围不明时不得输出确定结论。

来源等级固定为 A/B/C，并只从 PostgreSQL 治理事实读取。相同适用范围和时间内，跨等级冲突可以优先较高等级，但必须在追踪中记录被抑制冲突；同等级冲突一律展示并请求人工确认。不同国家、履约模式、版本或生效范围的差异按条件分别回答。C 级证据可以辅助说明，但不能单独通过高风险操作、关键限制和确定性经营结论的证据门禁。

首期证据充分性规则如下：

- 字段定义、标识符和数据口径至少有一条 A/B 级证据直接支持，并具有可复核的精确定位。
- 操作流程和排障结论分别校验前置条件、动作/检查项与预期结果；跨来源组合时逐步骤引用。
- 权限、安全、删除等高风险声明需要 A 级证据，或两份来源独立且内容一致的 B 级证据；C 级证据永远不能单独满足该门槛。
- 数字、日期、枚举、限制和否定条件必须有原文跨度，不能根据相邻语义推算或由模型补齐。
- 证据冲突、缺少适用条件或只支持部分声明时，只保留已证实声明，其余返回 `unsupported`、`needs_clarification` 或冲突状态。

系统不定义跨嵌入模型、跨精排模型通用的固定原始分数阈值。每个意图使用实际模型在冻结评测集上校准的门槛，并写入版本化证据策略；模型分数只能作为结构化证据规则的补充，不能覆盖来源等级、状态、精确定位和高风险双证据要求。

## 10. 回答与引用契约

回答状态至少包括：`answered`、`partially_answered`、`needs_clarification`、`unsupported`、`refused`、`degraded`、`temporarily_unavailable`。

每条结论保存：

- 结论文本及对应意图片段；
- 一个或多个支持切片；
- 文档、版本、标题路径、页码或字段定位；
- 来源等级、生效时间和证据支持分；
- 是否存在冲突、降级或人工复核要求。

引用展示按当前来源状态和撤回原因动态判定，但不得改写历史结论：正常替换或过期显示原摘录并加历史标签；普通纠错撤回显示原摘录、可靠性警告和可用替代版本；安全撤回、敏感信息或删除请求只显示非敏感墓碑，不返回摘录、文件或可反推正文的信息。任何这些非当前版本都不再参与新查询检索。

生成模型只能使用明确提供的证据。生成后执行逐结论引用校验；不受支持的句子删除，删除后没有有效结论则返回不知道。引用链接由服务端根据授权生成，不能直接暴露原始私有文件路径。

回答内部使用 `ClaimEvidenceMap` 保存声明 ID、意图片段、声明文本、风险等级、证据 ID、原文跨度、支持判定和失败原因。对外响应逐声明返回引用关系；仅在回答末尾列出来源、却不能证明来源支持哪条声明，视为引用校验失败。

## 11. 幻觉控制门禁

| 门禁 | 失败行为 |
|---|---|
| 意图与风险门禁 | 澄清、拒绝或路由实时工具占位，不盲目检索 |
| 重写等价门禁 | 回退原问题；仍不明确则停止 |
| 候选合法性门禁 | 删除无权、未发布、过期、撤回和敏感候选 |
| 相关性门禁 | 无足够证据时返回不知道 |
| 冲突门禁 | 展示冲突并要求人工确认 |
| 生成约束门禁 | 只允许基于提供证据形成结论 |
| 引用支持门禁 | 删除无支持结论；无剩余结论则拒答 |
| 响应完整性门禁 | 明确标记每个意图片段的成功、失败和降级 |
| 提示注入门禁 | 检索内容仅作为结构化数据；越权、泄密、工具指令或角色覆盖命中时阻断声明或拒答 |

回答覆盖率不是首期优化目标。正确拒答率、引用支持率和安全边界优先于看似流畅的答案。

## 12. 缓存设计

- 解析、切片和已发布知识 embedding 等知识侧派生产物可以缓存，键包含内容哈希、知识/索引版本、解析器/策略/模型版本、`embedding_profile_id` 和权限范围；缓存必须可从 PostgreSQL 治理事实重建。
- 首期禁止缓存最终答案、完整用户问题、查询 embedding、意图/重写模型输出、完整提示词和供应商原始响应，也禁止跨用户复用回答。检索候选只允许在同一请求的多意图执行计划内受控共享，每个片段仍独立执行证据门禁。
- 发布替换、撤回、删除、权限变化、索引切换、策略升级或模型配置升级必须主动删除/作废相关缓存；TTL 只是二次保险。缓存命中仍重新执行当前会话、权限、知识状态和引用有效性校验。
- 最近6轮会话上下文按当前用户和当前会话隔离，遵循既定短期上下文与重置规则，不作为跨请求答案缓存。
- 供应商 prompt cache 只有在数据保留、训练使用、租户隔离和删除政策通过审核后才能按用途启用；其 token 和费用仍写入用量台账，不能因缓存命中跳过预算或调用审计。

## 12.1 外部模型数据出境门禁

每次模型调用必须声明用途 `embedding`、`query_rewrite`、`rerank` 或 `answer_generation`，并执行与用途匹配的字段白名单：

- 嵌入：只发送通过治理和敏感检查的单个检索增强切片，不发送所有者、内部路径或无关元数据。
- 查询重写：只发送当前意图片段、必要对话指代和已审核术语；不发送完整会话历史。
- 多轮指代解析：只发送当前问题和最近6轮脱敏结构化摘要；历史模型生成文字、无支持声明和失效引用不得进入模型上下文。
- 精排：只发送规范化问题和有限候选的最小正文、非敏感来源信号；不发送被过滤候选。
- 回答生成：只发送最终通过证据门禁的内容及受控输出 Schema；不发送整份文档。

调用前必须验证供应商配置处于启用状态，处理区域、数据保留和训练政策符合项目配置。调用追踪保存用途、供应商、模型版本、输入/输出 token、延迟和脱敏哈希，不默认保存完整提示词或响应。无法完成数据分类、最小化或供应商策略校验时，不得发起请求。

供应商由服务端 `ModelProviderRegistry` 配置，可包含 DeepSeek、MiniMax、GPT 等适配器。嵌入、意图/重写、精排和生成分别绑定主模型及预先审核的备用模型；任何切换都记录配置版本和原因。API Key 不参与追踪且不可读取，模型或供应商未通过对应用途的 `shadow` 基线时不得进入 `pilot`。

DeepSeek、MiniMax、OpenAI/GPT 使用专用适配器，其他兼容服务只能通过受控 `openai_compatible` 适配器接入。适配器能力清单决定可参加的评测集合；连接成功、模型可发现或返回 HTTP 200 均不能替代结构化输出、跨语言、引用支持、降级和安全评测。

额度耗尽、余额不足、硬配额和认证失败立即停止在线重试并触发用途级熔断；限流只允许在供应商明确给出重试窗口且请求总预算允许时执行一次受控重试。意图/重写和生成只能切换到已预审备用模型，精排失败回退 RRF。嵌入查询只有在备用端点与当前索引共享同一 `embedding_profile_id` 时才允许切换，否则关闭向量通道并显式降级到精确/全文检索。

首期每个用途配置一个主模型和至多一个备用模型，每个请求最多发生一次自动切换。主模型熔断期间直接使用合格备用，不逐请求试探；备用也失败时进入该能力既定最终降级。追踪必须记录计划供应商/模型、实际供应商/模型、切换原因、熔断状态和配置版本，但不得记录密钥或供应商原始敏感错误。

离线嵌入任务遇到额度或余额问题时不得把部分向量标记为可发布；任务保存幂等进度并等待原配置恢复。更换嵌入模型必须创建新索引版本并执行完整质量评测，不能把新旧向量混入同一 Collection/索引版本。

## 13. 可观测性

每次查询记录：意图分段、实体、风险、改写结果、召回通道、候选数量、过滤原因、融合与精排得分、证据选择、引用校验、降级原因、模型/提示词/索引版本、延迟和成本。日志默认只保存 ID、哈希、枚举和脱敏摘要。

质量运营人员和高权限管理员可在 30 天内查看脱敏问题、意图/实体/风险、重写结果、候选 ID 与来源版本、各阶段分数、过滤原因、最终证据、版本、延迟、token、成本和降级原因。普通运营人员只能查看自己的回答与反馈，不能浏览全局查询追踪。完整会话、完整提示词、原始模型响应和被过滤候选正文不进入追踪。

30 天后删除逐查询明细，只保留 180 天聚合指标。用户反馈保留至结案后 180 天；安全与发布审计保留 1 年。加入冻结回归集的样本必须重新脱敏、人工确认并使用独立的数据集生命周期。

核心指标包括：

- 摄取成功率、各层耗时、待人工复核数量；
- Chroma 与 PostgreSQL 索引差异、重建时长和失败重试；
- 各意图流量、低置信度率、空召回率、拒答率和降级率；
- Precision@K、Recall@K、MRR、nDCG；
- 引用支持率、冲突识别率、正确拒答率；
- P50/P95 查询延迟、模型调用次数、token 和单次成本；
- 高频未知问题、过期来源和用户错误反馈。

## 14. 离线评测集

评测样本必须来源可追溯、经过脱敏并由业务人员确认。每条样本包含问题、意图、业务域、实体、适用条件、相关/禁止切片、参考声明、引用定位、期望状态、是否应拒答、拒答原因和风险标签。

AI 可以从已发布 A/B 级知识、数据库中文说明、API 契约、SOP 和已确认故障记录生成案例草稿及语言、拼写、多意图、多跳和攻击变体。生成器必须保存来源版本、生成模型/提示词版本和生成原因；自动校验来源存在、版本有效、引用可定位、声明可支持、近重复和集合交叉泄漏。AI 生成结果始终为 `draft`，不能审核自己或直接进入冻结集。

人工最终确认按风险分级：普通知识案例由质量运营或对应业务人员确认；权限、安全、敏感、写操作和高风险案例由 reviewer/admin 确认。确认后冻结问题、预期状态、声明、引用、禁止引用、来源版本和内容哈希；知识版本失效时案例进入待复核，而不是静默改写黄金答案。

样本类型至少覆盖：

- 定义、字段口径、步骤、排障、比较和多跳问题；
- 中文提问、俄文/英文资料及术语缩写；
- 中→中、中→俄、中→英和同一问题混合中俄英标识符的独立子集；
- 跨语言数字、日期、否定、限制条件和适用范围保持测试；
- 拼写错误、同义表达、否定条件和指代；
- 多意图、局部受限、部分未知和需要澄清；
- 无答案、过期、冲突、权限越界和提示注入；
- 同时包含真实攻击和合法讨论提示注入的资料，验证系统既不服从攻击，也不因关键词误删安全知识；检测器异常和高风险不确定样本必须失败关闭；
- 表格、跨页 PDF、多栏 PDF、扫描 PDF 检测、OCR 解析失败和 OCR 低质量；未配置/失败 OCR 的正确结果是阻断发布，配置成功后评测 OCR 召回质量；
- Chroma、重写、精排或生成模型故障下的降级路径。

评测集分为开发集、调参集和冻结回归集。禁止在冻结集上反复调参后继续将其报告为独立评估。

考虑 2GB 开发服务器，案例生成和执行由独立 `rag-worker` 单并发、小批次处理，不把全部问题、证据或模型响应同时载入内存。批次任务保存游标、预算预留、结果和失败原因，可暂停、续跑和幂等重试；在线 API、现有业务 Worker 和当前发布索引优先。案例总量主要受人工确认覆盖面约束，执行频率和单次子集规模按服务器压测定档。

首期最小评测库为400个已人工确认案例：160个校准案例用于 `shadow` 调整意图、重写、检索、精排和证据策略；240个冻结案例不参与调参，只用于独立发布判断。冻结集通过稳定案例清单派生三级执行：

- `quick`：固定30例，适用于相关代码或配置改动后的快速检查；
- `standard`：固定120例，适用于模型、检索、切片、提示词或证据策略版本变化；
- `full`：全部240例，仅用于进入 `pilot/internal`、关键模型迁移或重要索引升级。

每批最多10例，单并发串行执行。三个层级均包含固定的权限、敏感信息、撤回、提示注入和降级硬门槛案例；不能用随机抽样使安全样本缺席。资源、预算、熔断或在线健康不满足时评测进入 `paused` 并保存游标，`not_run`、`skipped` 和 `error` 均不计入通过分母，也不能被视为成功完成。

## 15. 首期质量门槛

以下数值已确认为进入 `pilot` 的最低发布门槛。进入 `internal` 前必须加入试用期真实问题复测；安全硬门槛不能被平均分或其他高分抵消：

- 权限、撤回、敏感信息和提示注入测试必须 100% 通过；
- 引用定位成功率 100%，引用支持率不低于 95%；
- 标识符和字段口径类问题 Recall@5 不低于 95%；
- 综合知识问题 Recall@10 不低于 85%，Precision@5 不低于 70%；
- 中→俄、中→英跨语言问题 Recall@10 不低于 80%；
- 应拒答样本的正确拒答率不低于 95%；
- 多意图逐片段状态完整率 100%；
- Chroma 故障时降级标记准确率 100%；
- 同一输入、策略和版本的切片及检索结果可复现；
- P95 延迟和资源上限在部署压测后定档，任何持续 Swap/OOM 均阻止发布。

P95 延迟、单次成本和吞吐在模型供应商、模型版本与服务器压测完成后定档；未定档不代表可以无上限运行，试验阶段仍使用请求超时、token、候选数和并发预算。

门槛未达到时不得通过放宽权限、降低引用要求或强制回答来改善表面指标。

发布门槛按三阶段执行：`shadow` 完成离线、安全和恢复验证；`pilot` 收集小范围内部真实问题与反馈；`internal` 需要冻结回归集、安全门禁、资源预算和故障演练全部通过。任何阶段发现敏感泄露、撤回内容召回或严重引用错误，立即回退到 `disabled` 或 `shadow`，不能只在客户端隐藏提示。

`pilot` 不设置强制最短天数，由 `admin` 决定开始和结束，可在运行1天后申请晋级。真实问题数、真实用户数和运行时长作为独立风险指标展示，不与 AI 增强样本合并，也不构成硬阻断；样本不足时管理员必须确认残余风险并填写晋级理由。240例完整冻结验收、安全硬门槛、严重事件为0和未解决高风险反馈为0仍不可豁免。

当前单用户部署的真实用户数允许为1，现有 `root/admin` 的正常提问和反馈属于真实试用数据。系统不得复制账号、重复问题或把 AI 样本标记为多个真实用户来改善指标；试运行报告明确标注单用户局限，并保持全部硬门槛。

## 16. 在线反馈闭环

用户可以标记有用、错误、来源过期、答案缺失或引用不匹配。反馈先进入人工分诊，不直接作为模型训练事实或自动修改知识。处理结果应关联：

- 原查询追踪和结论；
- 被质疑的引用；
- 根因分类：知识缺失、知识过期、解析错误、切片错误、召回错误、精排错误、生成错误或界面问题；
- 修复动作和验证用例；
- 是否加入冻结回归集。

高频未知问题用于建立知识缺口清单；不能由模型自动生成文档并直接发布。

## 17. 性能与资源预算

当前 2GB 开发服务器必须将离线摄取与在线查询隔离：

- 解析、切片和嵌入由受限 Worker 执行，设置并发、文件大小、页数、耗时和内存上限；OCR 使用独立超时、配额和资源预算，失败时阻断当前版本；
- 大型 PDF 分页或流式处理，不把原文件和全部中间对象同时驻留内存；
- Chroma 单副本、固定镜像、持久卷和显式内存限制；服务器只拉镜像，不本地构建；
- 查询阶段限制重写数、各通道候选数、精排数、上下文 token 和模型调用数；
- 超时按阶段分配并保留聚合预算，避免单个组件耗尽整个请求；
- 索引构建和全量评测不与核心 API 高峰并发；后续 OCR 必须使用独立资源预算和调度窗口。

## 18. 运行期工程定档参数

- 满足中俄英跨语言门槛的具体嵌入模型、维度和升级策略；
- DeepSeek、MiniMax、GPT 等供应商采用可配置注册机制；仍需逐账户定档处理区域、数据保留期限、是否用于训练及合规审核结果；
- 查询重写数量、3秒超时和失败策略已确认；具体重写/重排模型和单次成本预算由候选模型在160例校准集及2GB服务器压测中工程定档；
- 已确认RRF及候选/精排初始数量；最终相关性门槛按意图和实际模型通过冻结评测校准，不设置跨模型通用原始分数阈值；
- 已确认初始意图阈值 `0.85/0.60`；各意图是否使用差异化阈值由160例校准集结果工程定档，不再要求产品逐项确认。
- 已确认多跳步骤、深度、模型调用和候选预算；总延迟与token预算由模型/服务器压测工程定档；
- 正式 P95、吞吐、容量和重建恢复目标；
- 已确认线上追踪与反馈保留期；仍待定档聚合指标的具体字段和安全审计归档位置。
