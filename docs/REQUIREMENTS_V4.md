# ozonslj 产品需求文档 V4

> 版本：V4.0  
> 日期：2026-07-31  
> 状态：已完成产品确认  
> 适用范围：Web 控制台、Chrome 扩展、FastAPI、Worker、PostgreSQL、Redis，以及后期智能体与 RAG

## 1. 版本说明

V4 以 V3 为基础，按照成熟 Ozon 运营团队的日常工作链路重新组织需求。V4 不仅要求“看见数据”，还要求每项能力形成“发现问题—判断影响—给出建议—受控执行—回读结果—复盘效果”的闭环。

本版主要完善：

1. 将经营驾驶舱从数据展示升级为目标、同比环比、归因和待办入口。
2. 增加商品刊登工作台、内容质量评分、批量处理和版本对比。
3. 增加采购在途、库存调拨建议、滞销处理和库存资金占用。
4. 增加退货退款、赔付争议、结算对账和费用异常。
5. 增加促销日历、广告利润联动和活动前后复盘。
6. 增加规则自动化中心、通知中心、批量导入导出和运营模板。
7. 增加合规风险、账号健康、数据质量和运营目标管理。
8. 明确公开市场选品与竞品信息只能使用合法、获授权的数据来源，不默认采用网页爬虫。
9. 将智能体定位为受权限约束的运营协作者，不允许直接执行任意 SQL 或绕过审批。

## 2. 产品定位

ozonslj 是面向 Ozon 跨境卖家团队的运营效率平台。系统连接卖家自有店铺数据，将商品、价格、库存、订单、履约、售后、费用、利润、广告和内容运营统一到工作区，并通过异常、规则、待办和智能运营助手推动闭环处理。

产品核心价值：

- 用可信数据替代多页面人工抄录与核对。
- 用异常和机会排序替代无目标巡店。
- 用标准流程、模板和批量工具减少重复劳动。
- 用利润而非单一销售额约束价格、广告和促销决策。
- 用权限、预览、确认、幂等、回读和审计保护高风险操作。
- 用可追溯知识与业务工具支持自然语言运营。

## 3. 产品目标与指标

| 目标 | 建议衡量指标 |
|---|---|
| 降低巡店成本 | 日常人工巡店耗时下降 50% |
| 提高异常响应 | 严重异常在数据同步完成后 5 分钟内生成待办 |
| 提高商品维护效率 | 可批量处理的商品任务不再要求逐商品重复录入 |
| 降低缺货与积压 | 缺货天数、滞销库存金额和超龄库存持续可量化 |
| 保住经营利润 | 利润资料齐备订单的可计算覆盖率达到 95% |
| 提高履约质量 | 即将超时履约可提前发现并分派 |
| 保证操作安全 | 高风险写操作 100% 可追溯并完成回读核对 |
| 提高知识可信度 | 智能体知识结论附来源，业务结论附数据口径和时间范围 |

指标目标值应支持按组织、工作区和统计周期配置，不作为写死的系统常量。

首批经营驾驶舱默认采用北京时间（`Asia/Shanghai`），展示销售额、订单量、销售件数、客单价、贡献利润、贡献利润率、广告花费和退款金额，并支持今日、昨日、近 7 日、近 30 日及环比。

## 4. 用户、组织与权限

### 4.1 组织模型

- 首版为单组织、多卖家账户、多工作区。
- 一个卖家账户首版对应一个工作区；后续如官方账号层级需要再扩展映射。
- 数据库查询、缓存、任务、通知、审计和 RAG 均强制工作区隔离。
- 跨工作区汇总只能由具有相应授权的用户发起，并保留访问审计。

### 4.2 角色

| 角色 | 主要能力 |
|---|---|
| 管理员 | 组织、成员、角色、工作区、凭据、系统策略和运维设置 |
| 主管 | 经营目标、规则、审批、任务分配和跨工作区汇总 |
| 运营人员 | 商品、价格、库存、订单、内容、售后和日常待办 |
| 财务人员（新增） | 成本、汇率、费用、结算、对账和利润查看；默认不能改商品与库存 |
| 只读分析人员（新增） | 查看授权报表和导出脱敏数据，不执行业务写操作 |
| 智能运营助手 | 继承当前用户与工作区权限，不拥有独立权限 |

### 4.3 安全边界

- 用户采用账号密码登录，密码只保存强哈希。
- Ozon 凭据只在后端加密保存和使用，浏览器不得持久化。
- 后端必须逐请求鉴权，前端菜单隐藏不能代替权限校验。
- 高风险权限支持按操作类型、工作区、商品范围、金额或数量上限约束。
- 凭据查看、验证、轮换、失败和停用必须审计。

## 5. 数据来源与业务边界

### 5.1 允许的数据来源

- 当前官方 Ozon Seller API 提供且账号有权访问的自有店铺数据。
- 运营人员导入的成本、采购、在途、词表、目标和业务资料。
- 经授权的第三方服务或公开合规数据，必须记录来源、许可和更新时间。
- 经人工确认并具备来源的内部知识文档。

### 5.2 禁止和限制

- 首版不默认建设公开市场网页爬虫。
- 不绕过登录、验证码、限流、robots、平台协议或数据许可。
- 不虚构 Ozon 接口、字段、枚举、配额或更新时间语义。
- 原始上游响应不得无筛选落库，只保存规范化字段和白名单脱敏摘要。
- 每个 Ozon 适配器实施前必须复核官方文档、权限、版本、分页、限流和错误语义。

## 6. 功能需求

### FR-001 经营驾驶舱与目标管理（完善）

- 支持组织、工作区、类目、品牌、商品和日期维度。
- 展示销售额、订单量、销量、客单价、退款、广告花费、贡献利润和利润率。
- 支持今日/昨日、近 7/30 日、周环比、月环比和去年同期；数据不足时明确提示。
- 支持录入月度销售、利润、库存周转和履约目标，并展示目标完成率。
- 指标可下钻至商品、订单、履约、费用或异常证据。
- 自动解释主要变化来源，但必须展示统计口径、数据时间和归因依据。
- 提供“今日优先处理”清单，按利润影响、缺货风险、履约时限和严重程度排序。
- 支持保存个人视图、主管共享视图和定时导出。

### FR-002 异常、机会与团队待办（完善）

- 统一管理同步失败、审核失败、价格、库存、履约、售后、费用、广告和合规异常。
- 除风险异常外，也生成增长机会，例如高转化低曝光、有库存未投放、可提价和可补货商品。
- 每条事件包含类型、证据、影响范围、预计金额、置信度、建议动作和来源时间。
- 支持负责人、关注人、截止时间、评论、附件、状态、忽略原因和重新打开。
- 相同对象和规则在冷却期内合并，指标恢复后自动关闭或等待人工确认。
- 支持服务级别规则：即将到期提醒、逾期升级和主管汇总。
- 任务模板可把同类异常自动分配给指定角色，但不能自动执行高风险写操作。
- 首批覆盖同步失败、零价、价格剧烈变化、负利润、零库存、低库存、履约超时、费用异常、商品审核失败、退款异常、广告异常和合规风险。
- 异常采用紧急、严重、警告、提示四级制，结合预计金额影响、剩余处理时间和影响范围自动判级。
- 默认按“工作区 + 异常类型”配置负责人；未配置时分配给工作区主管，并支持逾期升级。

### FR-003 卖家账户与工作区（完善）

- 创建账户时录入显示名称、`Client-Id` 和 `Api-Key`，由后端验证有效性与权限范围。
- 凭据加密保存，支持版本、轮换、失效提醒和连接诊断。
- 展示各数据域是否有权访问，不能把“无权限”误报成“暂无数据”。
- 支持工作区启停、成员授权、默认币种、时区、成本口径和运营规则。
- 工作区停用后禁止新同步和写入操作，保留历史、任务和审计。

### FR-004 数据采集、同步与数据质量（完善）

- 同步策略为“首次有限全量 + 时间窗口增量 + 状态快照 + 周期性对账”。
- 覆盖商品、价格、库存、订单、FBO/FBS 履约；财务、售后、广告等按接口核验逐步加入。
- 稳定业务键幂等 UPSERT；外部 HTTP 不放入数据库事务，每页短事务落库。
- 同一工作区最多一个活动同步任务，支持优先级、心跳、租约、取消和恢复。
- 临时游标保存在任务中，只有完整成功才推进长期水位。
- 失败或部分成功不推进水位；完整快照成功后才允许软失效缺失商品或库存。
- 展示每个资源的最后成功时间、覆盖窗口、记录计数、延迟和错误摘要。
- 提供数据质量中心：缺字段、未知枚举、孤儿关系、币种异常、时间倒退和跨源不一致。
- 支持人工重新同步单资源或安全时间窗口，不允许无边界重复全量同步。

### FR-005 商品刊登与商品中心（大幅完善）

- 支持按工作区、状态、类目、品牌、标签、库存、销量、利润和负责人筛选。
- 展示 Offer ID、Ozon 商品编号、名称、类目、价格、库存、审核状态、销量和最后同步时间。
- 商品详情统一呈现内容、属性、图片、变体、价格、库存、表现、问题和版本历史。
- 建立商品内容质量评分：标题、类目、必填属性、图片、描述、关键词、本地化和合规风险。
- 识别审核失败、下架、类目错放、属性缺失、变体异常、重复 Offer、图片不足和内容过期。
- 支持草稿、模板复制、字段批量填充、批量查找替换、导入校验和错误行回传。
- 任何商品创建或内容回写都必须先生成差异预览，再人工确认、执行和回读。
- 保存商品内容版本，可比较修改前后流量、转化、退货和利润变化。

### FR-006 价格监控、定价与促销价保护（完善）

- 保存价格事实历史，展示当前价、原价、促销相关价格（如官方数据可用）及变更来源。
- 展示 7/30/90 日最低、最高、均价和变更时间线。
- 检测零价、缺失、异常涨跌、低于成本、低于利润线、超出品牌价带和回写不一致。
- 默认 24 小时变化超过 5%告警，可按工作区、类目和商品覆盖。
- 利润计算器联动输出保本价、目标利润价、最大促销折扣和汇率敏感区间。
- 支持固定价、利润底价、尾数策略和分层规则的建议预览，不默认无人值守改价。
- 改价流程：选择目标—冲突检测—影响预览—权限/审批—幂等执行—回读—效果跟踪—审计。
- 批量操作限制商品数、最大涨跌幅、最低利润、有效期和回滚/补偿方案。

### FR-007 库存、采购、在途与补货（大幅完善）

- 按商品、仓库和 FBO/FBS 展示可售、预留、在途、不可售和有效库存；以官方可用字段为准。
- 展示 7/14/30/60 日销量、日均销量、销售波动、预计可售天数和预计缺货日。
- 支持采购成本、安全库存、采购周期、最小采购量、箱规和供应商信息。
- 支持采购单和在途批次导入，记录预计到货、实际到货和数量差异。
- 生成补货日期、建议数量、缺货概率和计算依据，允许人工调整并记录原因。
- 识别零库存、低库存、滞销、超龄、库存不一致、异常预留和库存资金占用。
- 提供 FBO/FBS 库存结构建议和调拨建议，但不虚构平台仓间调拨能力。
- 库存写入采用与价格相同的受控操作闭环。
- 首版采购单与在途库存采用 Excel/CSV 模板导入，保留后续对接 ERP 的扩展边界。
- 低库存默认以预计可售天数为主、固定数量为辅，并允许按工作区、类目和商品覆盖。

### FR-008 订单、FBO/FBS 履约与物流（完善）

- 按时间、状态、履约模式、仓库、承运方式和异常类型筛选。
- 展示订单、一个或多个履约单、成交商品快照、物流和状态时间线。
- 商品删除或下架后仍保留成交时名称、编号、数量、单价和币种。
- 计算最晚处理时间和剩余时长，识别即将超时、已超时、长期不更新和物流异常。
- 支持拣货、打包、标签、交接和发运工作清单；具体写入能力实施前核验官方接口。
- 支持批次操作、扫描核对和重复操作保护。
- 取消、状态迁移、标签或文档操作属于高风险写入，必须预览、确认、回读和审计。

### FR-009 退货、退款、赔付与争议（新增）

- 在官方数据可用时同步退货、退款、取消、赔付或争议信息。
- 将售后记录关联订单、履约、商品、仓库、供应商和商品内容版本。
- 展示原因、阶段、金额、责任判断、材料截止时间和处理状态。
- 识别高退款率商品、重复原因、异常金额、即将超期和应申诉未申诉事项。
- 支持证据材料清单、内部处理意见和俄语沟通草稿。
- 提交申诉、退款或消息发送属于高风险动作，首版仅提供待办和草稿，实施前核验接口与法规。

### FR-010 利润计算器、费用与结算对账（大幅完善）

- 支持手工试算、商品计划利润、订单预计利润和结算实际利润。
- 成本至少包括采购、头程、尾程、佣金、履约、仓储、广告、促销、退款损失、税费和汇兑损益。
- 输出贡献利润、利润率、保本售价、目标利润售价和最大可承受广告/促销成本。
- 成本支持模板导入、版本、生效期、供应商和修改审计。
- 汇率记录来源、币种对、适用日期和版本，历史计算不随当前汇率覆盖。
- 建立结算对账：订单/履约预计费用与结算事实匹配，展示差额及原因。
- 检测重复扣费、未知费用、异常佣金、结算缺失、预计实际差异和负利润订单。
- 支持商品、订单、类目、工作区、费用类型和周期汇总。
- 数据缺失时标记“估算/不完整”，不得伪装成准确利润。
- 首批按完整贡献利润设计，覆盖采购、头程、尾程、佣金、履约、仓储、广告、促销、退款损失、税费和汇兑损益。
- 汇率默认每日自动获取并保存来源与版本；财务人员可以锁定结算汇率，历史利润不被后续汇率覆盖。

### FR-011 广告、促销与营销日历（完善）

- 在官方接口或授权数据可用时展示曝光、点击、CTR、CPC、花费、订单、ACOS、ROAS 和广告贡献利润。
- 识别高花费无转化、预算耗尽、缺货投放、低利润投放和搜索词浪费。
- 促销日历统一展示报名期、活动期、价格要求、库存要求和负责人。
- 活动前检查库存、利润、内容质量和履约能力；不满足条件时阻止建议直接执行。
- 活动后比较基线、活动期和活动后的销量、利润、自然流量和库存消耗。
- 广告或促销写操作必须经过权限、影响预览、人工确认、结果回读和审计。
- 评价、退货、广告和财务等扩展模块在连接账户后动态检测权限；无权限时明确展示原因并保持关闭。

### FR-012 商品分析、选品与竞品情报（新增）

- 基于自有店铺数据识别高增长、高利润、高退货、潜力和淘汰候选商品。
- 提供类目、价格带、销量趋势、季节性、库存周转和利润矩阵。
- 支持人工导入或授权来源的竞品快照，记录来源、采集时间和许可状态。
- 对竞品价格、内容、评价主题和促销变化提供比较，缺乏可靠数据时不得生成伪精确销量。
- 选品评分包含需求信号、竞争强度、预计成本、物流限制、利润、季节性和合规风险。
- 每个选品结论必须展示数据来源、时间范围、权重和不确定性。
- 竞品数据仅使用 Ozon 官方数据、获授权第三方数据和人工导入资料，不建设公开网页爬虫。

### FR-013 关键词挖掘与搜索表现（完善）

- 使用“关键词项目 + 分析版本”，可按类目、品牌、商品组或单商品创建。
- 来源包括自有内容、自有业务表现、官方允许的分析数据和人工/授权词表。
- 支持俄语词根、词形、单复数、拼写变体、同义词、否定词和中俄映射。
- 输出意图、相关度、热度证据、竞争证据、转化价值和推荐位置。
- 建立关键词—商品映射，防止同店商品无意竞争或关键词错配。
- 对标题、属性、描述和广告分别生成建议，并保留采用/拒绝原因。
- 版本发布后跟踪曝光、点击、转化和排名相关信号（以合法可得数据为准）。
- 关键词项目默认按商品组创建，同时支持类目和单商品范围，并检测同店商品关键词冲突。

### FR-014 俄语翻译与内容本地化（完善）

- 支持标题、卖点、描述、属性、客服草稿和运营资料的中俄互译。
- 使用类目术语库、品牌词、禁止翻译词、单位规范、敏感词和固定译法。
- 检查语法、自然度、关键词遗漏、字符限制、单位和合规表达。
- 展示原文、机器译文、人工确认和差异，支持审校状态与负责人。
- 翻译记忆复用已确认片段，记录模型、提示词、术语库和版本。
- 首版商品译文只复制或导出；自动回写须独立审批。
- 翻译采用可插拔多模型架构，记录模型、提示词、术语库版本、Token 用量和费用；具体模型接入前评估数据出境边界。

### FR-015 评价、问答与商品质量（完善）

- 评价、问答和消息能力必须按当前 Seller API 权限核验后启用。
- 提醒新评价、低星评价、未处理问题和高频负面主题。
- 聚类质量、包装、尺寸、物流、说明不符和使用困难等原因。
- 生成中文解释和俄语回复草稿，发送前人工确认。
- 关联退货、商品版本、供应商和批次，生成质量整改待办。
- 监控评分变化和评价处理时效，不通过诱导或违规方式干预评价。

### FR-016 合规、账号健康与风险中心（新增）

- 汇总商品审核、禁限售、知识产权、危险品、标签和内容风险。
- 展示账号连接状态、接口权限、凭据失效、同步连续失败和关键资源异常。
- 风险规则必须记录依据、适用范围、版本和维护人。
- 高风险商品允许暂停内部发布流程并要求主管复核。
- 系统只提供运营辅助，不替代平台规则、税务、法律或认证专业判断。

### FR-017 批量工具、导入导出与模板中心（新增）

- 支持商品、成本、采购在途、词表、目标和规则的模板化导入。
- 上传后先解析预览，显示新增、更新、忽略和错误数量；错误精确到行列。
- 支持部分通过与整批拒绝两种策略，由数据类型预先定义。
- 导入任务具备幂等键，重复上传不得产生重复业务数据。
- 导出支持当前筛选、字段选择、脱敏、异步生成、有效期和下载审计。
- 模板带版本、字段说明、示例、币种/时区说明和兼容范围。
- 批量操作显示目标数量、预计影响、失败项和可重试项。

### FR-018 自动化规则与通知中心（新增）

- 规则包含触发条件、范围、频率、冷却期、动作、负责人、启停状态和版本。
- 动作分为生成异常、创建待办、站内通知、外部通知和发起操作草稿。
- 首版规则不得直接执行改价、库存、履约、消息或广告写入。
- 支持规则试跑，以历史数据展示预计命中数量，发布前进行冲突检查。
- 通知支持站内为必选，邮件、企业微信、钉钉或其他渠道后续按配置接入。
- 支持用户订阅、免打扰、严重程度、聚合摘要和发送失败重试。
- 所有自动化命中、抑制、升级和通知结果可追溯。
- 首版仅提供站内通知；企业微信、钉钉和邮件作为后续可插拔渠道。

### FR-019 协作、审批与审计（完善）

- 异常、机会、导入、智能体建议和运营动作均可转为团队任务。
- 审批策略支持按操作类型、工作区、数量、金额、涨跌幅和角色配置。
- 审批人不能批准自己无权执行的操作；关键操作可配置双人复核。
- 支持 Web 与移动浏览器上的待办查看和轻量审批，不单独承诺原生 App。
- 审计记录操作人、工作区、请求编号、对象、前后摘要、审批链、结果和时间。
- 普通用户不能修改或删除审计记录，审计中禁止凭据和完整客户 PII。

### FR-020 智能运营助手（完善）

- 支持自然语言查询经营、商品、库存、履约、利润、广告、售后和异常。
- 对查询意图展示数据范围、口径、时间和工作区，避免模糊结论。
- LangChain 用于模型、嵌入、检索和类型化工具封装；LangGraph 用于状态、审批、超时和恢复。
- 智能体不得直连数据库、执行任意 SQL、调用任意 URL 或自创业务工具。
- 工具由后端白名单提供，显式携带用户、工作区、权限和请求编号。
- 只读工具可在授权后执行；写工具先生成结构化草稿与影响预览，再等待明确确认。
- 工具超时、数据过期、部分失败、回读不一致或结论低置信时停止扩大动作。
- 首批工具：今日异常、低库存、负利润、同步状态、商品诊断、俄语草稿和任务创建。
- 支持会话短期记忆、个人偏好、团队规则和组织知识，但记忆写入需分类、可查看和可删除。
- 采用可插拔多模型架构，按分析、翻译、生成和工具调用选择模型并记录费用、延迟和效果。
- 设置组织月度预算，在 70%、90% 和 100% 时告警；达到上限后暂停非必要生成任务。
- 首批只读工具覆盖今日异常、同步状态、商品诊断、低库存、负利润、履约风险、费用异常和经营指标解释。

### FR-021 RAG 运营知识库（完善）

- Chroma 保存文档分块和向量索引；PostgreSQL 保存目录、版本、权限、哈希、状态和审计。
- 来源包括项目文档、SQL 中文注释、领域语言、SOP、规则、经确认的官方知识和授权资料。
- 文档块包含来源、标题、版本、更新时间、语言、工作区可见性和内容哈希。
- 检索必须执行组织、工作区、角色和文档状态过滤。
- 回答附来源；无来源、来源过期或相互冲突时明确说明不确定性。
- 外部文档视为不可信数据，不能覆盖系统权限、审批或工具规则。
- 凭据、完整客户 PII、未脱敏日志和非必要订单明细不得进入向量库。
- 支持重新索引、版本回滚、删除传播和索引质量评估。

### FR-022 系统设置与运维（完善）

- Docker Compose 部署 PostgreSQL、Redis、API、Worker、Nginx/Web；Chroma 按资源评估加入。
- PostgreSQL 和 Redis 不开放公网，开发期数据库客户端通过 SSH 隧道访问。
- 当前保持公网 IP + HTTP 开发节点；进入内部试用或保存正式用户数据前必须配置域名、HTTPS 和正式身份认证。
- 提供健康检查、启动依赖、资源上限、重启策略、日志轮转和容量告警。
- 数据库迁移按版本与校验和执行，失败回滚并阻止不兼容应用启动。
- PostgreSQL 每日自定义格式备份，本地保留 14 天，定期隔离恢复演练并记录结果。
- 当前不配置异地备份，并将“服务器与本地备份可能同时丢失”登记为开发阶段已接受风险；正式运营前必须再次评审。
- 密钥使用服务器 Secret 文件或后续密钥服务注入，不写入镜像、Compose、Git、日志和 API。
- 提供同步、队列、数据库连接、磁盘、备份、接口错误率和任务积压监控。

## 7. 共用业务规则

### 7.1 统一受控写操作

价格、库存、商品内容、履约状态、取消、文档、消息、广告和促销等写操作统一采用：

`选择目标 → 校验数据新鲜度 → 生成差异预览 → 风险限制 → 审批/确认 → 幂等执行 → 分项结果 → 回读核对 → 审计 → 效果复盘`

禁止模型或规则引擎绕过此流程。官方接口不支持幂等时，系统必须使用请求指纹、短期去重锁和回读降低重复风险。

### 7.2 数据时间与口径

- 所有页面展示数据更新时间、统计范围和币种。
- 业务时间存储为 UTC `timestamptz`，按用户时区显示。
- 金额使用最小货币单位整数，外部编号使用文本。
- 当前状态、历史事实、计算结果和审计必须分开建模。
- 预计、已确认、已结算和不完整数据在界面上明确区分。

### 7.3 客户数据与脱敏

- `source_payload_json` 仅保存后端白名单生成的脱敏摘要。
- 不保存非业务必要的完整姓名、电话、邮箱和地址。
- 导出、日志、通知、RAG 和智能体上下文执行相同的最小化与脱敏规则。

## 11. 核心验收场景

1. 用户只能查看被授权工作区，跨工作区汇总也必须逐工作区授权。
2. 数据权限不足显示“无权限”，不显示为“暂无数据”。
3. 首次同步中断可恢复，失败任务不推进水位，单页缺失不误停用记录。
4. 驾驶舱指标可下钻到事实数据，并显示口径、币种和更新时间。
5. 严重异常只生成一条去重事件，能分派、升级、关闭和复盘。
6. 商品导入错误能定位到行列，重复上传不重复创建数据。
7. 价格跌破利润底线时阻止执行；确认后的改价完成回读与审计。
8. 补货建议展示销量窗口、采购周期、安全库存、在途和调整原因。
9. 履约即将超时时提前告警；商品下架后成交快照仍可查询。
10. 预计费用与结算差异可定位至订单、履约和费用类型。
11. 翻译保留品牌、型号和术语，人工确认版本可追溯。
12. 选品和竞品结论显示合法来源与不确定性，不伪造精确市场销量。
13. 智能体回答包含工作区、时间、口径和来源，过期数据有明显提示。
14. 智能体执行任意 SQL、跨工作区查询或未确认写操作时被拒绝并审计。
15. 容器重建后数据仍在，备份可恢复到隔离数据库且不影响生产库。

## 12. 已确认产品决策

1. 真实同步顺序为“商品/价格 → 库存 → 订单 → FBO/FBS 履约”。
2. 驾驶舱首批采用 8 个核心指标，以北京时间统计并支持常用周期与环比。
3. 首批采用扩展异常范围，包含审核、退款、广告和合规异常。
4. 低库存以预计可售天数为主、固定数量为辅。
5. 采购单与在途库存首版采用 Excel/CSV 模板导入。
6. 汇率采用每日自动获取加财务人工锁定，历史计算不被覆盖。
7. 首批利润计算按完整贡献利润设计，资料缺失时明确标记不完整。
8. 扩展数据模块按 Ozon 账号实际权限动态启用，无权限时显示原因。
9. 竞品数据只使用官方、获授权第三方和人工导入来源，不建设公开网页爬虫。
10. 关键词项目默认按商品组创建，并支持类目和单商品范围。
11. 俄语翻译采用可插拔多模型架构，具体模型接入前评估数据出境。
12. 首个受控写操作为商品价格，默认单批最多 20 个商品、涨跌不超过 10%，且不得低于利润线。
13. 首版只提供站内通知。
14. 智能体采用可插拔多模型架构。
15. 智能体设置月度预算，在 70%、90% 和 100% 时分级告警。
16. 智能体首批开放完整运营只读工具集，不直接开放写操作。
