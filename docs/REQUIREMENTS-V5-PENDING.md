# ozonslj 产品需求文档 V5（待确认）

> 版本：V5.1  
> 日期：2026-08-04  
> 状态：待确认

## 1. 本次变更摘要

V5 保留 V4 的组织、工作区、可信数据、日常运营闭环和受控写入原则，并新增四组能力：

1. 选品工作台：`explore`、`validate`、`expand` 三种研究模式。
2. Listing 工作台：俄语关键词分层、FABE 草稿、风险词检测和版本复盘。
3. 广告诊断：独立接入 Ozon Performance API，生成广告指标和优化建议。
4. 多 Agent 协同：销售、库存、广告、竞品、选品和汇总 Agent 只读运行。

V5 对 V4 已确认决策 9 提出变更：允许建设范围受控的公开页面采样层，但不得绕过登录、验证码、robots、服务条款或访问限制，不得把估算数据伪装成官方事实。

### 1.1 V5 与 V4 的关系

V5 是完整需求候选版本，不是只描述增量功能的附录。除本文明确提出变更的事项外，V4 已确认的经营驾驶舱、异常待办、卖家账户、同步、商品中心、库存、订单、履约、售后、利润、广告促销、规则、通知、知识与智能体安全要求继续有效。

V5 确认前采用以下治理规则：

- 开发中的已有功能继续依据 V4 和架构 V5，不因待确认内容改变行为。
- 只允许实施不会预判待确认决策的底层工作，例如 PostgreSQL 迁移、租户隔离、任务幂等和只读数据适配器。
- 公开采样、Performance API、审核写入和 Agent 编排必须等对应决策确认后再进入实现。
- 任一需求若与 Ozon 最新官方契约冲突，以官方契约为准并重新发起需求确认，不在代码中猜测兼容。

## 2. 产品定位与原则

ozonslj 是面向 Ozon 跨境卖家团队的智能运营工作台。系统整合店铺私有事实、广告数据、运营导入资料和合规公开样本，通过异常、研究、建议、审核、受控执行和效果复盘形成运营闭环。

必须遵守以下原则：

- 只服务 Ozon，不引入付费第三方市场数据订阅作为核心依赖。
- AI 与 Agent 默认只读，只能分析、生成建议、草稿、报告和待办。
- 上架、改价、改库存、修改 Listing、广告出价和预算等写操作必须人工确认。
- 官方事实、人工导入、公开样本、估算结果在存储和界面中明确区分。
- 每项结论必须携带工作区、时间范围、币种、来源、计算口径和不确定性。

### 2.1 用户与职责

| 角色 | 主要目标 | 允许能力 | 默认限制 |
|---|---|---|---|
| 组织所有者 | 管理组织和关键安全策略 | 组织、成员、凭据、审批策略和全部工作区 | 不能绕过写入预览、确认与审计 |
| 管理员 | 维护成员、工作区和系统配置 | 成员授权、凭据轮换、同步与运行诊断 | 不能转移组织所有权 |
| 运营主管 | 管理目标、异常、任务和审批 | 跨授权工作区汇总、分派、审批和复盘 | 只能访问获授权组织和工作区 |
| 运营人员 | 完成商品、库存、履约和增长工作 | 查询、导入、分析、草稿和待办处理 | 高风险写入必须提交审核 |
| 财务人员 | 维护成本、汇率和利润口径 | 成本导入、费用、结算、利润与对账 | 默认不能修改商品、库存和广告 |
| 只读分析人员 | 获取可信报表 | 查询和脱敏导出 | 不创建外部写入命令 |
| 智能运营助手 | 降低分析和报告成本 | 继承当前用户的只读工具和数据范围 | 无独立权限、无 SQL、无写适配器 |

### 2.2 租户和工作区边界

- SaaS 租户边界是组织（Organization），一个组织可拥有多个卖家账户和工作区。
- 用户必须先是组织有效成员，再通过组织角色或显式工作区授权访问业务数据。
- API、PostgreSQL RLS、Redis 键、任务、导入、导出、通知、审计、报告和 Agent 运行都必须带组织与工作区上下文。
- 跨工作区汇总必须逐工作区验证权限，不允许使用“组织管理员页面可见”代替后端授权。
- 工作区停用后禁止新同步、采集和写入，保留历史事实、报告、任务和审计。

### 2.3 产品目标与首批指标

| 目标 | 指标口径 | 首批目标 |
|---|---|---:|
| 降低巡店成本 | 每日人工巡店耗时 | 下降 50% |
| 提高异常响应 | 严重异常从同步完成到生成待办 | 不超过 5 分钟 |
| 提高数据可信度 | 业务结论含来源、时间和口径的覆盖率 | 100% |
| 提高选品效率 | 从导入资料到生成决策书草稿 | 不超过 10 分钟（不含外部采集等待） |
| 保证操作安全 | 高风险写入完成预览、确认、幂等、回读和审计 | 100% |
| 控制采集风险 | 被策略禁止后仍发起的公开请求 | 0 |
| 控制资源占用 | 核心服务在既定云服务器预算内稳定运行 | 无持续 Swap 压力和 OOM |

目标值支持按组织和工作区配置；上述数值是产品默认目标，不写死为不可调整常量。

## 3. 数据来源与可信度

| 来源 | 数据范围 | 可信度标签 | 主要用途 |
|---|---|---|---|
| Ozon Seller API | 自有商品、库存、订单、履约、财务和销售分析 | `official_private` | 店铺运营事实 |
| Ozon Performance API | 广告活动、关键词和效果报表 | `official_private` | 广告诊断 |
| 卖家后台报告导入 | 搜索词、成本、采购、在途、目标等 | `operator_imported` | 选品、关键词和利润 |
| 公开页面采样 | 标题、价格、评分、评价数、公开属性等 | `public_sample` | 竞品与类目样本 |
| 系统计算 | 利润、机会评分、市场估算、建议 | `derived_estimate` | 决策辅助 |

系统不得宣称能够以零成本获得全市场精确历史销量、损失销售额或完整搜索排名历史。公开页面数据只能表达采样时点和样本范围。

### 3.1 数据时间与新鲜度

- 事实记录使用 UTC `timestamptz`，界面按用户时区显示；首批经营报表默认 `Asia/Shanghai`。
- 每个数据域展示统计窗口、最后成功同步时间、数据延迟、记录数和错误摘要。
- 当前状态、历史事实、公开样本、计算结果和审计记录分开建模。
- 研究、建议和审核请求必须冻结所引用的数据版本；数据过期后必须重新计算或重新确认。
- 金额使用最小货币单位整数，币种使用 ISO 4217 三位大写代码，外部业务编号按文本保存。

### 3.2 数据质量规则

- 缺字段、未知枚举、孤儿关系、币种异常、负库存、时间倒退和跨源不一致进入数据质量中心。
- 公开样本价格偏离样本中位数超过 10 倍时标记异常，不直接用于聚合结论。
- 评分为 0 但存在评价、未来时间、非法 URL、响应类型异常等记录必须隔离。
- 数据不足时显示“资料不完整”及缺口，不以默认值生成看似精确的结果。

## 4. 功能需求

### 4.1 继承并继续实施的 V4 核心能力

#### FR-001 经营驾驶舱与目标管理

- 展示销售额、订单量、销售件数、客单价、贡献利润、贡献利润率、广告花费和退款金额。
- 支持今日、昨日、近 7 日、近 30 日、环比及按授权工作区下钻。
- 每项指标显示币种、时间范围、数据更新时间、计算口径和事实来源。
- 支持月度销售、利润、库存周转和履约目标，并生成按影响排序的今日待办。

#### FR-002 异常、机会与团队待办

- 统一管理同步、商品、价格、库存、履约、售后、费用、广告和合规异常。
- 异常包含证据、影响范围、预计金额、置信度、建议动作、负责人、截止时间和来源时间。
- 相同对象与规则在冷却期内去重；支持分派、升级、忽略、关闭和重新打开。
- 严重级别采用紧急、严重、警告、提示四级制。

#### FR-003 卖家账户、组织与工作区

- 支持组织、成员、角色、卖家账户、工作区和显式工作区授权。
- Seller 凭据由后端加密保存，支持创建、独立验证、轮换、失效、停用和权限诊断。
- Performance 凭据属于独立凭据域，不得与 Seller Api-Key 混用。
- 浏览器不得持久化 Ozon 凭据、数据库凭据或长期应用刷新令牌。

#### FR-004 同步任务与数据质量

- 按“商品/价格 → 库存 → 订单 → FBO/FBS 履约”顺序接入真实 Seller 数据。
- 同步采用首次有限全量、时间窗口增量、状态快照和周期性对账。
- 任务支持持久化、租约、心跳、幂等、取消、恢复、重试和部分失败。
- Redis 丢失后能从 PostgreSQL 恢复任务；失败任务不推进长期同步水位。

#### FR-005 商品、库存、订单与履约中心

- 商品中心统一展示内容、属性、价格、库存、审核状态、表现、问题和版本。
- 库存必须区分 FBO/FBS、仓库、可售、预留、在途、可售天数和滞销状态。
- 订单与履约只保存业务必要、脱敏的事实和成交快照，不保存非必要买家 PII。
- 首期提供只读查询、手动同步和风险预警，不修改订单或履约状态。

#### FR-006 利润、费用与结算

- 支持成本、汇率、采购、头尾程、平台费用、广告、退款和损耗资料。
- 区分预计、已确认、已结算和资料不完整的利润结果。
- 历史计算绑定汇率和成本版本，不被后续修改静默覆盖。

#### FR-007 规则、通知与批量工具

- 规则先提供预览/试跑，显示命中对象、预计影响和数据时间。
- 批量导入提供字段映射、校验、错误定位、文件指纹和幂等处理。
- 首期通知仅站内；外部渠道按待确认决策安排到 P2。

#### FR-008 受控操作与智能体安全

- 所有写操作遵循：选择目标 → 新鲜度校验 → 差异预览 → 风险限制 → 人工确认 → 幂等执行 → 回读 → 审计 → 复盘。
- 智能体只能调用参数化业务工具，不能执行任意 SQL、读取凭据、跨工作区查询或绕过审核。
- 模型输出不构成授权，提示词不能改变角色、权限、数据隔离和审核边界。

### 4.2 V5 新增能力

### FR-101 选品研究工作台

- 支持 `explore`、`validate`、`expand` 三种模式。
- `explore` 按搜索词热度、类目公开样本、价格带、评分和评价分布探索机会。
- `validate` 围绕目标 SKU 对比 3～5 个竞品快照、自有销售缺口、利润假设和 FBO/FBS 差异。
- `expand` 从种子商品或关键词扩展相关词、属性词、场景词和同类变体。
- 每次研究运行保存输入摘要、数据版本、算法版本、状态、来源统计和生成时间。
- 支持生成《商品立项决策书》草稿，包含机会摘要、市场样本、竞品对标、利润测算、风险和行动建议。
- 研究结果只能进入“待人工确认”，不得自动上架、采购、调价或投放广告。

### FR-102 搜索词报告导入

- 支持 CSV/XLSX 导入俄语搜索词报告。
- 导入前显示字段映射、编码、日期范围和预览；导入错误定位到行列。
- 保存搜索词、曝光、点击、加购、转化、排名等实际存在的字段，不虚构缺失指标。
- 相同工作区、报告类型、统计区间和文件指纹不得重复导入。
- 原始文件限时保存或导入完成后删除；长期保存规范化字段和脱敏导入摘要。

### FR-103 竞品种子与公开采样

- 运营人员手工录入 10～50 个核心竞品种子 URL 或 Ozon 商品编号。
- 采集前检查目标域名、robots、访问许可和采集策略；被禁止时停止并给出原因。
- 只采集公开展示的标题、价格、评分、评价数、主图 URL、公开属性和可验证的上架时间。
- 默认每域名并发 1、全局并发 2；429/503 遵守 `Retry-After` 或指数退避。
- 不轮换代理绕过限制，不绕过验证码，不访问登录后私有页面。
- 页面结构变化、字段缺失和采集失败必须可观测，旧快照不得被静默覆盖。

### FR-104 利润与 FBO/FBS 测算

- 用户输入采购成本、头程、尾程、佣金、支付费、广告比例、退货损耗和固定投入。
- 金额使用最小货币单位整数，比例使用明确精度的小数。
- 分别计算 FBO 与 FBS 的单件贡献利润、利润率、ROI 和盈亏平衡销量。
- 所有假设可保存为版本并显示缺失项；资料不完整时不得输出“精确利润”。

### FR-105 Listing 草稿工作台

- 支持俄语核心词、属性词和场景词分层。
- 生成标题、Search Attributes、FABE 卖点、长描述和主图卖点建议。
- 检测关键词重复、堆砌、绝对化疗效、未经授权品牌词和认证风险表述。
- 检测结果给出证据和修改建议，不自动删除用户文本。
- 草稿、人工修改、审核和发布结果形成版本链；发布写入必须走审核流程。

### FR-106 Performance API 与广告诊断

- Seller API 和 Performance API 使用独立凭据、认证流程、域名和限流策略。
- 支持读取账号实际有权访问的活动、关键词、否定词和报表。
- 计算 ACOS、TACOS、CPC、CTR、CVR、ROI，并显示公式、时间范围和数据完整度。
- 将关键词分为明星词、高 CVR 词、潜力词和高费无转化词；阈值可配置并版本化。
- 生成预算、出价和否定词建议；默认不写入 Performance API。

### FR-107 人工审核队列

- 所有外部写入建议进入统一审核队列，记录目标、差异、风险、数据新鲜度和预计影响。
- 支持批准、拒绝、退回修改、过期和取消。
- 批准不等于直接执行；系统先生成一次性幂等命令，再由执行器调用白名单接口。
- 执行后必须回读核对并记录分项结果；部分失败不得伪装成整体成功。

### FR-108 多 Agent 协同

- 销售 Agent：订单、销售额、客单价和退款异常。
- 库存 Agent：FBO/FBS 库存、可售天数、断货和滞销建议。
- 广告 Agent：广告指标、预算、关键词和异常建议。
- 竞品 Agent：种子竞品价格、评分、评价和内容变化。
- 选品 Agent：扫描关键词和类目样本，生成候选研究任务。
- 汇总 Agent：汇总各 Agent，生成日报、周报、月报和告警。
- Agent 继承当前用户和工作区权限，不持有写适配器，不执行任意 SQL。

## 5. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-101 来源透明 | 每条快照和结论记录来源类型、采样时间、统计窗口、是否估算和版本 |
| NFR-102 合规采集 | 遵守 robots、服务条款和限速；禁止绕过访问控制和验证码 |
| NFR-103 凭据隔离 | Seller、Performance 和应用会话凭据分别加密、轮换和审计 |
| NFR-104 数据最小化 | 买家 PII 不进入选品、竞品、广告、通知或 RAG 数据集 |
| NFR-105 可靠性 | 外部读取按错误类型退避；写入不做无边界自动重试 |
| NFR-106 资源预算 | 适配 2 核 2GB、约 4GB Swap 的现有 Linux 节点；P0 不引入 ClickHouse、向量数据库或爬虫集群 |
| NFR-107 可测试 | 自动化测试只使用 Stub、Mock、脱敏夹具和本地静态页面 |
| NFR-108 可访问性 | 关键流程支持键盘、明确标签和非颜色状态提示 |
| NFR-109 数据隔离 | 应用授权与 PostgreSQL RLS 双重约束；Redis、任务、导出和报告同样按组织/工作区隔离 |
| NFR-110 可恢复 | PostgreSQL 每日备份、迁移前备份、隔离恢复演练；Redis 状态可由 PostgreSQL 重建 |
| NFR-111 部署 | 使用 Docker Compose 与 ACR 镜像；服务器只拉取镜像，不在 2GB 节点本地构建 |
| NFR-112 可观测 | 监测服务健康、队列长度、任务年龄、外部限流、数据库连接、磁盘、备份和采集失败 |

### 5.1 已确认的云服务器约束

| 服务 | 资源上限 | 运行要求 |
|---|---:|---|
| PostgreSQL 16 | 512MB | `max_connections=30`，`shared_buffers=128MB`；唯一业务数据库 |
| Redis 7.4 | 128MB | 数据上限 96MB，`noeviction`；不保存唯一业务事实 |
| API | 320MB | 单 Uvicorn Worker；负责 REST、认证、权限和查询 |
| Worker | 192MB | 单进程；全局业务并发初始上限 2 |
| Nginx/Web | 64MB | 静态资源和反向代理；公网只开放该入口 |

- PostgreSQL 与 Redis 只在 Compose 内部网络；PostgreSQL 宿主机回环端口仅供 SSH 隧道，Redis 不映射宿主机端口。
- 数据库密码和 Ozon 加密主密钥使用彼此独立的 Compose Secret 文件，不进入 Git、镜像、普通环境变量或日志。
- 当前开发节点使用公网 IP + HTTP；内部试用或正式业务数据进入前必须完成域名、HTTPS 和正式认证。
- Swap 只用于突发保护，不计入正常容量；持续 Swap、OOM 或连接池耗尽视为容量/实现缺陷。
- PostgreSQL 每天 03:15（Asia/Shanghai）备份，开发阶段本地备份保留 14 天；结构升级前必须完成备份和隔离恢复验证。

## 6. 版本路线图

### V5.1 可信数据与同步（P0）

完成登录授权、Seller 凭据、商品/价格、库存、订单、履约同步、任务恢复和数据质量。

退出条件：授权用户能在云端工作区稳定查看真实、可追溯的 Seller 数据；容器重建、Redis 丢失和 Worker 重启不会造成业务事实丢失或跨租户访问。

### V5.2 选品 MVP（P0）

完成搜索词报告导入、竞品种子、合规公开采样、三种研究模式、利润测算和决策书草稿。

退出条件：一份脱敏搜索词报告和一组人工竞品种子可生成可复现决策书；所有公开样本明确标记采样范围和估算属性。

### V5.3 Listing 与广告诊断（P1）

完成俄语关键词库、Listing 草稿、风险检测、Performance OAuth 和只读广告诊断。

退出条件：Listing 和广告建议均可追溯到词表、报表、规则和版本，且不会触发真实外部写入。

### V5.4 审核与受控写入（P1/P2）

完成人工审核队列、白名单写入、幂等、回读、部分失败和审计。首个写能力仍为 V4 已确认的商品价格小批量受控修改。

退出条件：未授权、未确认、数据过期、超批量、超涨跌幅或低于利润线的请求全部被拒绝；批准后分项执行并完成回读。

### V5.5 多 Agent 协同（P2）

完成只读 Agent、定时报告、告警、汇总和可追溯复盘。

退出条件：Agent 通过跨租户、提示注入、任意 SQL、凭据访问和写入绕过测试；报告能追溯到事实快照和模型版本。

## 7. 核心验收场景

1. 一份脱敏搜索词报告可预览、校验、幂等导入并追踪来源。
2. 被 robots 或访问策略禁止的页面不会被采集，并产生可理解的停止原因。
3. 公开样本在界面上明确标记“公开采样/估算”，不显示为官方销量事实。
4. 三种选品模式能生成可追溯的决策书草稿。
5. FBO/FBS 利润结果能回溯到输入假设和算法版本。
6. Listing 风险词检测只给建议，原始草稿和人工版本均保留。
7. Seller 与 Performance 凭据无法相互替代，且不进入浏览器、日志或任务消息。
8. 广告建议不会自动变更预算、出价或否定词。
9. Agent 尝试跨工作区、执行 SQL 或调用写适配器时被拒绝并审计。
10. 自动化测试不访问真实 Ozon 账号或真实公开页面。
11. 用户只能访问所属组织和获授权工作区；API 过滤与 RLS 任一失效时仍不能跨租户读取。
12. PostgreSQL 是唯一业务事实来源；Redis 清空后排队和超时任务可以恢复。
13. 工作区停用后，新同步、公开采集、Agent 运行和外部写入均被拒绝，历史数据仍可按权限查询。
14. 数据权限不足显示“无权限”，不能伪装为“暂无数据”。
15. 容器重建后业务事实仍在，备份可恢复至隔离数据库而不覆盖运行库。
