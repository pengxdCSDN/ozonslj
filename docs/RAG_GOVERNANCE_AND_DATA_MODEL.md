# RAG 知识治理与数据模型设计

> 状态：已定档待开发。本文定义知识型混合 RAG 的治理事实、生命周期、关系模型和迁移边界；具体 PostgreSQL DDL 在实施阶段依据本文编写。

## 1. 设计目标与数据职责

知识系统采用混合存储，但职责不能混淆：

- PostgreSQL 是知识来源、版本、权限、切片目录、发布状态、索引任务、引用和审计记录的唯一治理事实来源。
- Chroma 是可重建的语义向量索引，只保存已发布、允许检索的切片向量和最少非敏感过滤元数据。
- Redis 只承担队列、短期锁、幂等协调和有限时缓存，不保存需要审计或恢复的知识事实。
- 首期原始 PDF 使用服务器私有持久化卷；不得由 Nginx 直接公开，也不得把文件二进制写入 PostgreSQL、Redis 或 Chroma。未来对象存储通过同一文件存储端口接入。

工作负载属于 `mixed`，数据路线为 `hybrid`：治理核心需要关系完整性和事务发布；解析结构、质量报告及策略扩展参数可使用受约束 JSONB；向量属于派生索引。

## 2. 所有权与首期范围

首期只有全局项目知识域，不接收工作区私有上传。所有知识仍必须记录逻辑所有者和适用范围，以便后续扩展时不破坏历史数据。

- `owner_type` 首期固定为 `project`，`owner_id` 使用项目知识域标识。
- `business_domain` 表示知识内容所属业务域，不能替代权限所有权。
- `authority_level` 固定为 A/B/C：A 是权威来源，B 是已确认内部知识，C 是一般参考资料；它不等同于发布时间、检索分数或模型置信度。
- 浏览器端不得提交所有权、来源等级或发布状态；这些字段只能由服务端治理流程决定。
- 未来引入工作区私有知识前，必须新增独立所有权和授权模型，不能仅向 Chroma 元数据追加可选 `workspace_id`。

文件元数据必须包含服务端文件 ID、内容哈希、MIME、字节数、页数、私有存储键、展示文件名、存储后端、创建时间和生命周期状态。私有存储键由服务端生成且不可预测，不能使用用户文件名、来源标题或绝对路径。文件二进制不进入关系模型。

普通运营创建的新来源默认 `authority_level=C`。授予或提升为 A/B 必须由 reviewer/admin 执行，记录原等级、新等级、理由、操作者和时间；降级也必须审计，因为它会影响回答资格和冲突裁决。版本替换不自动继承未经确认的新来源属性，不能通过上传新文件绕过等级审批。

## 3. 核心实体

| 实体 | 用途 | 关键关系 | 生命周期 |
|---|---|---|---|
| `knowledge_source` | 描述仓库文档、数据库目录、PDF 等逻辑来源 | 一对多版本 | draft → active/paused → withdrawn/deleted |
| `knowledge_document_version` | 冻结一次可审计的原始内容版本 | 属于来源；一对一或一对多解析运行 | received → parsing → ready/rejected → published/superseded/withdrawn |
| `knowledge_ingestion_run` | 记录一次接入、解析、清洗执行 | 属于文档版本 | queued → running → succeeded/failed/cancelled |
| `knowledge_parsed_node` | 保存统一解析结构节点目录 | 属于版本和解析运行；支持父子关系 | 解析产物，不独立发布 |
| `knowledge_chunk_strategy` | 注册业务域与来源类型允许使用的版本化策略 | 被切片运行引用 | draft → approved → deprecated |
| `knowledge_chunk_run` | 记录策略、参数和质量报告 | 属于文档版本与策略 | queued → running → review_required/accepted/rejected |
| `knowledge_chunk` | 保存稳定切片目录、原始证据和定位信息 | 属于切片运行和文档版本；可有父切片 | draft → indexing → published/withdrawn/deleted |
| `knowledge_index_version` | 表示一次完整可切换的关键词/向量索引版本 | 包含多个索引项目 | building → validating → active/failed/retired |
| `knowledge_index_item` | 记录切片在各索引后端的写入和删除状态 | 属于索引版本与切片 | pending → indexed/failed/deleting/deleted |
| `knowledge_publication` | 原子记录文档版本和索引版本的发布、替换、撤回 | 引用操作者及审批结果 | append-only |
| `knowledge_query_trace` | 保存一次查询的非敏感可复盘摘要 | 关联模型、索引和策略版本 | 按保留期清理 |
| `knowledge_answer_claim` | 保存回答中的独立结论和处理状态 | 属于查询追踪 | append-only |
| `knowledge_answer_citation` | 把结论绑定到实际切片及来源版本 | 属于结论与切片 | append-only |
| `knowledge_feedback` | 记录有用、错误、过期、缺失等反馈 | 关联查询、结论和操作者 | open → triaged → resolved/dismissed |
| `model_provider_config` | 保存供应商非敏感配置、适配器和治理状态 | 一对多凭据版本和模型配置 | draft → enabled/disabled → retired |
| `model_provider_credential` | 保存宿主机凭据文件的不透明引用与轮换元数据，不保存 API Key | 属于供应商配置；引用一个受限文件版本 | active → superseded/unavailable → destroyed |
| `model_purpose_binding` | 版本化绑定各用途的主模型与一个备用模型 | 引用供应商模型和评测资格 | draft → shadow → pilot/internal → retired |
| `model_pricing_version` | 保存供应商模型的版本化估算单价与币种 | 被调用用量引用 | draft → active → retired |
| `model_budget_policy` | 保存供应商日/月预算和用途级单请求上限 | 属于供应商账户与用途 | draft → active/paused → retired |
| `model_budget_period` | 保存日/月周期的预算、已预留和已结算汇总 | 属于预算策略与时间窗口 | open → closed/reconciled |
| `model_usage_ledger` | 记录每次调用的预留、实际 token、估算费用和结算 | 关联查询/任务、供应商、模型和定价版本 | reserved → settled/released/uncertain |
| `reference_exchange_rate` | 保存仅供管理展示的版本化 CNY 参考汇率 | 被展示汇总引用，不参与硬预算 | draft → active → retired |
| `rag_evaluation_case` | 保存 AI 生成或人工创建的评测案例、黄金声明与风险 | 引用来源版本和确认人 | draft → validating → confirmed/frozen → needs_review/retired |
| `rag_evaluation_run` | 保存一次分层评测执行及版本组合 | 包含多个案例结果 | queued → running/paused → passed/failed/cancelled |
| `rag_evaluation_result` | 保存单案例检索、回答、引用与指标结果 | 属于评测运行和案例 | pending → passed/failed/error |

## 4. 查询关键字段

以下字段必须是一等列，不能藏在 JSONB 中：

- 所有主键、外键、逻辑所有者和业务域；
- 来源类型、来源等级、敏感级别和语言；
- 内容哈希、源版本、解析器版本、清洗版本、切片策略与版本；
- 所有生命周期状态及创建、更新、生效、失效、发布、撤回时间；
- 文档标题、源定位、页码范围、标题路径和切片序号；
- 索引后端、Collection、嵌入模型、维度和索引状态；
- 查询意图、业务域、风险等级、降级状态和最终回答状态；
- 结论、引用、反馈之间的关系。
- 模型供应商适配器、启用状态、凭据引用/版本、用途绑定、能力资格和熔断状态；API Key 明文和宿主机绝对路径不得成为任何列。
- 供应商模型定价版本、币种、日/月预算、用途级输入/输出/调用上限、预算周期、预留量、结算量和告警状态。
- 文档、解析节点和切片的提示注入检测状态、风险类别、定位、检测器版本和人工复核结果；高风险未决状态不得藏在可忽略 JSONB 中。
- 上传隔离状态、文件结构检查状态、危险 PDF 特性、沙箱限制版本、资源终止原因、恶意软件扫描能力/结果及扫描器版本；`not_configured` 与 `passed` 必须是不同状态。

可以保留在 JSONB 中的内容仅限变化频繁且不承担核心过滤、唯一性或权限判断的扩展属性，例如解析器供应商的版面提示、实验性质量指标和非关键诊断信息。任何被稳定用于筛选、排序、报表或约束的 JSONB 字段必须升级为正式列。

## 5. 关键约束

1. 同一来源的 `source_version + content_hash` 唯一，确保重复接入幂等。
2. 同一文档版本、策略版本、参数哈希只能有一个被接受的切片运行。
3. `chunk_id` 由文档版本、语义定位、序号和内容哈希稳定生成；正文变化必须生成新哈希。
4. 切片必须属于与其来源相同的文档版本，不能跨版本复用数据库身份。
5. `effective_to` 必须晚于 `effective_from`；已过期内容不能进入当前索引。
6. 只有 `accepted` 切片运行产生的切片可以进入索引，只有验证成功的索引版本可以激活。
7. 同一知识域在同一索引后端最多只有一个 `active` 索引版本。
8. 已撤回、已删除、未发布或受限内容不得存在可用的当前索引项目。
9. 引用必须指向回答当时使用的文档版本和切片，不随未来版本替换而漂移。
10. 发布、替换、撤回和删除必须写入不可变审计记录，不允许覆盖历史动作。
11. 每个活动供应商凭据只能有一个当前版本；数据库只保存随机、不含路径语义的不透明引用。引用缺失、文件不存在、权限不是 `0600`、所有者不符或文件异常时不得调用供应商。
12. 凭据轮换必须先原子创建并验证新文件，再切换数据库当前引用；失败时保留旧版本，不能产生指向半写文件的引用。旧引用失效后按保留规则删除对应文件。
13. 用途绑定只能引用已启用、能力匹配且具有合格评测状态的模型；主模型与备用模型不得相同，首期不得存在第二备用模型。
14. 预算预留与周期计数必须在同一 PostgreSQL 事务中原子检查和更新；达到硬上限时不得创建成功预留，并发请求不能导致已预留总额越界。
15. 用量台账是追加式事实；结算通过状态和差额记录完成，不能覆盖历史 token 或费用。历史记录固定引用调用时的定价版本和币种。
16. 日/月周期使用服务端统一时区规则计算并保存明确起止时间；修改时区、预算或定价只影响新周期/新版本，不重算已关闭周期。
17. 首期预算时区固定 `Asia/Shanghai`；周期保存 UTC 起止时间、时区 ID 和本地周期日期，且同一策略/周期类型/本地日期唯一，避免重复创建窗口。
18. 硬预算使用供应商原始计费币种和 token 分别判断，任一超限即拒绝预留。CNY 参考汇率只能生成展示字段，禁止参与约束、结算或修改历史原币金额。
19. 可持久化缓存只能引用公开、非敏感、可重建的知识侧派生版本；最终答案、用户问题、查询 embedding、意图/重写输出和完整模型上下文不得作为缓存正文。
20. 撤回、安全删除、权限变化和版本切换必须先在 PostgreSQL 阻断使用，再发出缓存失效任务；缓存清理失败不能恢复被阻断内容的可检索资格。
21. 提示注入检测为阻断型治理事实；确定恶意、高风险未决或检测失败的版本不得发布。人工复核只能记录裁决和理由，不能删除原始风险记录或沿用到内容已变化的新版本。
22. 隔离文件在结构检查通过前不得转为可解析状态；JavaScript、启动动作、嵌入附件、外部资源、密码保护、资源炸弹或沙箱异常均阻断发布。病毒扫描未配置不得记录为通过。
23. AI 生成评测案例只能进入 `draft`；进入 `confirmed/frozen` 必须具有人工确认人、确认时间、来源版本、内容哈希和风险对应的授权角色。生成模型不能成为确认主体。
24. 开发/调参/冻结集合按近重复组和来源切片族隔离；同组样本不得跨集合。冻结案例变更只能创建新版本，不能覆盖已经产生发布证据的历史版本。
25. 首期确认集至少400例，集合角色固定为160例校准和240例冻结；冻结案例通过版本化清单加入30例快速、120例标准或240例完整运行。同一冻结版本的层级清单不可在运行中变化。
26. 评测结果状态必须区分 `passed`、`failed`、`error`、`skipped` 和 `not_run`；只有实际执行且满足断言的案例可计为通过，发布门禁要求目标清单无未执行或错误案例。
11. Chroma 记录 ID 必须与 PostgreSQL `chunk_id` 一致，禁止使用随机且不可对账的向量 ID。
12. 原始正文、清洗正文和检索增强正文需要分别存储哈希；增强文本不能覆盖原始证据。
13. C 级来源不能作为高风险操作、关键限制或确定性经营结论的唯一引用；该约束在证据选择和引用校验两层执行。
14. RAG任务状态、步骤、租约、尝试次数和结果由PostgreSQL持久化；Redis消息不得成为唯一任务记录。相同任务幂等键只能有一个未终结实例。

## 6. 生命周期与原子发布

### 新增

1. 创建或匹配逻辑来源。
2. 以源版本和内容哈希创建文档版本。
3. 接入、解析、清洗、敏感检查和切片全部写入非发布状态。
4. 生成嵌入并写入非当前 Chroma Collection 或索引命名空间。
5. 校验数量、维度、元数据、抽样检索和质量报告。
6. 在 PostgreSQL 事务中激活索引版本并记录发布事件。

任一步骤失败都不得改变当前已发布版本。

### 更新

更新永远创建新文档版本，不原地修改已发布正文。内容未变化时复用现有结果并记录幂等命中；内容变化时只重建受影响文档和切片。新版本通过验证后原子替换旧版本，旧版本保留用于历史引用和回滚。

### 撤回与删除

- 撤回先在 PostgreSQL 阻断检索，再异步删除 Chroma 和缓存中的派生数据。
- 删除默认是逻辑删除和检索不可见；物理清理遵循保留期与审计要求。
- 涉及凭据、个人信息或错误公开的安全删除必须进入高优先级清理流程，并验证 PostgreSQL、Chroma、Redis、私有持久化卷/未来对象存储和可清理日志中均无残留。
- Chroma 删除失败不能恢复内容可见性；系统持续重试并告警。

撤回操作必须记录结构化 `withdrawal_reason`，至少区分 `superseded`、`expired`、`corrected`、`security`、`sensitive_data` 和 `deletion_request`。前两类保留历史引用并标注历史状态；`corrected` 保留引用但显示不可靠警告；后三类立即隐藏正文和文件。物理清理后保留的审计墓碑只包含实体 ID、版本、内容哈希、撤回/删除时间、操作者、原因代码和清理完成状态，不包含标题以外的敏感正文或摘录。

### 重建

全量重建从 PostgreSQL 已发布版本生成新索引，不在当前 Collection 上原地清空重写。完成对账和抽样验证后再切换；失败时保留旧索引。

## 7. 主要访问模式与索引依据

| 查询模式 | 建议索引 | 原因 |
|---|---|---|
| 按所有者、状态、业务域获取当前来源 | `(owner_type, owner_id, status, business_domain)` | 管理列表与摄取路由 |
| 按来源查询版本时间线 | `(source_id, created_at DESC)` | 审核、替换与回滚 |
| 幂等检测 | 唯一 `(source_id, source_version, content_hash)` | 防止重复处理 |
| 获取当前已发布切片 | `(document_version_id, status, ordinal)` | 索引与引用展示 |
| 关键词检索 | 规范化检索文本的 GIN 全文索引，并辅以术语/字段精确索引 | 支持自然语言和标识符双路召回 |
| 索引 Worker 拉取任务 | `(status, next_attempt_at, created_at)` 部分索引 | 避免全表扫描与重复执行 |
| Chroma 对账 | 唯一 `(index_backend, index_version_id, chunk_id)` | 检测丢失、重复和漂移 |
| 查询追踪定位 | `(trace_id)`、`(created_at)`、必要时 `(answer_status, created_at)` | 复盘与保留期清理 |
| 过期复核 | `(review_due_at)` 部分索引 | 只扫描待复核知识 |

外键列必须根据删除和查询模式建立索引。全文配置需要使用实际中俄英语料验证；不能在迁移中假定一种分词配置覆盖所有语言。

## 8. 审计、保留与隐私

- 历史引用按来源状态和安全删除规则保存；安全与发布审计保留 1 年。查询追踪明细保留 30 天，聚合指标保留 180 天，用户反馈保留至结案后 180 天。
- 查询追踪不保存原始敏感问题、完整会话、完整模型提示词/原始响应或完整被过滤候选正文；复盘数据限定为脱敏问题、哈希、ID、版本、分数、原因代码、最终证据、延迟、token 和成本。
- 每次外部模型调用必须记录用途、供应商、模型版本、处理区域配置版本、数据策略版本、token 用量、耗时和结果状态；默认不保存完整输入输出正文。
- 安全、角色、凭据配置、知识发布/撤回/删除和策略变更审计在 PostgreSQL 保留1年，并每日导出只追加压缩 JSONL 到私有审计卷；归档批次保存时间范围、记录数、内容哈希和前一批次哈希，支持检测缺失或篡改。
- 180天聚合指标只保存时间桶、业务域/意图/组件等低基数字段以及数量、比率、分位延迟、token、估算费用、预算/熔断、任务与资源统计，不保存原始问题、提示词、引用正文、模型响应或可识别用户字段。
- 模型供应商和用途绑定是版本化治理事实；DeepSeek、MiniMax、GPT 等 API Key 不加密且不进入 PostgreSQL，只保存于宿主机受限凭据文件。PostgreSQL 保存不透明引用、版本、末尾掩码和变更审计，明文写入后不可回读。
- 凭据目录不进入数据库或普通文件备份。轮换必须记录旧/新凭据版本、文件创建与权限校验结果、引用切换结果和操作者，但不得记录明文、绝对路径或可预测文件名。
- 灾难恢复保留供应商配置、用途绑定和非敏感审计，但凭据状态统一重置/核验为 `credential_missing`；管理员重新录入并验证成功前不得将其改为 `active`。备份恢复流程不能根据旧不透明引用推断宿主机路径。
- 模型调用先创建预算预留，再按实际 token 和版本化单价结算；70%/90% 告警和 100% 硬停止均从 PostgreSQL 权威周期计算。供应商账单差异作为独立对账事实，不反向修改调用台账。
- 日/月预算按上海时区划分但以 UTC 保存边界；各供应商按自身计费币种执行硬预算。CNY 汇总引用版本化参考汇率并标记仅供展示，不能覆盖原币种台账。
- 当前有效原文件持续保留；正常替换、过期或普通纠错撤回的文件记录 `purge_after=withdrawn_at+30 days`；安全撤回、敏感信息和删除请求进入立即清理队列。每日备份保留 7 个点，清理账本必须覆盖备份副本的到期或提前删除结果。
- 不记录凭据、买家个人信息、完整 Ozon 响应、模型密钥或未脱敏日志。
- 原始文件与派生正文必须有删除账本，记录目标、请求时间、各存储后端完成状态和最终校验。
- 历史引用长期保留的是版本关系和非敏感审计链，不代表正文永久保留；安全撤回与物理删除优先于历史展示。
- 线上评测样本进入长期数据集前必须经过人工脱敏和授权确认。

## 9. 迁移实施顺序

本设计属于增量扩展，不修改现有业务事实表：

1. 新增知识来源、版本、策略、运行和切片表，不接入线上请求。
2. 建立状态约束、唯一约束、外键和小规模索引。
3. 使用仓库文档和测试 PDF 回填试验数据，验证幂等与生命周期。
4. 新增索引版本和索引项目表，接入 Chroma shadow Collection。
5. 完成对账、撤回和重建演练后开放只读查询。
6. 新增查询追踪、引用和反馈表，再接入回答生成。
7. 数据量增长后使用 `CREATE INDEX CONCURRENTLY` 等低锁方案补充线上索引；具体方式由迁移规模评估决定。

停止条件包括：出现跨版本引用、撤回内容仍可召回、重复切片不可解释、Chroma 无法从 PostgreSQL 重建、迁移锁影响核心 API，或资源持续超出开发服务器预算。
