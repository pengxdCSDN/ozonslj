# ozonslj 自动化优先设计

> 状态：产品设计基线  
> 更新日期：2026-08-22  
> 适用范围：Web、Chrome 侧边栏、API、Worker、Scheduler 和受控执行流程。

## 1. 核心理念

**一切尽可能自动化。**

本项目所说的自动化是“受控自动化”：在输入、来源、规则、权限和结果边界明确时，系统主动完成获取、校验、去重、匹配、计算、调度、告警、回读和复盘；数据缺失、来源冲突、合规阻断、高风险写入和不可逆经营决策由人工处理。

自动化不能成为绕过以下边界的理由：

- 不伪造或猜测缺失事实，不用默认值掩盖资料不足。
- 不把公开样本、运营导入或系统估算冒充 Ozon 官方私有事实。
- 不绕过登录、权限、预算、幂等、robots、限流和停止策略。
- 不自动执行未经授权的价格、库存、商品、广告或物流写操作。
- 高风险写入必须经过差异预览、人工审核、独立执行、回读和审计。

## 2. 页面自动化标准

每个页面应尽量形成以下闭环：

`自动加载上下文 → 自动获取/补齐 → 自动校验 → 自动解释 → 自动推荐下一步 → 自动或批量执行低风险动作 → 高风险动作转审核 → 自动回读 → 自动复盘`

页面设计至少回答九个问题：

1. 进入页面后能否自动加载当前工作区、最近时间窗和上次选择？
2. 能从可信接口读取的数据，是否仍要求用户重复填写？
3. 能从历史规则复用的数据，是否仍要求每个 SKU/任务重复配置？
4. 是否自动显示来源、更新时间、缺失项和估算标记？
5. 是否在提交前自动校验格式、范围、冲突和重复？
6. 是否能批量处理、定时运行或在上游成功后自动触发？
7. 失败后是否给出原因、影响范围、恢复动作和安全重试？
8. 高风险动作是否自动生成预览并进入审核，而不是直接执行？
9. 执行后是否自动回读结果、记录差异并用于下一次优化？

### 2.1 自动化成熟度

所有功能改造均按同一成熟度分级，避免把“能点一下”误认为自动化闭环：

| 等级 | 定义 | 验收边界 |
| --- | --- | --- |
| L0 手工 | 用户逐项录入并自行判断 | 仅允许作为尚未改造的现状，不作为目标状态 |
| L1 辅助 | 自动带入、校验、预览和解释 | 不替用户执行外部写操作 |
| L2 批量 | 同类低风险动作可批量处理 | 必须具备去重、幂等和逐项结果 |
| L3 事件/定时 | 上游事件或计划任务自动触发 | 必须有新鲜度门禁、失败重试和停止策略 |
| L4 闭环 | 自动执行、回读、对账和复盘 | 高风险动作仍保留人工审核，且全链路可审计 |

页面应在风险允许时逐步提升成熟度，不以“无人值守”为唯一目标。涉及经营写入、预算变化、公开采样和外部通知时，自动化程度必须服从权限、合规和可逆性。

### 2.2 每项自动化改造的实施包

“自动化改进”进入开发前，必须拆成可验收的实施包，并至少记录以下内容：

1. **触发器**：页面进入、上游任务成功、文件导入、定时计划或人工确认。
2. **输入与前置条件**：数据来源、字段、时间窗、新鲜度、规则版本和权限范围。
3. **自动动作**：系统具体完成的获取、映射、校验、计算、调度或回读步骤。
4. **风险分级与人工闸门**：低风险可自动执行；中风险先预览；高风险必须审核并独立执行。
5. **幂等、去重与并发**：定义业务唯一键、重复提交结果、锁或任务串行边界。
6. **重试与停止策略**：仅重试可恢复错误；认证、权限、合规和数据冲突立即停止并生成待办。
7. **结果回读**：自动确认目标系统状态，记录成功、部分成功、失败和差异。
8. **审计与指标**：记录执行主体、来源、规则版本、时间和结果，不记录凭据或客户敏感数据。
9. **恢复与回滚**：明确安全重跑、人工修正或补偿方式；不可逆操作不得假设可以自动回滚。

缺少上述任一关键边界的改善项，只能保留为设计建议，不得直接进入无人值守执行。

### 2.3 自动化冲突与死循环防护

已有功能可以继续独立运行，但在增加事件触发、定时任务和跨页面联动之前，必须先建立统一编排层。各页面不得自行互相调用或把“页面刷新”当作业务触发器。

统一使用单向处理链：

`外部事实同步 → 数据质量 → 领域计算 → 异常/建议 → 人工审核 → 受控执行 → 结果回读 → 对账与复盘`

以下反向触发一律禁止：

- 展示刷新触发外部同步。
- 利润、诊断或评测结果直接修改其计算规则。
- 建议生成直接触发外部写操作。
- 对账差异修改历史事实。
- 通知失败再次产生同类型通知。
- 评测结果写入被监测的业务知识源并再次触发评测。

高风险循环及强制处理规则如下：

| 循环场景 | 可能链路 | 强制边界 |
| --- | --- | --- |
| Seller 同步 | 同步 → 页面刷新 → 利润重算 → 再次同步 | 利润计算只能消费 Seller 事实；同步仅由定时计划、人工操作或明确上游任务触发 |
| 数据质量 | 导入 → 检查 → 自动修复 → 再检查 → 再修复 | 同一数据版本最多自动修复一次，随后只复检一次；仍失败则转人工待办 |
| 佣金/物流规则 | 利润变化 → 建议改规则 → 重算 → 再次建议 | 计算结果只能生成建议；新规则版本必须人工确认后生效 |
| 财务对账 | 财务同步 → 差异 → 调整规则 → 再次同步 | 财务事实仅由计划任务或人工同步；差异不得改写历史事实或反向触发同步 |
| 页面加载 | 页面刷新 → 创建同步 → 完成后再刷新 | 页面加载只读取现有数据；创建同步任务必须是独立动作 |
| Token 刷新 | 认证失败 → 刷新 → 重试失败 → 再刷新 | 单个请求链最多刷新一次并重试一次，仍失败立即停止并生成待办 |
| 外部通知 | 任务失败 → 通知失败 → 新任务 → 再通知 | 通知任务失败不触发同类型通知，只进入任务中心 |
| RAG 评测 | 知识更新 → 评测 → 结果写入 → 再次评测 | 业务知识、评测结果和运行日志分区存储；评测输出不发布知识源变更事件 |

编排层必须提供以下通用能力：

1. 每次运行生成唯一 `run_id`，并保存 `root_run_id`、`parent_run_id`、`trigger_source` 和数据版本。
2. 同一根任务、同一工作区、同一数据版本和同一自动化类型只允许成功执行一次。
3. 事件明确区分外部事实变化、领域事实变化、计算结果变化、建议生成和展示刷新；只有白名单事件可以触发下游任务。
4. 每条触发链设置最大深度，默认不超过 5 层；达到阈值立即熔断并转人工处理。
5. 每类任务明确最大重试次数、指数退避、不可重试错误和停止条件；认证、权限、合规及数据冲突不得盲目重试。
6. 所有任务使用业务幂等键和唯一约束，重复消息、重复点击或 Worker 重启不得产生重复事实。
7. 自动修复、Token 刷新和通知等特殊任务使用更严格的单次执行限制。
8. 审计记录完整触发链和熔断原因，但不得保存凭据、令牌或客户敏感响应。

开发结论：先完成事件分类、任务幂等、触发链追踪、重试停止和熔断机制，再启用任何跨页面自动联动。未经过防循环验收的改善项只能停留在 L1 辅助或人工触发的 L2 批量阶段。

## 3. 全页面自动化改进

表中的“改善方向”是产品设计目标；未在当前代码形成闭环的能力不得标记为已开发。

| 页面 | 当前可自动完成 | 建议改善方向 |
| --- | --- | --- |
| 运营总览 | 加载当前工作区商品与汇总状态 | 自动选择最近有效时间窗；异常按影响排序；直接给出可执行下一步；同步完成后自动刷新 |
| 商品与库存 | 读取 Seller 商品/库存事实并显示风险 | 增量同步、自动分类缺货/低库存/滞销；自动关联补货建议、利润和异常；详情页自动补齐规格来源 |
| 运营事实 | 汇总销售、订单、履约等只读事实 | 定时同步；跨商品/订单/履约自动关联；自动检测超时、状态停滞、费用异常和资料缺失 |
| 任务中心 | 展示任务状态和错误 | 自动重试可恢复错误；失败聚类；显示下一次重试时间；成功后触发质量检查和下游刷新 |
| 知识问答 | 检索、引用、拒答和模型降级 | 自动识别问题意图与工作区；推荐相关操作手册；知识过期时自动提示责任人与更新入口 |
| 知识源管理 | 解析、切片、索引、版本和质量门禁 | 监测源文件变更；自动创建待发布版本；失败按原因分流；低风险更新可批量预览 |
| 数据质量 | 自动加载摘要和开放问题 | 上游完成后自动检查；问题自动关联影响页面与修复建议；修复后自动复检关闭；严重问题生成待办 |
| 搜索词导入 | CSV/XLSX 解析、字段映射、预览、去重和批次历史 | 自动识别中俄英表头；记住来源映射；提供模板下载；批量/定时导入；成功后自动进入质量与 Explore |
| 竞品种子 | URL 校验、规范化、去重和状态管理 | CSV 批量导入；自动提取商品 ID/标题供确认；按研究项目分组；失效种子自动暂停 |
| 公开采样 | 合规策略检查和阻断记录 | 受控 HTTP 适配器、显式 `live-preview` 和 `live-collect` 已实现 HTTPS、服务端域名白名单、robots 先行检查、低并发、退避、公开字段解析、快照持久化和保存后质量事件；仍需完成快照质量规则的真实部署验收 |
| 探索选品 | 按搜索量、转化率、机会分和覆盖缺口筛选 | 默认读取最新有效搜索词批次与公开样本；自动保存筛选方案；定时发现新增机会并解释变化 |
| 选品验证 | 根据输入计算可行性和风险 | 自动带入 Seller 相似商品、最新成本/费率和竞品快照；缺失项一次性集中补录；自动生成验证清单 |
| 竞争分析 | 聚合竞品与选品指标 | 自动选择同类有效种子；按日/周更新变化；异常价格、评价和内容变化自动提示；保留样本范围 |
| 利润模型 | Ozon 商品同步、多选导入、规格/价格/佣金带入、物流模板预览、利润计算和财务只读同步 | 按类目与生效时间自动复用佣金规则；按仓库/线路/区域自动选物流版本；成本批量导入；财务明细自动匹配 SKU/订单并形成差异闭环 |
| 关键词策略 | 基于输入生成关键词分层和覆盖建议 | 自动读取已确认搜索词批次、现有 Listing 和广告词；自动标记新增/流失/冲突词；保存策略版本 |
| 标题草稿 | 生成候选标题 | 自动带入商品属性、关键词策略和禁用词；生成多版本并解释覆盖差异；保留人工选择反馈 |
| 内容风险 | 检查禁用词、属性缺失和内容风险 | 草稿变化后自动运行；按严重级别定位字段；可确定问题提供一键修复预览；修复后自动复检 |
| 受控发布 | 生成差异预览和审核流程 | 自动检查新鲜度、批量限制和利润线；审核后独立执行；自动回读 Ozon 结果并处理部分失败 |
| 广告活动 | Performance OAuth 后只读活动 | 定时增量同步；自动识别新增、暂停和异常活动；连接失效时自动刷新 Token 或生成明确待办 |
| 广告指标 | 读取并计算展示、点击、订单、销售额和花费 | 自动选择完整结算时间窗；按活动/商品/词聚合；异常消耗、无转化和数据延迟自动告警 |
| 关键词诊断 | 计算关键词表现和建议 | 自动融合搜索词导入、Listing 覆盖和广告指标；自动生成否定词/扩词建议，但写入必须审核 |
| 汇总报告 | 汇总只读运营指标 | 定时生成日报/周报/月报；自动解释变化和引用来源；待办去重；通知先预览后发送 |
| Performance 凭据 | 获取 Token、判断过期和验证连接 | 到期前自动刷新；失败按认证/权限/限流/网络分类；只显示脱敏状态；禁止回显令牌 |
| 模型供应商 | 配置供应商、模型和用途 | 自动健康探测、主备切换和失败冷却；模型能力/维度变更自动阻断不兼容用途 |
| 模型额度 | 统计日/月 Token、请求和预算状态 | 自动按 Asia/Shanghai 日切；70%/90%/100% 告警；超限自动降级；账单差异生成对账记录 |
| RAG 评测确认 | 执行评测、去重、展示指标和确认 | 知识/模型/策略变化后自动生成待评测任务；失败样例自动聚类；门禁未过禁止发布 |
| Seller 数据同步 | 创建只读同步任务、分页和任务追踪 | 按数据域定时增量同步；Token/权限检测；断点续传；成功后触发质量、指标和页面刷新 |
| Agent 权限 | 配置用途级工具边界 | 从角色模板自动生成最小权限；变更前展示差异；越权调用自动拒绝并记录审计 |
| 外部通知 | 配置模板和预览 | 严重事件自动生成通知草稿；合并重复告警；静默时段和重试；敏感字段自动脱敏；真实发送遵循授权 |

## 4. 优先改善顺序

### P0：减少重复输入并保证数据可信

1. 数据准备四页形成“导入/采样 → 自动质量检查 → 下游可用”的闭环。
2. Explore 默认读取最新有效搜索词批次，不再依赖页面内固定样本。
3. 利润模型自动复用佣金与物流规则版本，财务明细自动匹配 SKU/订单。
4. Seller/Performance 同步成功后自动刷新依赖页面，并显示数据新鲜度。
5. 所有页面统一显示来源、时间、缺失项、估算标记和下一步。

### P1：从手动点击升级为事件驱动和定时运行

1. Scheduler 按数据域执行增量同步、质量检查、报告和告警。
2. 任务中心提供安全重试、失败聚类和下游触发记录。
3. 公开采样在真实适配器完成后按启用种子低并发调度。
4. 知识、模型和检索策略变化自动创建 RAG 评测任务。
5. Performance Token 到期前自动刷新并验证只读连接。

### P2：形成自动复盘和持续优化

1. 预计利润与实际财务费用自动对账并建议更新规则版本。
2. Listing/广告建议执行后自动比较前后效果，保留人工采纳反馈。
3. 报告待办与质量问题、任务和审核请求自动关联并去重。
4. 自动化运行统计成功率、人工介入率、节省步骤、数据新鲜度和回读完整率。

## 5. 验收指标

- 可从可信来源自动获得的字段，不要求用户重复填写。
- 同一来源、同一格式的映射和规则可复用，重复文件不产生重复事实。
- 自动化结果的来源、时间、规则版本和执行主体覆盖率为 100%。
- 任何自动化失败都显示原因、影响范围和可操作恢复步骤。
- 高风险写入未经审核的执行次数为 0。
- 合规阻断后继续发出的公开采样请求数为 0。
- 同步、导入或采样成功后，相关质量检查和页面刷新可以自动触发。
- 自动回读可确认的执行，其回读和差异记录覆盖率为 100%。

## 6. 文档与改造落地规则

1. 用户操作手册的每个功能统一使用“功能描述、数据来源、格式与字段、作用、数据体现、当前操作、自动化改进”七段模板。
2. 每个“自动化改进”都必须映射到本文件的页面改善方向，并在开发计划中拆成实施包；不得只写“后续自动化”而缺少触发器和安全边界。
3. 实施状态统一标记为“现状、已设计、开发中、已开发、已验收”；只有代码、测试、文档和运行验收均完成后，才能标记为“已验收”。
4. 每次页面功能变化都检查其上游来源、下游用途、自动触发、失败恢复和回读对账，避免形成新的人工断点。
5. 自动化优先级按“减少重复劳动、提高数据可信度、缩短问题发现时间、降低经营风险”综合排序，不按技术实现便利程度排序。
