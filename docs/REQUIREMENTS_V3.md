# ozonslj 产品需求文档 V3（待确认）

> 版本：V3.0  
> 日期：2026-07-31  
> 状态：待产品确认  
> 适用范围：Chrome 扩展、Web 控制台、FastAPI 服务、Worker、PostgreSQL、Redis，以及后期智能体

## 1. 产品定位

ozonslj 是面向 Ozon 跨境卖家运营团队的异常驱动运营系统。系统通过 Ozon Seller API
采集自有店铺的商品、价格、库存、订单、履约和财务数据，在 Web 控制台与 Chrome 扩展中
形成统一工作台，并通过规则、待办和智能运营助手减少后台切换、人工核对和重复操作。

产品不是 Ozon 后台的页面复制，也不是无边界的自动化机器人。核心价值是：

1. 将分散数据标准化为可信、可追溯的经营事实。
2. 自动发现影响销售、利润、库存和履约的异常。
3. 为运营人员提供可解释的决策依据和处理建议。
4. 将价格、库存等高风险操作纳入预览、确认、执行、回读和审计闭环。
5. 让智能体通过受控业务工具协助运营，而不是直接操作数据库或任意调用 Ozon 接口。

## 2. 产品目标与衡量指标

### 2.1 产品目标

- 单一入口管理多个 Ozon 店铺工作区。
- 将运营模式从“逐页巡检”转变为“异常和待办驱动”。
- 建立商品、库存、订单、履约、费用和利润的一致数据链路。
- 降低中俄商品内容生产、关键词分析和数据解释成本。
- 在保证权限、幂等、审批和审计的前提下逐项开放受控业务操作。
- 支持 2 核 2GB Linux 单节点 Docker Compose 部署，并可平滑扩展。

### 2.2 首阶段建议指标

| 指标 | 目标 |
|---|---|
| 每日人工巡店耗时 | 相比完全人工流程下降 50% |
| 严重异常发现时间 | 数据同步完成后 5 分钟内生成待办 |
| 同步任务可追溯率 | 100% 有任务、分页、计数、水位和脱敏错误记录 |
| 高风险写操作审计率 | 100% 有预览、确认人、前后值、执行结果和回读结果 |
| 利润可计算订单覆盖率 | 成本和费用数据齐备订单达到 95% 以上 |
| 智能体回答来源覆盖率 | 涉及知识结论的回答 100% 附来源或明确标记无可靠来源 |

## 3. 用户、组织与权限

### 3.1 组织模型

首版采用单组织团队系统，一个组织可以管理多个店铺工作区。每个业务请求必须显式携带
工作区编号，数据库查询、缓存、RAG 检索、待办和审计均按工作区隔离。

### 3.2 角色

| 角色 | 主要职责 | 权限边界 |
|---|---|---|
| 管理员 | 系统、账号、成员和权限管理 | 可管理全部工作区与系统配置 |
| 主管 | 运营策略、审批和任务分配 | 访问被授权工作区，可审批高风险操作 |
| 运营人员 | 日常商品、库存、订单和内容运营 | 只访问被授权工作区，只执行被授权工具 |
| 智能运营助手 | 检索、分析、生成建议和发起工具调用 | 不拥有独立授权，继承当前用户与工作区权限 |

### 3.3 登录与授权

- 云端首版采用账号密码登录。
- 密码只保存强哈希，不保存明文或可逆密文。
- Ozon `Client-Id` 与 `Api-Key` 只进入后端凭据模块，浏览器不得持久化。
- 工作区授权必须在后端执行，前端隐藏菜单不能代替权限校验。
- 登录失败、权限拒绝、凭据验证和敏感操作必须进入安全审计。

## 4. 产品范围与边界

### 4.1 数据来源

- 首版数据采集仅指通过官方 Seller API 同步卖家自有店铺数据。
- 支持人工导入成本、词表和经确认的业务资料。
- 不把公开市场网页爬虫纳入首版范围。
- Ozon 具体端点、字段、权限、分页、限流和更新时间语义必须在实现对应适配器前重新核验。
- 上游原始响应不得无筛选写入数据库；只保存业务字段和白名单脱敏摘要。

### 4.2 首版核心数据域

- 商品及当前价格。
- 仓库库存和 FBO/FBS 履约模式。
- 客户订单、履约单及成交商品快照。
- 同步任务、同步水位、异常待办和操作审计。
- 商品成本、汇率、平台费用和订单贡献利润。

### 4.3 暂不承诺

- 未经官方能力核验的任意接口或字段。
- 自动回复客户、自动投放广告或无人值守批量改价。
- 绕过 Ozon 平台权限、配额或审核规则。
- 模型生成任意 SQL、任意 Ozon URL 或直接数据库写入。
- 将完整客户联系方式、地址、凭据或未脱敏日志写入 RAG。

## 5. 功能需求

### FR-001 运营总览与异常中心

- 展示今日、昨日、近 7 日及上周同期的销售额、订单量、销量和贡献利润。
- 展示缺货、低库存、价格异常、同步失败、履约超时、审核失败和费用异常数量。
- 异常按严重程度、预计影响、工作区和发生时间排序。
- 每条异常必须包含证据、影响对象、建议动作、负责人、状态和处理记录。
- 支持待处理、处理中、已解决、已忽略和重新打开。
- 支持规则去重和冷却时间，避免同一异常重复轰炸。
- 首版不强依赖短信或邮件，先提供站内待办；外部通知后续按需增加。

### FR-002 卖家账户与工作区

- 管理员可以创建卖家账户并输入显示名称、`Client-Id` 和 `Api-Key`。
- 后端必须验证凭据有效性和所需权限后才能启用账户。
- 凭据加密保存，支持版本和密钥轮换。
- 一个卖家账户首版对应一个工作区。
- 支持工作区列表、切换、停用和成员授权。
- 工作区停用后禁止发起新同步和写操作，但保留历史数据与审计。

### FR-003 数据同步

- 真实同步采用“首次有限全量 + 时间窗口增量 + 状态快照 + 周期性对账”。
- 商品、价格、库存、订单和履约使用稳定业务键幂等 UPSERT。
- 外部 HTTP 调用不得放入数据库事务；每页标准化数据使用短事务写入。
- 同一工作区任意时刻最多运行一个活动同步任务。
- 分页临时游标写入同步任务，完整成功后才推进长期水位。
- 失败和部分成功不得推进水位。
- 商品和库存只有在完整快照成功后才能软失效本轮未出现记录。
- 支持任务进度、插入/更新/失效/失败计数、心跳、租约、取消和安全重试。
- 展示数据新鲜度；超过资源时效目标时生成异常。

### FR-004 商品中心

- 按工作区、类目、状态、品牌、库存和关键字筛选商品。
- 展示 Offer ID、Ozon 商品编号、名称、价格、库存、状态和最后同步时间。
- 识别审核失败、下架、缺失属性、零价、无库存和变体关系异常。
- 支持商品详情、上游状态摘要和版本变更记录。
- 支持批量导出和批量编辑草稿。
- 商品内容回写必须在官方接口能力核验后单独评审。

### FR-005 价格监控与受控改价

- 保存自有商品价格变化历史，不只保存当前值。
- 展示当前价、变化时间、近 7/30 日最低价、最高价和平均价。
- 检测零价、价格缺失、越界、低于成本、低于目标利润和回写不一致。
- 默认规则：24 小时价格变化超过 5%生成告警，允许按工作区或商品覆盖。
- 支持价格规则，但首版只生成建议和操作预览。
- 受控改价流程必须为：选择目标 → 预览影响 → 人工确认 → 幂等执行 → 回读核对 → 审计。
- 批量改价必须设置最大商品数、最大涨跌幅和最低利润保护。

### FR-006 库存、补货与受控库存操作

- 按商品、仓库和 FBO/FBS 展示可售、预留和当前有效库存。
- 展示近 7/14/30 日销量、日均销量和预计可售天数。
- 支持安全库存、采购周期和在途数量的人工配置或导入。
- 生成低库存、零库存、积压库存和库存不一致异常。
- 生成建议补货日期和建议补货量，并展示计算依据。
- 库存写入与价格写入采用相同的预览、确认、幂等、回读和审计流程。

### FR-007 订单与 FBO/FBS 履约

- 按时间、状态、工作区和履约模式筛选客户订单与履约单。
- 展示一个订单对应一个或多个履约单的关系。
- 履约明细保存成交时 Offer ID、商品编号、名称、数量、单价和币种快照。
- 商品不存在或已下架时，历史履约明细仍可查询。
- 检测即将超时、已经超时、状态长期不更新和物流号异常。
- 支持异常履约待办、负责人和处理记录。
- 标签、拣货单、交接单和履约状态写入在官方能力核验后分切片实现。

### FR-008 利润计算器与财务分析

- 支持手工场景试算和真实订单自动带入两种模式。
- 成本项至少包括采购成本、头程/尾程物流、平台佣金、履约、仓储、广告、退款损失、税费和汇率损益。
- 输出贡献利润、贡献利润率、保本售价和目标利润售价。
- 订单日生成预计利润，结算数据到达后修正为实际利润。
- 支持商品、订单、类目、工作区和日期维度汇总。
- 标记缺少成本、缺少费用、异常汇率和预计/实际差异过大的记录。
- 成本支持表格导入、版本生效时间和修改审计。
- 汇率必须记录来源、币种对、适用日期和版本，不覆盖历史计算依据。

### FR-009 俄语翻译与商品本地化

- 支持标题、描述、卖点和属性值中俄互译。
- 使用 LLM、类目术语库、禁止翻译词和固定译法。
- 检查俄语语法、单位格式、关键词遗漏和敏感表述。
- 展示原文、机器译文、人工确认版本和差异。
- 建立翻译记忆，复用已确认短语。
- 保存模型、提示词、术语库和人工修订版本。
- 首版只支持复制与导出；自动回写商品内容不在首版范围。

### FR-010 关键词挖掘

- 采用“关键词项目 + 分析版本”管理。
- 项目可按工作区、类目、品牌或商品组创建。
- 数据来源包括自有商品内容、业务表现、官方允许的分析数据和人工词表。
- 支持种子词、俄语词根、单复数、拼写变体和中俄同义词归并。
- 输出候选词、聚类、搜索意图、相关度、竞争度、商业价值和证据来源。
- 为标题、属性、描述和广告分别给出使用建议。
- 支持待验证、已采用、无关、禁用和归档状态。
- 保存负责人、备注、关联商品和不同分析版本的效果对比。

### FR-011 评价、售后与商品质量

- 同步评价、问答或售后数据前必须核验 Seller API 当前能力和权限。
- 支持新评价、低星评价和高频负面主题提醒。
- 将问题聚类为质量、包装、尺寸、物流和描述不符等主题。
- 生成中文解释和俄语回复草稿，发送前必须人工确认。
- 将评价、退货原因与商品版本、仓库和批次关联分析。
- 首版不自动发送回复。

### FR-012 广告与促销分析

- 在利润数据可靠后接入广告与促销模块。
- 展示曝光、点击、CTR、CPC、花费、广告订单、ACOS、ROAS 和广告贡献利润。
- 检测高花费无转化、预算即将耗尽、广告商品缺货和广告商品负利润。
- 保存活动预算、出价、策略、商品和状态变化历史。
- 广告预算、出价、商品增删和停用操作必须经过权限、预览、确认和审计。
- 具体接口和指标必须在实现前核验官方能力，不虚构字段。

### FR-013 团队待办与审计

- 异常、人工任务和智能体建议可以转为待办。
- 待办包含工作区、类型、严重程度、负责人、截止时间、状态和处理记录。
- 记录认证、同步、读取敏感信息、审批和业务写入操作。
- 审计记录包含操作人、工作区、请求编号、目标、前后摘要、结果和时间。
- 审计不得包含 Api-Key、密码、完整客户联系方式、地址或可重放敏感请求。
- 审计记录不可由普通运营人员修改或删除。

### FR-014 智能运营助手

- 支持自然语言查询商品、价格、库存、订单、履约、利润和异常。
- 智能体使用 LangChain 封装模型、嵌入、检索器和类型化工具。
- 使用 LangGraph 编排意图识别、检索、工具调用、审批、超时和失败恢复。
- 智能体不得直接连接数据库或执行模型生成的任意 SQL。
- 所有工具显式携带当前用户、工作区、权限和请求编号。
- 只读工具可在授权后执行；写工具必须先输出结构化预览并等待明确确认。
- 结果不确定、工具超时或回读不一致时停止后续写入，不得扩大范围。
- 首批建议开放只读工具：异常查询、低库存查询、利润解释、同步状态和商品内容建议。

### FR-015 RAG 运营知识库

- Chroma 保存项目文档、业务规则、经确认的 Ozon 官方知识和授权运营资料的向量索引。
- PostgreSQL 保存文档目录、版本、权限、索引状态和审计；Chroma 不是业务事实来源。
- 文档块包含来源、标题、版本、更新时间、语言、工作区可见性和内容哈希。
- 回答必须返回来源；无来源、过期或冲突时明确提示不确定性。
- SQL 中文注释、数据库文档、领域语言和操作手册是重要 RAG 来源。
- 凭据、客户 PII、未脱敏日志和不必要订单明细不得进入向量库。
- 外部文档视为不可信输入，不能覆盖系统指令、权限和审批规则。

### FR-016 云端部署与运维

- 使用 Docker Compose 部署 PostgreSQL、Redis、API、Worker、Nginx/Web；Chroma 后续按资源评估加入。
- PostgreSQL 与 Redis 不开放公网，数据库客户端通过 SSH 隧道访问。
- 当前无域名阶段允许公网 IP + HTTP 作为开发节点；正式运营前必须配置域名和 HTTPS。
- PostgreSQL、Redis 和后续 Chroma 使用持久化卷。
- 提供存活、就绪检查、启动依赖、资源上限、重启策略和日志轮转。
- PostgreSQL 迁移按版本和校验和执行，失败回滚并阻止应用继续启动。
- 每日执行 PostgreSQL 自定义格式备份，至少保留 7 天，并定期完成隔离恢复演练。
- 密钥使用服务器 Secret 文件注入，不写入镜像、Compose、Git 或日志。

## 6. 数据与计算规则

### 6.1 数据所有权

- `store_workspace` 是所有卖家业务数据、同步、异常、任务和审计的隔离边界。
- Ozon 外部编号使用文本，不假设为整数。
- 金额使用最小货币单位整数，API 展示保持货币小数位格式。
- 业务时间使用 UTC `timestamptz`，界面按用户时区展示。
- 当前状态、历史事实和审计数据必须分开建模。

### 6.2 数据质量

- 每个资源展示最后成功同步时间和数据新鲜度。
- 上游字段缺失、类型异常和枚举未知时不得静默丢弃。
- 派生指标保存计算版本或可重建依据。
- 预计利润和实际利润必须显式区分。
- 价格、库存等历史事实不得通过覆盖当前状态伪造。

### 6.3 敏感数据

- `source_payload_json` 只保存后端白名单生成的脱敏摘要。
- 禁止保存完整客户姓名、电话、邮箱、地址以及未知上游字段。
- 浏览器只保存会话所需信息和选中的工作区编号，不保存 Ozon 凭据。

## 7. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-001 | 安全 | 凭据、密码和客户 PII 不进入浏览器持久化、日志、URL、RAG 和测试夹具 |
| NFR-002 | 隔离 | API、数据库查询、缓存、异步任务和 RAG 均强制工作区隔离 |
| NFR-003 | 性能 | 常规列表接口 P95 目标小于 500ms，不包含 Ozon 实时调用；列表必须分页 |
| NFR-004 | 可靠性 | 读取调用按错误类型重试并遵守 Retry-After；写操作不得无边界自动重试 |
| NFR-005 | 幂等 | 同步和受控写操作必须具有稳定幂等键、请求编号和回读核对 |
| NFR-006 | 可用性 | 所有页面提供加载、空数据、过期、部分失败、错误和重试状态 |
| NFR-007 | 可维护性 | pytest、Ruff、mypy、Schema、TypeScript、Vite 和 diff 检查必须通过 |
| NFR-008 | 可追溯性 | 数据同步、异常结论、利润计算、RAG 回答和业务操作均可追溯来源与版本 |
| NFR-009 | 本地化 | 产品文案、需求、设计、SQL 业务注释和开发说明使用简体中文 |
| NFR-010 | 可部署性 | 2 核 2GB 节点可稳定运行当前基础服务，并保留资源扩展余量 |
| NFR-011 | 可恢复性 | PostgreSQL 每日备份且恢复演练成功；结构升级前必须生成可用备份 |
| NFR-012 | 智能体安全 | 模型输出不构成授权，工具白名单、权限、审批和审计不可被提示词绕过 |

- 商品内容诊断、俄语翻译、术语库和翻译记忆。

## 10. 核心验收场景

1. 运营人员登录后只能看到被授权工作区。
2. 首次同步中断后可恢复，失败任务不推进水位。
3. 商品或库存单页缺失不会导致误停用，完整快照成功后才软失效。
4. 价格 24 小时变化超过阈值时生成一条去重异常并附证据。
5. 商品低于最低利润线时，系统阻止直接改价并要求重新确认。
6. 一个订单多个履约单可以正确展示，商品下架后历史成交明细仍存在。
7. 成本或费用缺失时利润明确标记“不完整”，不得展示为准确利润。
8. 俄语翻译保留品牌、型号和术语，人工确认版本可追溯。
9. 智能体回答“哪些商品库存不足 10 天且仍在投广告”时，只返回授权工作区数据和来源。
10. 智能体尝试执行任意 SQL、跨工作区查询或未确认改价时被拒绝并记录审计。
11. 应用容器重建后 PostgreSQL 数据仍存在，每日备份可恢复到隔离数据库。

## 11. 待确认决策
