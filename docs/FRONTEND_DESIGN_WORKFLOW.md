## 设计方向

产品是跨境电商运营控制室，不是营销落地页。界面采用“夜间控制室”方向：深墨蓝承载长时间工作，紫色表示当前操作和导航，青色表示可用数据，橙色表示需要关注，玫红表示阻断或错误。

设计必须保留一个有记忆点的签名元素，但只使用一个：当前项目为“紫色信号光轨”，用于页面标题左侧、面板顶部短光轨和选中导航，不把渐变、发光和圆角同时堆到每个控件上。

## 强制流程

1. 先确认页面任务、使用者、数据来源和最重要的一个动作。
2. 在改代码前写出简短的视觉方案：色彩、字体、布局、状态和签名元素；方案不能只是通用后台模板。
3. 优先复用 `styles.css`、`operations.css`、`desktop.css` 和 `frontend-design.css` 的设计令牌与组件 class，不在单个页面复制一套颜色。
4. 新页面必须同时设计加载、空数据、失败、重试、成功、禁用和权限不足状态；错误文案必须说明原因和下一步。
5. 表单、下拉、弹窗和导航必须有键盘焦点、可访问名称、Escape/外部点击关闭（适用时）和窄屏布局。
6. 使用真实 Stub/API 数据完成一次 Web 构建，至少检查桌面宽屏和 320px 窄屏；视觉变更应使用截图或实际页面复核。
7. 完成后运行 TypeScript 检查、Vite 构建和 `git diff --check`，并在提交说明中记录未验证项。

## 组件约定

- 页面标题使用 `.page-heading`，业务分组使用 `.panel` 和 `.section-heading`。
- 主动作使用 `.primary-button`，次动作使用 `.secondary-button`，文字型次要动作使用 `.text-button`；同一动作在等待期间必须禁用并显示进行中状态。
- 表单优先使用 `.form-grid`，字段标签和输入控件保持一一对应；API Key、Seller 凭据和其他 Secret 不得回显或写入浏览器持久化存储。
- 结果列表使用 `.operation-row`；质量、引用、审计和可追溯结果使用 `.quality-result`，空数据使用 `.empty-search`。
- 状态颜色只表达状态，不作为唯一信息：必须同时提供文字、图标或可访问标签。
- 新增图标统一使用 Phosphor Icons，不引入风格不一致的 Emoji 或临时 SVG。

## 当前实现基线

- `extension/src/frontend-design.css`：统一设计令牌、控制室背景、面板、表单、按钮、状态卡片和响应式规则。
- `extension/src/main.tsx`：最后加载设计层，确保既有页面和后续页面共享同一套视觉覆盖。
- 账号级 RAG、模型额度和 Performance 页面与店铺级 Seller/Agent 页面使用同一视觉系统，但权限和店铺门禁必须按领域边界实现，不能用样式掩盖权限问题。
