# Ozon 跨境电商运营插件开发计划

## 1. 项目目标

开发一个 Chrome Manifest V3 扩展，为 Ozon 跨境卖家提供商品、价格、库存、客户订单和履约数据的统一运营入口。可信 Python 后端负责保存凭据、访问 Ozon、持久化和审计。

## 2. 技术方案

- 扩展：React、TypeScript、Vite、Manifest V3。
- 后端：Python 3.12、FastAPI、Pydantic、Uvicorn。
- 当前唯一数据库：PostgreSQL 16，本地开发和云端节点共用版本化迁移。
- 云端节点：PostgreSQL、Redis、Linux Docker Compose 和 HTTP 开发入口；域名就绪后启用 HTTPS。
- 后期智能体：LangChain、LangGraph、RAG、受控业务工具和人工审批节点。
- 测试：pytest、临时 PostgreSQL 16、Stub、后续 Playwright E2E。
- 版本管理：Git，主分支为 `main`。

## 3. 开发阶段

### 阶段 0：需求与契约

- 明确目标卖家、区域、FBO/FBS 范围和所需数据。
- 核验 Ozon 官方接口、权限和配额。
- 完成领域语言、需求、架构、数据库和 API 文档。

退出条件：业务边界与第一版接口契约可评审。

### 阶段 1：本地基础

- FastAPI、PostgreSQL/Redis 配置、健康检查、调试配置和测试框架。
- Manifest V3 扩展、React 侧边栏和本地 API 客户端。
- Ozon Stub 与商品报价分页查询。

退出条件：开发人员可以本地启动、加载扩展并看到商品报价。

### 阶段 2：账户与工作区

- 运营人员会话。
- 卖家账户添加、凭据加密和验证。
- 店铺工作区隔离和切换。
- 认证与账户操作审计。

退出条件：多个卖家账户的数据与权限正确隔离。

### 阶段 3：只读 MVP

- 商品报价搜索与同步。
- 库存位置、客户订单和 FBO/FBS 履约单。
- 同步任务、部分失败、限流提示和最后同步状态。
- API、契约、集成和 E2E 测试。

退出条件：只读 MVP 达到需求和质量验收标准。

### 阶段 4：受控写入

- 每次只引入一种写能力。
- 提供操作预览、明确确认、幂等、审计和失败恢复。
- 优先评估价格或库存更新，不默认开放破坏性操作。

退出条件：每项写操作均完成风险评审和失败路径测试。

### 阶段 5：云端节点

- 将持久化适配器迁移到 PostgreSQL，并保留工作区隔离和版本化迁移。
- 建立 Chroma 向量库、后台执行器、健康检查和持久化卷。
- 使用 Docker Compose 在 Linux 部署反向代理、API/智能体服务、执行器、PostgreSQL 和 Chroma。
- 完成 HTTPS、应用身份认证、密钥注入、备份恢复、日志轮转和滚动升级说明。

退出条件：全新 Linux 服务器可以按中文文档重复部署，重启和升级不会丢失业务或向量数据。

### 阶段 6：智能运营助手

- 建立运营知识库的采集、切分、版本、元数据过滤和质量评估流程。
- 使用 LangChain 封装模型、嵌入、检索器和类型化工具。
- 使用 LangGraph 编排意图识别、RAG、工具调用、操作预览、人工确认和失败恢复。
- 首先开放只读自然语言查询，再逐项开放受控业务写操作。
- 增加提示注入、越权、跨工作区泄漏、幻觉、工具失败和审批绕过测试。

退出条件：运营人员能通过自然语言完成可追溯的查询；写操作无法绕过权限、预览、确认和审计。
