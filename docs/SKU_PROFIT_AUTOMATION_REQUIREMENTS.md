# SKU 自动利润计算需求与落地设计

## 1. 目标与交付范围

本功能面向当前单人运营场景，实现以下闭环：

`输入产品及 SKU → 按类目匹配佣金规则 → 按 SKU 计费重量匹配 FBS 物流分档 → 归集费用 → 输出分 SKU 预计贡献利润和盈亏平衡售价`

首期输出属于**推导估算**，不等同于 Ozon 结算后的实际利润。每个结果必须携带规则版本、来源和生效时间，缺少必需规则时阻断计算，不使用未标注的默认费率。

## 2. 对原始需求的调整

1. 系统优先尝试通过 Seller API 读取店铺商品、SKU、类目、价格、重量、尺寸、仓库和可用履约信息；但不假设 Seller API 一定提供完整的 FBS 预估费率或后台物流模板。每个同步字段都要标记 `official_private`、`manual`、`cached` 或 `missing`。
2. 物流模板由系统支持手动配置、CSV 导入和后续官方只读同步。FBS 与 realFBS 分开建模：FBS 预计费用可能依赖 Ozon 线路和订单上下文，realFBS 更接近卖家维护的配送方式；未获得完整费率时，系统必须显示“估算”并允许实际财务费用校准。
3. 物流计算使用“计费重量”，即实重与体积重的较大值。体积重系数属于物流模板版本，不能写死在代码中。
3. 佣金、支付、广告和预期退货损耗均以折后成交价为基数。每项单独按最小货币单位四舍五入，结果不使用浮点金额。
4. “盈亏平衡价”定义为在当前固定费用、费率和折扣假设下，使贡献利润首次不小于 0 的最低售价；由计算引擎按同一套舍入规则求解，避免公式与逐项舍入不一致。
5. 首期只计算 FBS 预计利润。FBO、整店批量、Excel 导出、真实结算对账和目标利润率反推价属于后续迭代，不混入首期验收。

## 3. 统一术语

- **利润测算**：一次固定输入、规则版本和算法版本的分 SKU 预计利润计算。
- **佣金规则**：类目在指定生效时间下对应的佣金费率版本。
- **FBS 物流模板**：包含体积重系数和按计费重量递增分档的物流费规则版本。
- **计费重量**：`max(实重, ceil(长×宽×高 / 体积重系数))`，内部统一使用克和毫米。
- **贡献利润**：折后成交价扣除预期退款、到岸成本、佣金、FBS 物流、包装、支付、广告及其他单件可变费用后的余额。
- **盈亏平衡售价**：按当前假设计算，贡献利润首次达到 0 的最低售价。
- **商品组**：由店铺商品报价、Ozon 商品编号或本地导入标识聚合的一组 SKU；商品组不是单一 SKU。
- **物流费率规则**：按照履约方式、仓库、线路、区域、生效时间、计费重量和附加条件计算预计物流费用的不可变版本。
- **预计费用**：在订单尚未结算时由费率规则推导出的费用，必须与实际结算费用分开保存。
- **实际费用**：从 Ozon 财务交易或结算报告归集的已发生费用，用于校准预计费用。

## 4. 输入、匹配与计算流程

1. 用户优先选择店铺中的 `offer_id`、`product_id` 或已同步商品组；只有新品不存在于 Ozon 时才手动输入商品和 SKU。
2. 系统通过后端只读同步商品报价、SKU、类目、价格、重量、尺寸、仓库和履约信息；字段缺失时保留缺失原因，不用商品名称猜测 SKU。
3. 用户补充 Ozon 无法提供的到岸成本、包装费、广告费率、退货损耗率和其他业务假设。
4. 引擎按 `category_id + 生效时间 + 费率来源优先级` 精确匹配一条佣金规则；未命中、重复命中或规则失效均阻断整次计算。
5. 引擎按 `履约方式 + 仓库 + 线路 + 区域 + 生效时间 + logistics_template_id` 选择物流费率规则，计算实重和体积重的较大值。
6. 按计费重量选择分档，并叠加适用的首重、续重、比例费、尺寸、偏远区域、退回和取消附加费用；无法确认所需上下文时输出“资料不完整”，不得给出伪精确金额。
7. 按费用瀑布计算每个 SKU，输出费用明细、利润、利润率、盈亏平衡价、数据来源和预计/实际状态。

### 4.1 用户实际需要提供的内容

已有 Ozon 商品时，用户只需选择 `offer_id`/商品组并补充到岸成本；包装费、广告费率、支付费率和退货损耗率可以使用工作区默认值。新品未上架时，用户还必须提供类目、售价、SKU、包装后重量和长宽高。

### 4.2 系统尝试自动获取的内容

| 数据 | 首选来源 | 缺失时的处理 |
|---|---|---|
| 商品与 SKU | Seller API 商品列表/详情 | 允许 CSV 导入或手动录入 |
| 类目、售价、重量、尺寸 | Seller API 商品属性/价格 | 标记缺失并阻断相关 SKU |
| 佣金 | Seller API 可用的当前价格/佣金字段，或手工规则 | 使用最近有效缓存并显示时效；无规则则阻断 |
| 仓库、履约方式、线路 | Seller API 或用户模板配置 | 必须由用户选择，不能从名称推断 |
| 物流费率 | 官方只读接口、用户模板、导入文件 | 无完整费率时只输出资料不完整 |
| 实际佣金和物流费用 | Seller API 财务交易/结算报告 | 订单产生后用于预计值校准 |

## 5. 权威计算口径

设折后成交价 `T = 售价 - 折扣`：

```text
预期退款损耗 = round(T × 退货损耗率)
净收入       = T - 预期退款损耗
佣金         = round(T × 佣金率)
支付费       = round(T × 支付费率)
广告费       = round(T × 广告费率)
贡献利润     = 净收入 - 到岸成本 - 佣金 - FBS物流费
               - 包装费 - 支付费 - 广告费 - 其他单件费用
贡献利润率   = 贡献利润 / 净收入
```

费率使用基点（1 bp = 0.01%），金额使用 RUB 戈比整数。若净收入为 0，则利润率返回空值。汇率换算不是首期利润判断依据，避免将汇率缺失变成核心计算阻塞。

## 6. 数据设计

采用关系型优先、计算快照使用 JSONB 的混合模型：

| 实体 | 关键字段 | 约束与用途 |
|---|---|---|
| 佣金规则 | category_id、rate_bps、version、source、effective_at | 同一规则版本不可变；计算结果引用其完整快照 |
| 物流费率规则 | template_id、fulfillment_type、warehouse_id、route_id、region_id、version、source、effective_at | 规则必须能说明适用履约、仓库、线路、区域和时间 |
| 物流计价分档 | max_chargeable_weight_g、base_fee、additional_fee、fee_rate | 上限严格递增；费用项分开保存，禁止把多种附加费塞入一个未知金额 |
| 物流附加条件 | max_length、max_sum_dimensions、remote_region、return/cancel policy | 不满足条件时阻断或进入资料不完整状态 |
| 利润测算快照 | 产品/SKU 输入、命中规则、费用结果、algorithm_version | 只追加不覆盖，确保历史结果可重放 |

首期 API 将规则目录与产品输入一起提交并返回计算结果；保存接口可把完整请求和结果写入现有 `profit_models` 快照。配置管理落库时采用新增表和双读迁移，不破坏历史 JSONB 快照。所有 Ozon 原始响应只保存脱敏、必要的标准化字段和来源指纹，不保存凭据。

### 6.1 物流模板 CSV

```csv
template_id,fulfillment_type,warehouse_id,route_id,region_id,version,effective_from,effective_to,volumetric_divisor_cm3_per_kg,max_weight_g,base_fee_minor,additional_fee_minor,additional_step_g,fee_rate_bps,remote_surcharge_minor,return_fee_minor,cancel_fee_minor,currency,source
fbs-main,FBS,warehouse-1,route-main,all,v1,2026-08-20,,5000,1000,5000,0,0,0,0,0,0,RUB,manual
fbs-main,FBS,warehouse-1,route-main,all,v1,2026-08-20,,5000,3000,8000,0,0,0,0,0,0,RUB,manual
```

导入必须先预览、校验分档顺序、日期重叠、币种、费率范围和模板覆盖范围；通过后生成不可变规则版本。

## 7. 边界与失败策略

- 售价必须大于 0；折扣不得大于或等于售价。
- 重量和三个尺寸必须大于 0；金额不得为负。
- 费率范围为 0～10000 bp，佣金、退货、支付和广告费率合计必须小于 100%。
- 同一类目出现多个有效佣金规则时拒绝猜测，返回明确冲突错误。
- 物流分档必须按上限严格递增；计费重量超出模板覆盖范围时拒绝估算。
- 任何 SKU 失败时整批不返回半套结果，便于用户修正后得到同口径结果。
- 不调用 Ozon 写接口；自动同步将来只能使用后端保存的凭据和官方只读接口。

## 8. 首期验收标准

1. 输入同一类目的 3 个 SKU，只配置一次佣金规则，三个结果自动使用同一佣金率并显示其版本和来源。
2. 三个 SKU 的规格落入不同物流分档，返回不同物流费、贡献利润和盈亏平衡售价。
3. 体积重高于实重时使用体积重；边界重量准确命中对应分档。
4. 佣金缺失、模板缺失、规格非法、费率总和达到 100% 或超出物流分档时，API 返回可操作的校验错误。
5. 修改规则版本后新测算使用新规则，已保存测算快照不被改写。
6. 负贡献利润结果有明确状态，前端同时展示金额与费用明细，不只用颜色表达。
7. 自动化测试不访问真实 Ozon；领域测试、API 测试、Ruff、mypy 和前端类型检查通过。
8. 同一 SKU 在不同仓库、线路、区域或生效日期下可以命中不同物流规则；缺少这些上下文时明确提示，不静默套用全局规则。
9. CSV 模板导入可以预览错误行、生成版本并导出标准化模板；历史版本不被覆盖。

## 9. 实现顺序

1. 物流模板领域模型、版本校验、CSV 预览导入和配置页面。
2. 商品选择与 SKU 自动展开，接入后端 Ozon 只读目录适配器；生产启用前必须用目标店铺脱敏响应完成上游契约验收。
3. 佣金、物流费率和财务交易的来源快照与校准。
4. CSV 结果导出、整店批量测算、预计/实际利润对账。

当前已增加实际费用 CSV 对账预览接口。它先计算差异，不直接覆盖物流模板或利润快照；后续保存功能必须保留来源、订单范围、导入批次和人工确认状态。

## 10. 后续迭代

- 独立的佣金规则和物流模板配置管理、启停、预览与版本回滚。
- 经官方文档核实后的 Seller API 只读费率同步；同步结果先预览，再生成新规则版本。
- 从商品报价导入 SKU 规格、整店批量计算和 CSV/Excel 导出。
- 目标贡献利润率反推售价、价格敏感性对比和 FBO/FBS 方案对比。
- 以订单、结算和实际费用生成“已确认/已结算利润”，与预计利润并存并对账。
