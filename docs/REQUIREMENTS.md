# Ozon 跨境电商运营插件项目需求文档

## 1. 产品概述

本产品是一款面向 Ozon 跨境卖家的 Chrome 运营插件。它通过本地 Python 后端安全访问 Ozon Seller API，在浏览器侧集中展示商品、价格、库存、客户订单和履约信息，降低多店铺日常查询与同步成本。

## 2. 产品目标

- 为运营人员提供快捷、清晰的 Ozon 店铺数据入口。
- 支持多个卖家账户，并保证不同店铺工作区数据隔离。
- 首期完成只读运营闭环，避免高风险写操作。
- 本地开发和云端节点统一使用 PostgreSQL；可连接本机服务或 Docker Compose 服务。
- 为后续价格、库存和履约操作预留安全可审计的扩展能力。
- 后期提供基于自然语言的智能运营助手，降低复杂查询和业务操作门槛。
- 后期支持在云 Linux 服务器通过 Docker Compose 部署独立运行节点。

## 3. 用户角色

| 角色 | 描述 | 主要权限 |
|---|---|---|
| 运营人员 | 使用插件管理一个或多个 Ozon 店铺的人员 | 登录、连接账户、查看数据、触发同步 |
| 应用系统 | 扩展/Web、FastAPI、PostgreSQL 与 Redis 组成的可信应用 | 校验、持久化、审计、调用 Ozon |
| 智能运营助手 | 理解自然语言并调用受控业务工具的系统角色 | 检索知识、生成计划、发起查询或待确认操作 |
| Ozon 平台 | 外部业务数据来源 | 根据卖家 API 权限返回或变更数据 |

## 4. 范围

### 4.1 MVP 范围

- 本地后端启动、健康检查和调试。
- Chrome Manifest V3 侧边栏。
- 卖家账户添加、凭据验证和工作区切换。
- 商品报价列表、搜索和分页。
- 价格及库存摘要。
- 客户订单、FBO/FBS 履约单列表与筛选。
- 手动同步、同步进度和最后同步时间。
- 加载、空数据、数据过期、权限不足和局部失败状态。
- 认证、查询和同步的审计记录。

### 4.2 非 MVP 范围

- 自动修改价格或库存。
- 履约推进、取消、归档、签署文件。
- 客服聊天、广告投放和财务自动化。
- 页面抓取作为业务数据或凭据来源。
- 云端部署、Docker 和智能体能力；这些属于后期范围，不影响本地 MVP。

### 4.3 后期范围

- 基于 LangChain 和 LangGraph 的智能运营助手。
- 使用 Chroma 构建运营知识库并提供 RAG 检索。
- 运营人员通过自然语言查询本地/云端业务数据、解释经营状态和生成操作建议。
- 自然语言业务操作通过受控工具进入现有应用服务，不直接暴露任意 SQL 或任意 Ozon 路径。
- 在云 Linux 服务器使用 Docker Compose 部署 API、智能体执行器、PostgreSQL、Chroma
  和反向代理组成的独立节点。
- 本地模式与云端节点模式并存；云端能力不得成为本地开发和测试的强制依赖。

## 5. 功能需求

### FR-001 本地系统启动

- 后端必须绑定本机回环地址。
- API 启动时按版本和校验和执行 PostgreSQL 迁移，失败时回滚并拒绝继续启动。
- 提供存活和就绪检查。
- 不安装 Docker、PostgreSQL 也能运行。

### FR-002 卖家账户管理

- 运营人员可以输入账户显示名称、`Client-Id` 和 `Api-Key`。
- 凭据只能提交到本地后端并加密保存。
- 后端验证凭据后创建店铺工作区。
- 无效、过期或权限不足时给出可理解的错误。

### FR-003 店铺工作区切换

- 支持列出已连接的店铺工作区。
- 当前选择必须在扩展重开后保留。
- 每次数据请求必须显式携带工作区编号。
- 一个工作区不得读取另一个工作区的数据。
- 当前已实现工作区目录、浏览器侧选择持久化和商品报价的工作区隔离。

### FR-004 商品报价

- 展示报价编号、Ozon 商品编号、名称、价格、币种和可用库存。
- 支持关键字搜索、分页和手动刷新。
- 显示数据来源、同步状态和最后更新时间。
- 当前已实现本地工作区的分页列表。

### FR-005 库存位置

- 按商品报价、仓库和履约模式展示库存。
- 支持无库存与低库存标识。
- 明确区分 FBO 与 FBS。

### FR-006 客户订单与履约单

- 按时间、状态和履约模式筛选。
- 展示客户订单与一个或多个履约单之间的关系。
- 展示商品明细、数量、状态和物流摘要。

### FR-007 同步任务

- 运营人员可以手动发起指定工作区的数据同步。
- 同一工作区应限制重复并发同步。
- 展示等待、运行、成功、部分成功和失败状态。
- 记录开始时间、完成时间、数量和脱敏错误信息。
- 失败、部分成功和运行中的任务不得推进长期同步水位。
- 同一工作区任意时刻最多运行一个同步任务。
- 商品和库存只在完整快照成功后软失效未出现记录。

### FR-008 审计

- 记录运营人员、工作区、操作类型、目标、结果和时间。
- 不得记录密钥和完整敏感客户数据。
- 后续所有重要写操作必须具备操作预览和审计记录。

### FR-009 Stub/Live 模式

- 默认使用 Stub 模式，无需 Ozon 凭据。
- Live 模式必须显式开启。
- 自动化测试不得调用真实 Ozon API。

### FR-010 智能运营助手

- 运营人员可以在指定店铺工作区内用自然语言查询商品、价格、库存、订单、履约和同步状态。
- 智能运营助手必须把自然语言意图转换为预定义、带类型且有权限边界的工具调用。
- 模型不得直接连接数据库、执行模型生成的任意 SQL，或接受任意 Ozon API 路径透传。
- 只读查询可以在权限校验后执行；重要写操作必须先生成操作预览并等待运营人员明确确认。
- 写操作继续遵守幂等、目标数量限制、部分失败处理和卖家操作审计规则。
- 每次智能体执行记录工作区、运营人员、模型/提示版本、工具调用、审批结果和脱敏输出摘要。
- 工具调用失败、超时或结果不确定时必须停止后续写步骤，不得自行扩大操作范围。

### FR-011 RAG 运营知识库

- 使用 Chroma 保存项目文档、业务规则、Ozon 官方接口知识和允许进入知识库的运营资料向量。
- LangChain 负责模型、嵌入和工具抽象，LangGraph 负责编排有状态流程、审批节点和失败恢复。
- 每个文档块必须保存来源、版本、更新时间、数据范围和工作区可见性元数据。
- 检索必须执行工作区和权限过滤，不得把一个工作区的私有资料返回给另一个工作区。
- 回答应附带可追溯来源；资料缺失、过期或相互冲突时必须明确提示不确定性。
- 凭据、完整客户隐私数据、未脱敏日志和不必要的订单明细不得写入向量库。
- 外部文档内容视为不可信数据，不得通过提示注入改变工具权限、审批规则或系统指令。

### FR-012 云端 Linux 节点

- 支持在主流 Linux 服务器使用 Docker Compose 部署单节点环境。
- 节点至少包含反向代理、FastAPI/智能体服务、后台执行器、PostgreSQL 和 Chroma。
- 数据库、向量库和应用数据使用命名卷持久化，容器重建不得导致业务数据丢失。
- 凭据和模型密钥通过服务器密钥文件或部署环境注入，不写入镜像、Compose 文件或仓库。
- 对外流量必须使用 HTTPS；扩展连接云端节点时必须使用独立应用身份认证和工作区授权。
- Compose 服务提供健康检查、启动依赖、重启策略、日志限制、备份和升级说明。
- 云端节点升级必须包含 PostgreSQL Schema 迁移、Chroma 数据兼容检查和可回滚备份。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-001 | 安全 | Ozon 凭据不进入浏览器存储、扩展包、日志、URL 和测试数据 |
| NFR-002 | 性能 | 常规列表接口本地响应目标小于 500ms；所有外部列表分页 |
| NFR-003 | 可靠性 | 读取请求区分可重试和不可重试错误，遵守 `Retry-After` |
| NFR-004 | 可用性 | 关键页面具备加载、空状态、错误和重试入口 |
| NFR-005 | 可维护性 | Ruff、mypy、TypeScript 与测试必须通过 |
| NFR-006 | 兼容性 | 支持当前稳定版 Chrome 与 Python 3.12+ |
| NFR-007 | 本地化 | 项目业务文档与面向运营人员的界面描述使用中文 |
| NFR-008 | 隐私 | 只保存业务所需字段，日志和审计采用最小数据原则 |
| NFR-009 | 智能体安全 | 模型输出不视为授权；数据库与业务操作只允许调用白名单工具 |
| NFR-010 | 可追溯性 | RAG 回答可追溯来源，智能体执行可追溯工具、审批和结果 |
| NFR-011 | 云端部署 | Linux Docker Compose 节点可重复部署、持久化、健康检查和备份恢复 |
| NFR-012 | 模型可替换 | 模型与嵌入提供方通过配置和端口隔离，不与业务领域模型耦合 |

## 7. 验收标准

### 7.1 当前本地 MVP

- 干净工作区按文档命令可启动后端并加载扩展。
- 首次启动会执行 PostgreSQL 版本化迁移并创建必要业务表。
- 停止、重启或重建应用容器后，PostgreSQL 命名卷中的数据仍可读取。
- 扩展能展示商品报价并处理分页、空数据和错误。
- 没有真实 Ozon 凭据也能运行全部自动化测试。
- 代码检查和生产构建通过。
- 数据库、API、架构与开发规范文档和代码保持一致。

### 7.2 后期智能体与云端节点

- 全新 Linux 服务器可以按文档执行 Docker Compose 部署并通过全部健康检查。
- 重启或重建应用容器后，PostgreSQL 业务数据和 Chroma 知识库仍然存在。
- 运营人员可以在授权工作区内通过自然语言查询业务数据，并看到答案来源和工具执行结果。
- 跨工作区检索、越权工具调用和模型生成任意 SQL 的请求会被拒绝并记录安全审计。
- 重要写操作在未经过操作预览和运营人员明确确认时不能执行。
- 模型、检索或工具故障不会导致重复写入、扩大目标范围或错误推进业务状态。

## 8. 里程碑

1. 基础垂直切片：健康检查、PostgreSQL、商品报价、侧边栏。
2. 账户与工作区：工作区目录、选择持久化和商品隔离已完成；凭据加密与账户验证待继续。
3. 只读 MVP：库存、订单、履约单、同步和审计。
4. 受控写入：逐项引入价格或库存变更，并增加预览、确认和恢复。
5. 云端节点：PostgreSQL、Chroma、Docker Compose、HTTPS、备份和升级。
6. 智能运营助手：RAG、自然语言查询、受控工具、审批工作流和智能体审计。

## 9. 待确认事项

- 运营人员登录方式：纯本地口令、系统账户或后续云端身份。
- 首批目标市场、Ozon 区域和 FBO/FBS 覆盖范围。
- 数据刷新策略：请求时刷新、缓存优先或定时同步。
- 本地凭据加密主密钥的保管方式。
- Ozon 各业务接口的当前版本、权限、配额和错误码需在开发对应功能前从官方文档确认。
- 云端身份认证、节点多租户模式和密钥管理方案。
- 大语言模型与嵌入模型提供方、成本预算、数据出境和可用区域。
- 运营知识库的文档来源、更新频率、保留期限和质量评估标准。
- 首批开放给智能运营助手的写操作类型及单次操作数量上限。
