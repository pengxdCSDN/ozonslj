# ozonslj 当前产品需求

> 本文是持续维护的产品需求入口，文档职责见 [项目文档索引](./README.md)。完整定档快照以 [需求 V5 已确认](./REQUIREMENTS-V5.md) 为准；本文沉积后续开发反复需要的稳定范围、规则和验收基线。

## 1. 产品定位

ozonslj 是供当前运营团队使用的 Ozon 智能运营工作台，以 Web 和 Chrome 扩展为客户端，连接 Seller API、Performance API、运营资料导入和合规公开样本。当前暂不建设多组织 SaaS 产品。

`发现问题或机会 → 分析影响 → 生成建议/草稿 → 人工审核 → 受控执行 → 回读 → 效果复盘`

产品目标是减少巡店抄数和后台切换，以利润约束选品、价格、广告与促销，并让每个结论可追溯到来源、时间、口径和不确定性。

核心理念：**一切尽可能自动化**。本项目采用“受控自动化”：只要输入、规则、权限和结果边界可以明确，系统就应自动完成获取、校验、去重、匹配、计算、调度、告警、回读和复盘；只在数据缺失、来源冲突、权限不足、合规阻断、高风险写入或不可逆经营决策时要求人工介入。

所有页面遵循同一自动化设计顺序：自动加载当前上下文 → 自动补齐可信数据 → 自动校验与解释异常 → 自动给出下一步 → 低风险操作可批量或定时执行 → 高风险操作生成预览并进入人工审核 → 执行后自动回读和记录效果。不得用“自动化”绕过来源标记、权限、预算、幂等、合规停止或人工审核。

## 2. 技术与运行基线

### 2.1 受控自动化要求

所有跨页面自动化必须经过统一编排层，不能由页面之间直接互相调用。自动化运行必须具备唯一运行标识、根任务/父任务关系、数据版本、触发来源、幂等边界、有限重试、最大触发深度和熔断转人工机制。事实同步成功后才允许发布事实变化事件；展示刷新、计算结果和建议生成不得反向触发同步或直接执行外部写入。高风险写入仍必须经过差异预览、人工审核、独立执行和结果回读。

- 所有环境唯一业务数据库为 PostgreSQL，不提供第二套业务数据库运行模式。
- Redis 只用于可恢复队列、锁、限流、短期令牌缓存和协调状态。
- 后端是 FastAPI 模块化单体；API、Worker、Scheduler 使用同一代码库的不同进程入口。
- Web 与 Chrome 扩展共享 React 组件、API 类型和业务状态。
- Ozon、模型、对象存储和邮件凭据只在后端使用，不进入浏览器或日志。
- 自动化测试使用 Stub/Mock，不访问真实 Ozon、真实公开页面或真实模型服务。
- 首期运行在 Linux 2 核、2GB、约 4GB Swap 的 Docker Compose；Swap 不作为正常容量。

## 3. 用户与权限

- 当前部署绑定一个内部组织，用户登录不选择组织；产品只面向同一运营团队。
- 暂不开发组织注册、切换、邀请、成员目录、套餐、组织设置和复杂工作区成员授权。
- 权限只覆盖登录、运营功能访问、卖家凭据管理和高风险操作审核。
- 智能运营助手继承当前用户的只读数据范围，没有独立超级权限。
- PostgreSQL `organization_id` 与 RLS 仅作为内部隔离基础保留，不列入 SaaS 功能开发任务。
- 工作区停用后禁止新同步、采集、Agent 和外部写入；历史事实和审计按权限保留。

## 4. 数据来源与可信度

| 来源 | 标签 | 主要用途 |
|---|---|---|
| Seller API | `official_private` | 自有商品、价格、库存、订单、履约、财务和销售事实 |
| Performance API | `official_private` | 广告活动、关键词、否定词和效果报表 |
| 运营导入 | `operator_imported` | 搜索词、成本、采购、在途、目标和词表 |
| 公开页面采样 | `public_sample` | 受控竞品标题、价格、评分、评价数、主图和公开属性 |
| 系统计算 | `derived_estimate` | 利润、机会评分、市场估算和建议 |

- 不用公开估算静默覆盖官方事实。
- 不宣称零成本获得全市场精确销量、损失销售额或完整排名历史。
- 公开样本必须显示采样时间、数量、范围和估算属性。
- 数据不足时显示缺失项，不用隐藏默认值输出精确结论。
- 金额使用最小货币单位整数，时间按 UTC 保存。
- 异常数据进入质量中心或隔离区，不静默参与分析。

## 5. 七模块范围

| 模块 | V5 范围 | 状态 |
|---|---|---|
| 基础环境 | Web、扩展、FastAPI、PostgreSQL、Redis、账号授权 | 地基 |
| 数据接入 | Seller、Performance、CSV/XLSX 和公开采样 | 地基 |
| 店铺打通 | 商品、库存、订单、FBO/FBS 履约同步；ERP 只预留端口 | 必需 |
| 选品 Skill | Explore、Validate、Expand、利润和决策书 | V5 重点 |
| Listing Skill | 俄语 SEO、关键词分层、FABE、Smart Search 和风险检测 | V5 重点 |
| 广告 Skill | 搜索/模板/登顶广告概念、Performance 只读分析和建议 | V5 重点 |
| 多 Agent | 销售、库存、广告、竞品、选品和汇总只读工作流 | V5 重点 |

首期不接领星或其他具体 ERP。采购、成本和在途先通过 CSV/XLSX 导入。不接付费第三方市场数据订阅作为核心依赖。

## 6. 选品、Listing 与广告

- Explore 输出候选机会，不输出全市场精确销量。
- Validate 使用目标成本、3～5 个核心竞品、自有相似商品和 FBO/FBS 参数，输出利润、ROI、盈亏平衡和风险。
- Expand 从种子商品、核心词、关联词和公开样本扩展可验证候选。
- 商品立项决策书固定包含机会、客户场景、搜索词、竞品、FBO/FBS 利润、风险、价格、备货、种子词、来源/不确定性和人工状态。
- Listing 生成俄语标题、Search Attributes、FABE、描述、主图建议、类目建议和覆盖报告；风险检测只高亮和建议，不覆盖原稿。
- 广告模块计算 ACOS、TACOS、CPC、CTR、CVR、ROI，并生成关键词诊断和新品 30 天建议；建议不自动写入。

## 7. 公开采样边界

- 首期只维护 10～50 个运营人员手工竞品种子，不遍历全站、全类目或搜索结果页。
- 只访问获准的公开 HTTPS 页面，遵守 robots、服务条款和采集启停策略。
- 不绕过登录、验证码和访问限制，不轮换代理/User-Agent 规避限流。
- 默认每域名并发 1、全局并发 2；429/503 遵守 `Retry-After` 或指数退避。
- 首期只使用受控 HTTP，不在 2GB 核心服务器运行 Chromium/Playwright。
- 规范化公开字段快照保留 180 天，原始 HTML 默认不落库。

## 8. AI 与 Agent 权限

- 模型通过可配置适配器接入，不绑定供应商。
- Agent 永久只读，不持有 SQL、凭据、文件系统或外部写适配器。
- Agent 只能调用参数化业务工具，创建建议、报告、待办和待审核请求。
- 首期使用自建持久化工作流，不使用 CrewAI/LangGraph。
- 提示词不能改变权限、内部数据隔离、预算或人工审核规则。
- 每次运行记录主体、工作区、时间窗、事实版本、工作流/模型/提示词版本、工具摘要、成本和输出。

## 9. 人工审核与受控写入

统一流程：

`选择目标 → 校验新鲜度 → 差异预览 → 风险检查 → 人工批准 → 幂等命令 → 独立执行 → 回读 → 审计 → 复盘`

首个写入能力是商品价格：每批最多 20 件、涨跌不超过 10%、不得低于利润线、过期后重新预览、部分失败分项展示。V5.4 启用独立 `execution-worker`；Agent、模型、Scheduler、API 请求线程和普通 Worker 均不得直接执行外部写入。

## 10. 非功能要求

- 严重异常在同步完成后 5 分钟内生成待办。
- 业务结论来源、时间和口径覆盖率 100%。
- 高风险写操作安全流程覆盖率 100%。
- 禁止采集策略生效后继续发出的请求数为 0。
- PostgreSQL 是业务和任务事实来源；Redis 清空后任务可恢复。
- PostgreSQL 每天 03:15（Asia/Shanghai）备份，开发阶段保留 14 天，并可恢复到隔离库。
- PostgreSQL 和 Redis 不开放公网；凭据使用 Secret 注入。
- 核心服务不得持续使用 Swap 或发生 OOM。

## 11. 开发路线与验收

实施顺序为 V5.1 可信 Seller 数据、V5.2 选品 MVP、V5.3 Listing/广告诊断、V5.4 审核写入、V5.5 多 Agent，具体退出条件见 [PROJECT_PLAN.md](./PROJECT_PLAN.md)。

跨阶段必须满足：

- API 与 RLS 共同阻止跨工作区串读，客户端不能改变服务端固定的内部组织边界。
- Seller/Performance 凭据完全隔离。
- Redis 清空后任务可从 PostgreSQL 恢复。
- 重复导入不生成重复事实。
- 被 robots/策略禁止的页面不发请求。
- 研究、利润和报告可追溯到输入与版本。
- Listing 风险检测保留原稿；广告建议不自动写入。
- 未批准、过期、超批量、超幅和低利润线改价全部拒绝。
- 容器重建后事实仍在；备份可恢复到隔离数据库。
# 当前交付范围：单组织运营系统

当前阶段只服务同一运营团队，不建设面向客户的多组织 SaaS 管理产品。用户登录只需要邮箱和密码；系统不提供组织注册、组织切换、成员邀请、组织目录、组织套餐或复杂的工作区成员管理界面。

数据库中的 `organization_id`、成员关系和 PostgreSQL RLS 继续作为内部数据边界保留，由部署配置绑定唯一运营组织。它们用于防止数据串读并降低未来扩展时的迁移风险，不代表当前产品需要运营人员理解或管理“组织”。新增功能不得因为内部字段存在而自动扩张组织管理需求。

当前权限只围绕运营工作职责和高风险操作控制展开；需要新增角色、成员管理流程或多组织能力时，必须作为新的产品需求单独确认。
## 2026-08-09 开发状态同步

- DAT-013 继续只保留 ERP 适配端口；采购、成本和在途仍以 CSV/XLSX 导入为首期路径，统一金额事实必须同时带 ISO 4217 币种。
- Seller 商品、库存、订单和 FBO/FBS 履约已具备快照历史查询的本地闭环；真实 Ozon 同步仍需官方契约与只读账号授权。
- 分页同步失败不得推进长期水位，Redis 清空后仍以 PostgreSQL 任务事实恢复；云端 Worker/Scheduler 恢复能力尚待实际验证。

## 12. 知识型混合 RAG（需求已确认，核心闭环已开发）

知识型混合 RAG 首期服务当前单用户内部运营场景，在现有工作台提供“知识管理”和“知识问答”入口。知识来源覆盖项目 Markdown、PostgreSQL 表/字段中文注释、文本层 PDF 和经 OCR 质量门槛通过的扫描 PDF。

- PostgreSQL 保存知识治理、版本、切片目录、发布、任务、追踪、反馈和评测事实；Chroma 是必须部署的语义向量索引，但不得成为唯一知识事实来源。
- 摄取链路必须经过数据源、接入、清洗、文档切片、嵌入、索引和发布门禁；不同业务与 PDF 文档支持可配置、多策略、版本化切片，切片具有完整元数据，并支持新增、更新、撤回、删除、对账和重建。
- 查询链路必须包含意图识别、受控查询重写、关键词与向量混合召回、融合、重排序、证据校验和带引用回答；一轮多意图逐片段处理，局部澄清或拒答不得吞掉其余安全片段。
- 意图无法识别、查询重写失败且原问题不可安全检索、证据不足、来源冲突或引用校验失败时，必须明确回答“不知道”或请求澄清，不得补写事实。
- 首期只回答知识问题，不承担实时经营事实查询，不执行任意 SQL，不触发 Ozon 或其他外部写操作。
- 模型供应商支持 DeepSeek、MiniMax、OpenAI/GPT 等可配置适配器，按用途配置主备模型、预算和配额降级；嵌入模型切换不得混用向量空间。
- API Key 按已确认方案保存于宿主机受限明文凭据文件，PostgreSQL 只保存不透明引用；不得进入浏览器存储、日志、截图、备份或 RAG 语料。
- 试运行由 `admin` 决定，可缩短为 1 天；当前仅一名用户时可由 `root/admin` 兼任运营、普通内容确认和发布，但自动质量与安全门禁不放宽。
