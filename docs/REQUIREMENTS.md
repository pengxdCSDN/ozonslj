# Ozon 跨境电商运营插件项目需求文档

## 1. 产品概述

本产品是一款面向 Ozon 跨境卖家的 Chrome 运营插件。它通过本地 Python 后端安全访问 Ozon Seller API，在浏览器侧集中展示商品、价格、库存、客户订单和履约信息，降低多店铺日常查询与同步成本。

## 2. 产品目标

- 为运营人员提供快捷、清晰的 Ozon 店铺数据入口。
- 支持多个卖家账户，并保证不同店铺工作区数据隔离。
- 首期完成只读运营闭环，避免高风险写操作。
- 本地安装后无需 Docker 即可运行、调试和保存数据。
- 为后续价格、库存和履约操作预留安全可审计的扩展能力。

## 3. 用户角色

| 角色 | 描述 | 主要权限 |
|---|---|---|
| 运营人员 | 使用插件管理一个或多个 Ozon 店铺的人员 | 登录、连接账户、查看数据、触发同步 |
| 本地系统 | 扩展、FastAPI 与 SQLite 组成的可信应用 | 校验、缓存、审计、调用 Ozon |
| Ozon 平台 | 外部业务数据来源 | 根据卖家 API 权限返回或变更数据 |

## 4. 范围

### 4.1 MVP 范围

- 本地后端启动、健康检查和调试。
- Chrome Manifest V3 侧边栏。
- 卖家账户添加、凭据验证和工作区切换。
- 商品报价列表、搜索和分页。
- 价格及库存摘要。
- 客户订单、FBO/FBS 履约单列表与筛选。
- 手动同步、同步进度和最后同步时间。
- 加载、空数据、数据过期、权限不足和局部失败状态。
- 认证、查询和同步的审计记录。

### 4.2 非 MVP 范围

- 自动修改价格或库存。
- 履约推进、取消、归档、签署文件。
- 客服聊天、广告投放和财务自动化。
- 页面抓取作为业务数据或凭据来源。
- 云端部署、Docker、微服务、消息队列。

## 5. 功能需求

### FR-001 本地系统启动

- 后端必须绑定本机回环地址。
- 首次访问数据时自动创建 SQLite 文件和必要数据表。
- 提供存活和就绪检查。
- 不安装 Docker、PostgreSQL 也能运行。

### FR-002 卖家账户管理

- 运营人员可以输入账户显示名称、`Client-Id` 和 `Api-Key`。
- 凭据只能提交到本地后端并加密保存。
- 后端验证凭据后创建店铺工作区。
- 无效、过期或权限不足时给出可理解的错误。

### FR-003 店铺工作区切换

- 支持列出已连接的店铺工作区。
- 当前选择必须在扩展重开后保留。
- 每次数据请求必须显式携带工作区编号。
- 一个工作区不得读取另一个工作区的数据。

### FR-004 商品报价

- 展示报价编号、Ozon 商品编号、名称、价格、币种和可用库存。
- 支持关键字搜索、分页和手动刷新。
- 显示数据来源、同步状态和最后更新时间。
- 当前已实现本地工作区的分页列表。

### FR-005 库存位置

- 按商品报价、仓库和履约模式展示库存。
- 支持无库存与低库存标识。
- 明确区分 FBO 与 FBS。

### FR-006 客户订单与履约单

- 按时间、状态和履约模式筛选。
- 展示客户订单与一个或多个履约单之间的关系。
- 展示商品明细、数量、状态和物流摘要。

### FR-007 同步任务

- 运营人员可以手动发起指定工作区的数据同步。
- 同一工作区应限制重复并发同步。
- 展示等待、运行、成功、部分成功和失败状态。
- 记录开始时间、完成时间、数量和脱敏错误信息。

### FR-008 审计

- 记录运营人员、工作区、操作类型、目标、结果和时间。
- 不得记录密钥和完整敏感客户数据。
- 后续所有重要写操作必须具备操作预览和审计记录。

### FR-009 Stub/Live 模式

- 默认使用 Stub 模式，无需 Ozon 凭据。
- Live 模式必须显式开启。
- 自动化测试不得调用真实 Ozon API。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-001 | 安全 | Ozon 凭据不进入浏览器存储、扩展包、日志、URL 和测试数据 |
| NFR-002 | 性能 | 常规列表接口本地响应目标小于 500ms；所有外部列表分页 |
| NFR-003 | 可靠性 | 读取请求区分可重试和不可重试错误，遵守 `Retry-After` |
| NFR-004 | 可用性 | 关键页面具备加载、空状态、错误和重试入口 |
| NFR-005 | 可维护性 | Ruff、mypy、TypeScript 与测试必须通过 |
| NFR-006 | 兼容性 | 支持当前稳定版 Chrome 与 Python 3.12+ |
| NFR-007 | 本地化 | 项目业务文档与面向运营人员的界面描述使用中文 |
| NFR-008 | 隐私 | 只保存业务所需字段，日志和审计采用最小数据原则 |

## 7. 验收标准

- 干净工作区按文档命令可启动后端并加载扩展。
- 首次商品查询会创建 `data/ozonslj.db`。
- 停止并重启后端后，SQLite 中的数据仍可读取。
- 扩展能展示商品报价并处理分页、空数据和错误。
- 没有真实 Ozon 凭据也能运行全部自动化测试。
- 代码检查和生产构建通过。
- 数据库、API、架构与开发规范文档和代码保持一致。

## 8. 里程碑

1. 基础垂直切片：健康检查、SQLite、商品报价、侧边栏。
2. 账户与工作区：凭据加密、账户验证、数据隔离。
3. 只读 MVP：库存、订单、履约单、同步和审计。
4. 受控写入：逐项引入价格或库存变更，并增加预览、确认和恢复。

## 9. 待确认事项

- 运营人员登录方式：纯本地口令、系统账户或后续云端身份。
- 首批目标市场、Ozon 区域和 FBO/FBS 覆盖范围。
- 数据刷新策略：请求时刷新、缓存优先或定时同步。
- 本地凭据加密主密钥的保管方式。
- Ozon 各业务接口的当前版本、权限、配额和错误码需在开发对应功能前从官方文档确认。
