# ozonslj 用户操作手册

> 版本：2026-08-22
> 适用范围：当前 Web/Chrome 侧边栏全部业务页面。
> 核心理念：一切尽可能自动化；系统自动处理可确定、可回放、可审计的步骤，人工只处理缺失、冲突、合规阻断和高风险决策。
> 安全原则：Client ID、Client Secret、Api-Key、Access Token 和模型 API Key 只在对应页面输入，不写入文档、截图、工单、日志或聊天记录。

## 一、统一使用原则

推荐业务顺序：

```text
登录与工作区
  → Seller/Performance 凭据验证
  → Seller 数据同步
  → 数据准备与质量检查
  → 选品与利润测算
  → Listing 与广告分析
  → 汇总报告、任务、审核与复盘
```

手册中的“自动化改进”是目标设计，不代表已经上线。自动化必须保留来源、时间、规则版本、权限、幂等、合规停止、人工审核、回读和审计；任何规划能力都不能绕过这些边界。

## 二、登录与工作区

### 1. 登录

【功能描述】使用管理员分配的邮箱和密码进入运营工作台，建立受控登录会话。

【数据来源】用户身份、角色、组织边界和工作区授权来自系统 PostgreSQL；登录限流状态来自 Redis。

【格式与字段】邮箱、密码；响应只返回脱敏用户信息和授权范围，不返回密码、密码摘要或数据库连接信息。

【作用】确认当前操作主体和权限，使后续数据读取、审核、执行和审计都能关联到明确用户。

【数据体现】登录成功后显示用户名称、当前工作区和可访问页面；失败时显示认证或限流原因。

【当前操作】输入邮箱和密码登录；连续失败时等待限流窗口，不重复尝试或共享账号。

【自动化改进】自动恢复有效会话、在过期前提示续期、按角色自动加载最小菜单；异常地点或频繁失败只生成安全告警，不自动放宽认证。

### 2. 当前店铺工作区

【功能描述】选择当前店铺工作区，限定商品、订单、广告、知识和任务的数据边界。

【数据来源】工作区及状态来自服务端；Seller 凭据只保存在后端加密存储中。

【格式与字段】工作区 ID、显示名称、状态（待验证、已连接、凭据无效、已停用）。浏览器只保存当前工作区 ID。

【作用】防止不同店铺数据串读，确保同步、分析、利润和审核都属于正确店铺。

【数据体现】左侧显示当前店铺名称和连接状态；切换后页面重新读取新工作区数据。

【当前操作】登录后核对当前店铺；状态不是“已连接”时，先进入 Seller 数据同步或凭据页面处理。

【自动化改进】自动恢复上次有效工作区、切换时取消旧请求并刷新依赖页面；工作区失效时自动阻止新同步和写入，但不删除历史事实。

## 三、基础运营

### 1. 运营总览

【功能描述】集中展示当前工作区的商品、库存、运营状态和待处理事项。

【数据来源】Seller 同步事实、任务状态、数据质量问题、分析结果和告警摘要。

【格式与字段】指标值、时间窗、同比/环比、状态、来源、更新时间、缺失项和待办数量。

【作用】帮助运营人员先发现最重要的问题或机会，再进入具体页面处理。

【数据体现】指标卡、风险状态、异常摘要和页面快捷入口；没有可信数据时显示空状态。

【当前操作】先核对工作区和数据更新时间，再查看异常与待办；数据过旧时进入 Seller 数据同步。

【自动化改进】自动选取最近完整时间窗、按利润影响排序异常、同步成功后自动刷新、将可处理问题直接关联到下一步页面。

### 2. 商品与库存

【功能描述】查看自有商品报价、价格、库存数量、仓库与库存风险。

【数据来源】Ozon Seller API 商品、价格和库存只读接口；当前工作区 PostgreSQL 历史快照。

【格式与字段】Offer ID、Ozon 商品 ID、名称、类目、价格、币种、可售库存、仓库、FBO/FBS、规格、来源和同步时间。

【作用】支撑库存监控、补货判断、选品对比、利润计算和商品异常诊断。

【数据体现】商品列表、价格、库存状态、缺货/低库存标记和详情；缺失规格明确显示待确认。

【当前操作】先完成商品与库存同步，再搜索或筛选商品；确认数据时间后查看风险，不把公开样本当作自有商品事实。

【自动化改进】定时增量同步，自动分类缺货、低库存和滞销；关联销量、利润和补货建议；规格缺失自动生成质量问题，不静默填默认值。

### 3. 运营事实

【功能描述】查看销售、库存、订单、FBO/FBS 履约和财务等运营事实。

【数据来源】Seller API 只读接口、历史同步快照和系统标准化结果。

【格式与字段】时间窗、订单号、履约号、状态、计划日期、商品行、数量、收入、费用、来源和同步时间。

【作用】形成店铺经营事实底座，用于异常、报告、利润、任务和 Agent 分析。

【数据体现】运营指标、订单/履约列表、状态时间线、费用摘要和资料不完整提示。

【当前操作】选择对应数据域和时间范围，确认同步成功及数据时间，再做趋势和异常判断。

【自动化改进】按数据域定时增量同步，自动关联订单、履约、商品和费用；识别超时、状态停滞、重复费用和结算缺失并生成待办。

### 4. 任务中心

【功能描述】追踪同步、导入、采样、分析、索引、评测和报告任务。

【数据来源】PostgreSQL 任务事实、Worker/Scheduler 执行状态和脱敏错误摘要。

【格式与字段】任务 ID、类型、状态、进度、尝试次数、计划时间、租约、错误类别、创建/完成时间和工作区。

【作用】确认后台工作是否完成，避免重复点击、遗漏失败或把未完成数据用于分析。

【数据体现】待执行、运行中、成功、部分成功、失败和需人工处理状态，以及错误摘要。

【当前操作】查看任务状态；失败时先读错误和质量问题，再决定是否安全重试，不连续创建重复任务。

【自动化改进】可恢复错误自动退避重试，不可恢复错误转人工；失败自动聚类；成功自动触发质量检查、下游刷新和完成通知预览。

## 四、知识中心

### 1. 知识问答

【功能描述】基于已发布运营知识回答项目、规则、流程和字段问题，并返回可定位引用。

【数据来源】已发布 Markdown、SQL 注释、TXT、文本 PDF、通过 OCR 门槛的扫描 PDF及版本化知识索引。

【格式与字段】问题文本、工作区/知识域、回答、引用文档、标题路径、页码/行号、版本、置信和拒答原因。

【作用】降低查文档成本，确保回答可追溯；不替代实时 Seller 经营事实查询。

【数据体现】带引用回答、证据列表、降级状态；无证据或冲突时明确拒答。

【当前操作】确认知识版本已发布后提问，逐项查看引用；无可靠依据时不把回答当作经营事实。

【自动化改进】自动识别意图与语言、拆分多意图、推荐相关操作手册；知识过期自动提示责任人和更新入口，不能通过模型猜测补齐证据。

### 2. 知识源管理

【功能描述】创建知识源、导入版本、解析切片、发布、撤回和检查索引状态。

【数据来源】项目 Markdown、数据库表/字段中文注释、TXT、SQL、PDF 和经许可的内部资料。

【格式与字段】知识源名称、来源等级、用途、文件类型、版本、指纹、语言、状态、切片数、质量结果和发布时间。

【作用】维护可检索、可版本化、可撤回的运营知识，避免模型使用无来源或过期材料。

【数据体现】知识源列表、版本时间线、解析/索引任务、质量警告和发布状态。

【当前操作】新建知识源并导入文件，等待隔离、解析、切片和索引；检查质量后发布。更新时创建新版本，不覆盖历史版本。

【自动化改进】监测文件变化并创建待发布版本；自动分类语言与文档类型；失败按安全、解析、OCR、切片和索引原因分流；发布仍受质量门禁控制。

## 五、数据准备

### 1. 数据质量

【功能描述】集中查看同步、导入、采样和关系校验产生的数据质量问题。

【数据来源】Seller/Performance 同步、搜索词导入、公开采样和系统关系规则的脱敏检查结果。

【格式与字段】规则编号、影响字段、来源、严重级别、问题说明、状态和创建/处理时间；不保存凭据或敏感原值。

【作用】阻止缺失、非法、冲突或合规阻断数据静默进入分析；质量记录不直接覆盖业务事实。

【数据体现】开放问题数、错误/警告数、规则数和问题列表；已处理问题从开放列表移出。

【当前操作】页面自动加载摘要和开放问题；修复上游原因后刷新，再标记已处理。不要只为清空列表而处理。

【自动化改进】上游完成后自动运行相关规则；自动关联影响页面和修复建议；修复后复检关闭；严重问题自动生成待办和通知草稿。

### 2. 搜索词报告导入

【功能描述】把不同来源、不同列名的搜索词报告标准化为可复用运营导入事实。

【数据来源】Ozon Seller/Performance 后台允许导出的关键词报表、团队选品/广告报表和经授权第三方工具导出文件；来源不明数据不得标记为官方事实。

【格式与字段】支持 `.xlsx` 首个工作表或 UTF-8 CSV。第一行为表头，内部字段如下：

| 内部字段 | 必填 | 格式 | 含义 |
| --- | --- | --- | --- |
| `keyword` | 是 | 非空文本 | 搜索词/关键词 |
| `search_count` | 否 | 大于等于 0 的整数 | 来源报告搜索量 |
| `conversion_rate` | 否 | `0`～`100` 或带 `%` 的百分比 | 来源报告转化率 |

可用 CSV 模板：

```csv
term,volume,rate
wireless earbuds,18400,3.8
phone case,12600,2.6
```

外部表头可通过页面映射为内部字段，例如 `term → keyword`、`volume → search_count`、`rate → conversion_rate`。

【作用】减少人工抄数，统一关键词、搜索量和转化率口径，并保留批次、文件指纹和源行追溯。

【数据体现】预览行数、前五行样本、文件指纹、校验错误和导入批次历史；重复文件显示“已复用”。

【当前操作】选择 XLSX 或粘贴 CSV → 填写字段映射 → 映射并预览 → 核对样本 → 提交导入 → 必要时加载历史。空关键词、负搜索量和非法百分比会阻断；重复关键词去重；相同指纹复用批次。

【自动化改进】提供模板下载；自动识别中俄英常见表头；记住来源映射；支持拖放、批量和定时导入；提交后自动质量检查并将有效批次送入 Explore、Listing 和广告诊断。

### 3. 竞品种子

【功能描述】维护少量、明确、可暂停的公开竞品商品页，限定研究和采样范围。

【数据来源】运营人员从获准公开访问的 Ozon 或其他批准商品页复制 HTTPS URL。

【格式与字段】HTTPS URL、规范化 URL、标题、状态（启用/暂停/阻断）、最后采样时间和停止原因；不得含登录凭据或 fragment；每工作区最多 50 个。

【作用】让公开研究可复现、可停止、可审计，避免无边界全站抓取。

【数据体现】种子列表、数量、标题/URL和状态；同一 URL 不重复创建。

【当前操作】粘贴公开 HTTPS 商品页并添加；根据研究需要启用或暂停；被阻断种子不能绕过限制重新启用。

【自动化改进】CSV 批量导入与去重；自动提取商品 ID/标题供确认；按类目/研究项目分组；长期失败或失效 URL 自动暂停并说明原因。

### 4. 公开采样

【功能描述】在请求前执行 HTTPS、robots、限流和停止策略检查，并记录允许或阻断结果。

【数据来源】已启用竞品种子和获准公开页面。当前生产重点是合规检查和 Stub 预览，尚不能描述为真实 Ozon 自动采样闭环。

【格式与字段】输入 URL、robots 是否允许、是否限流、是否停止；目标快照字段包括 URL、采样时间、标题、价格最小单位、币种、评分、评价数、图片 URL、公开属性、样本数和 `estimated=true`。

【作用】在明确范围内观察竞品公开展示变化；不能替代 Seller API 官方事实或推导全市场精确销量。

【数据体现】允许/禁止、原因代码、规范化 URL和质量问题；目标快照保留时间、范围和估算标记，原始 HTML 默认不落库。

【当前操作】输入待检查 URL，设置 robots/限流/停止状态，点击“检查并记录”；被禁止时停止，不尝试绕过。

【自动化改进】从启用种子生成计划；自动检查 robots/限流/停止；按域名低并发、退避和熔断；成功后规范化、去重和质量检查；阻断后停止请求并创建质量问题。

## 六、选品研究

### 1. 探索选品

【功能描述】按搜索热度、转化率、样本、价格和自有覆盖缺口筛选候选机会。

【数据来源】搜索词导入、公开样本、自有 Seller 商品/库存/销售事实及当前页面输入。

【格式与字段】关键词、搜索量、转化率、样本数、中位价格、现有库存/销量、机会分、覆盖缺口、缺失字段和来源。

【作用】从大量搜索词中找到值得进入 Validate 的候选，不宣称全市场精确销量。

【数据体现】候选列表、机会分、筛选状态、资料不完整提示和已保存研究结果。

【当前操作】设置最低机会分、最低搜索量和覆盖缺口等筛选条件，运行并保存结果，再进入选品验证。

【自动化改进】默认读取最新有效导入批次和公开样本，保存筛选方案；定时发现新增/下降机会并解释变化；资料不足自动转质量或补录任务。

### 2. 选品验证

【功能描述】结合成本、价格、竞争、物流和自有相似商品验证候选是否值得立项。

【数据来源】Explore 候选、Seller 自有商品、公开竞品样本、运营导入成本和版本化规则。

【格式与字段】候选 ID、目标售价、采购/到岸成本、仓库/履约、竞品样本、利润/ROI、风险、缺失项和来源版本。

【作用】把“看起来有机会”转成可解释、可复核的经营判断。

【数据体现】验证结果、利润与风险摘要、资料完整度、建议和人工确认状态。

【当前操作】选择候选，核对来源和估算标记，补充必要成本/约束，运行验证并人工确认。

【自动化改进】自动带入 Seller 相似商品、最新成本/费率和竞品快照；缺失项集中一次补录；自动生成验证清单和立项草稿，但最终立项由人工确认。

### 3. 竞争分析

【功能描述】比较目标商品、竞品种子和公开样本的价格、评价、属性和竞争强度。

【数据来源】启用竞品种子、公开快照、搜索词事实和自有 Seller 商品。

【格式与字段】商品/种子标识、样本时间、价格、币种、评分、评价数、属性、样本量、估算标记和差异指标。

【作用】解释竞争格局和目标商品的差异化空间，支撑 Validate、利润和商品决策书。

【数据体现】竞品对比、价格带、评价竞争度、属性差异、样本不足和来源说明。

【当前操作】选择候选与竞品范围，核对采样时间和样本数，再查看对比结果；样本过少时不做精确结论。

【自动化改进】自动选择同类有效种子，按日/周更新变化；异常价格、评价和内容变化生成提示；始终保留样本范围和估算属性。

### 4. SKU 利润轨道

【功能描述】同步或手动录入一个商品的多个 SKU，按版本化佣金和 FBS 物流规则计算预计贡献利润，并用实际财务费用校准。

【数据来源】Seller API 商品、价格、规格和可用佣金；运营人员到岸成本与经营假设；物流模板 CSV；Ozon 财务只读明细或实际费用 CSV。

【格式与字段】商品名称、类目、SKU、售价、到岸成本、重量、长宽高；佣金/广告/退货/支付费率；包装费；物流模板；结果包含计费重量、各项费用、贡献利润、利润率、盈亏平衡价和规则追溯。

物流模板必填字段：`template_id`、`fulfillment_type`、`warehouse_id`、`route_id`、`region_id`、`version`、`effective_from`、`volumetric_divisor_cm3_per_kg`、`max_weight_g`、`base_fee_minor`、`currency`、`source`。可选字段：`effective_to`、`additional_fee_minor`、`additional_step_g`、`fee_rate_bps`。金额使用最小货币单位，重量使用克，尺寸使用毫米。

【作用】在上架、备货或投放前判断每个 SKU 是否有利润空间；结果是推导估算，不是结算事实。

【数据体现】SKU 结果卡、贡献利润/利润率、物流费、计费重量、盈亏平衡价、负利润状态、规则版本、财务明细和对账差异。

【当前操作】点击“同步 Ozon 商品”→ 搜索、分页、多选并导入 → 核对自动带入的名称、类目、价格、规格和佣金 → 补充到岸成本/缺失项 → 配置或导入物流模板并预览 → 运行测算 → 导出结果。订单产生后选择日期同步 Ozon 财务，或粘贴实际费用 CSV 预览对账。

【自动化改进】按类目和生效时间复用佣金规则；按仓库/线路/区域选择物流版本；成本批量导入；规则缺失只集中补录一次；财务明细自动匹配订单/SKU，形成“预计—实际—规则调整建议”闭环，规则更新仍需人工确认。

## 七、内容增长

### 1. 关键词策略

【功能描述】整理核心词、长尾词、属性词和广告词，形成版本化 Listing 关键词策略。

【数据来源】搜索词导入、现有 Listing、公开竞品内容、Seller 商品属性和广告关键词指标。

【格式与字段】关键词、语言、层级、搜索量、转化率、覆盖位置、来源、状态、策略版本和冲突标记。

【作用】统一标题、属性、描述和广告使用的关键词依据，减少重复与关键词堆砌。

【数据体现】关键词分层、覆盖缺口、新增/冲突词、来源和策略版本。

【当前操作】选择商品与已准备搜索词，核对来源和语言，生成并人工调整策略。

【自动化改进】自动读取最新有效搜索词批次、现有 Listing 和广告词；标记新增、流失、重复和冲突；策略变化自动触发标题草稿和内容风险预览。

### 2. 标题草稿

【功能描述】基于商品属性和关键词策略生成多个俄语 Listing 标题候选。

【数据来源】Seller 商品属性、关键词策略、竞品公开内容、内部写作规则和模型供应商。

【格式与字段】商品/草稿 ID、标题文本、语言、关键词覆盖、规则/模型版本、风险提示和人工状态。

【作用】提高标题覆盖和可读性，同时保留原稿和人工选择权。

【数据体现】多个候选标题、关键词覆盖差异、风险和来源说明。

【当前操作】选择商品和策略，生成候选，比较覆盖与风险，选择或编辑草稿；生成不会直接修改 Ozon。

【自动化改进】自动补齐可信商品属性，生成多版本并解释差异；记录人工选择反馈；任何发布动作都必须进入内容风险和受控发布。

### 3. 内容风险

【功能描述】检查标题、属性、卖点和描述中的禁用词、缺失属性、重复和合规风险。

【数据来源】Listing 草稿、商品属性、规则词表、平台限制和版本化风险规则。

【格式与字段】草稿 ID、字段、规则编号、严重级别、问题位置、说明、建议和规则版本。

【作用】在发布前发现内容风险，避免自动生成内容直接覆盖原稿或触发平台问题。

【数据体现】按字段定位的问题列表、严重级别、建议和复检结果。

【当前操作】选择草稿运行检查，逐项处理问题；修订后重新检查，保留原稿和版本。

【自动化改进】草稿变化后自动检查；可确定问题生成一键修复预览；修复后自动复检；高风险和规则冲突必须人工处理。

### 4. 受控发布

【功能描述】把已确认 Listing 或价格变更转换为差异预览、审核请求和幂等执行命令。

【数据来源】已通过风险检查的草稿、Seller 当前值、利润线、权限和审核策略。

【格式与字段】目标商品、字段、旧值、新值、数据时间、风险、批量大小、幂等键、审核状态、执行和回读结果。

【作用】在允许自动化提高效率的同时，确保高风险外部写入可审、可停、可追踪。

【数据体现】差异预览、审核请求、执行状态、部分失败、回读差异和审计记录。

【当前操作】核对目标与差异 → 提交审核 → 有权限人员批准 → 独立执行 → 查看回读。未批准、过期、超范围或低于利润线时禁止执行。

【自动化改进】自动检查新鲜度、限制和利润线；审核通过后自动排队执行；回读失败进入人工处理。自动化只能推进流程，不能代替批准。

## 八、广告分析

### 1. 广告活动

【功能描述】通过 Performance API 只读查看广告活动、状态和基础结构。

【数据来源】已授权 Ozon Performance 服务账号和工作区广告事实。

【格式与字段】活动 ID、名称、类型、状态、预算周期、开始/结束时间、来源和同步时间。

【作用】确认广告结构和活动状态，为指标与关键词诊断提供范围。

【数据体现】活动列表、启用/暂停状态、预算摘要和连接错误。

【当前操作】先验证 Performance 凭据，再加载活动；检查状态和同步时间。当前只读，不修改活动。

【自动化改进】定时增量同步；识别新增、暂停和异常活动；Token 失效时自动刷新或生成凭据待办；任何预算修改建议进入审核。

### 2. 广告指标

【功能描述】汇总广告展示、点击、订单、销售额、花费和效率指标。

【数据来源】Performance API 报表、活动结构和 Seller 销售事实。

【格式与字段】日期、活动/商品/关键词、展示、点击、订单、销售额、花费、CTR、CVR、CPC、ACOS、TACOS、ROI和来源。

【作用】判断广告投入效率、数据完整性和异常消耗。

【数据体现】指标卡、趋势、活动/商品/词分组、异常和资料不完整状态。

【当前操作】选择时间范围并同步/加载指标，先核对结算延迟和来源，再比较表现。

【自动化改进】自动选择完整结算窗口；按日增量同步；无转化消耗、指标突变和数据延迟自动告警；建议不直接改预算或出价。

### 3. 关键词诊断

【功能描述】分析广告关键词表现、搜索词覆盖、否定词和扩词机会。

【数据来源】广告指标、搜索词导入、Listing 关键词策略和 Seller 商品事实。

【格式与字段】关键词、匹配类型、展示、点击、订单、花费、销售额、效率指标、诊断状态、建议和来源。

【作用】发现高花费低转化、缺失覆盖、否定词和扩词机会。

【数据体现】关键词分组、问题原因、建议、影响范围和资料缺失提示。

【当前操作】选择活动/商品和时间窗，查看诊断，人工确认建议；当前不自动写入关键词或否定词。

【自动化改进】自动融合导入词、Listing 和广告事实；定时生成诊断；建议按影响排序并生成写入预览，执行仍需审核。

### 4. 汇总报告

【功能描述】生成日报、周报、月报和跨销售、库存、广告、竞品的运营摘要。

【数据来源】Seller/Performance 事实、数据质量、任务、选品、利润、公开样本和 Agent 工作流。

【格式与字段】报告类型、周期、标题、指标行、异常、待办、来源、数据时间、工作流/模型版本和只读标记。

【作用】把分散页面数据转成可追溯结论和待办，支持日常复盘。

【自动化改进】定时生成日报/周报/月报；自动解释变化、去重待办并关联任务/质量问题；通知只自动生成草稿，真实发送按渠道授权。

## 九、系统工具

### 1. Performance 凭据

【功能描述】保存 Performance Client ID/Secret，获取短期 Token 并验证广告只读连接。

【数据来源】运营人员输入的 Performance 服务账号和 Ozon OAuth 响应。

【格式与字段】Client ID、Client Secret、Token 是否存在、到期时间（北京时间）、是否需要刷新和连接状态；不回显密钥或 Token。

【作用】为广告活动和指标提供与 Seller 凭据隔离的授权边界。

【数据体现】凭据存在状态、Token 到期状态、连接结果和脱敏错误类别。

【当前操作】加密保存密钥 → 获取 Token 并测试连接 → 确认状态可用。不得填写 Seller API Key。

【自动化改进】到期前自动刷新；按认证、权限、限流、网络和上游错误分类；连续失败进入冷却并生成待办，不记录上游敏感正文。

### 2. 模型供应商

【功能描述】配置嵌入、重排、回答和翻译等用途的模型供应商与优先级。

【数据来源】管理员配置、主机 Secret 中的 API Key和供应商只读健康探测。

【格式与字段】供应商 ID、名称、API 地址、模型、用途、优先级、启用状态、维度/能力、超时和凭据存在状态。

【作用】让业务逻辑不绑定单一模型，并支持用途隔离和安全降级。

【数据体现】供应商池、启用状态、优先级、用途路由和连接错误；API Key 不显示。

【当前操作】填写供应商和模型信息，加密保存凭据，启用后检查用途路由；不要使用来源不明的兼容地址。

【自动化改进】周期健康探测、失败冷却、主备切换；模型能力或向量维度变化自动阻断不兼容用途；变更后自动创建评测任务。

### 3. 模型额度

【功能描述】按供应商和用途设置日/月 Token、请求数和人民币预算，并显示用量与阻断状态。

【数据来源】模型策略配置和 PostgreSQL 脱敏用量台账。

【格式与字段】日 Token 上限、月 Token 上限、每日请求上限、月度预算 RMB、今日/本月用量、比例和正常/预警/阻断状态。

【作用】控制模型成本与调用风险，为主备降级提供预算门禁。

【数据体现】当前治理范围、正常运行、临界预警、已阻断和各供应商用途用量。

【当前操作】按用途填写上限并保存；每日用量按 Asia/Shanghai 自然日统计，月度预算单位为 RMB。

【自动化改进】70%提醒、90%严重告警、100%拒绝新预留；超限自动选择合规备用；供应商账单差异生成对账记录，不修改历史台账。

### 4. RAG 评测确认

【功能描述】运行固定评测集、查看质量指标、处理失败样例并确认知识检索发布门禁。

【数据来源】版本化评测用例、知识版本、检索策略、模型配置和评测运行结果。

【格式与字段】运行 ID、用例、状态、通过率、引用正确率、拒答、延迟、Token、失败原因、版本和人工确认。

【作用】防止知识、模型或检索变化在没有质量证据时进入生产。

【数据体现】评测进度、指标卡、失败样例、结果版本和确认状态。

【当前操作】选择评测规模和配置运行，查看失败项与指标，门禁通过后再确认发布。

【自动化改进】知识/模型/策略变化自动生成去重评测任务；失败样例自动聚类；门禁未过自动阻止发布，但人工不能直接抹去失败证据。

### 5. Seller 数据同步

【功能描述】创建商品、库存、订单、履约和财务等 Ozon 只读同步任务并跟踪状态。

【数据来源】当前工作区加密 Seller 凭据和 Ozon Seller API 只读接口。

【格式与字段】数据域、同步模式、游标/分页、水位、任务状态、数量、错误类别、开始/完成时间和数据新鲜度。

【作用】持续刷新官方私有事实，为商品、运营、利润、报告和 Agent 提供可信数据。

【数据体现】同步按钮、任务状态、处理数量、最后同步时间和脱敏错误；凭据不回显。

【当前操作】确认 Seller 凭据有效，选择数据域创建同步任务，在任务中心等待成功；失败时按错误分类处理。

【自动化改进】按数据域定时增量同步、断点续传、Token/权限预检和安全重试；成功后自动质量检查和刷新依赖页面；禁止调用商品、价格、库存、订单、广告和物流写接口。

### 6. Agent 权限

【功能描述】配置 Agent 工作流可使用的参数化只读工具和高风险门禁。

【数据来源】组织角色、工作区授权、工具目录、工作流定义和安全策略。

【格式与字段】角色/工作流、工具、数据域、允许/拒绝、风险级别、版本、变更主体和审计时间。

【作用】确保 Agent 继承用户权限，只生成分析、草稿、报告、建议和待审核请求。

【数据体现】权限矩阵、拒绝原因、变更差异和审计记录。

【当前操作】按工作流配置最小必要工具，保存前核对范围；不得授予 SQL、文件系统、凭据或外部写入能力。

【自动化改进】从角色模板生成最小权限；变更前自动差异预览；越权调用自动拒绝、告警和审计；高风险建议自动转审核请求而非执行。

### 7. 外部通知

【功能描述】配置飞书、钉钉、企业微信或邮件通知模板，并在真实发送前预览。

【数据来源】质量问题、任务、报告、告警和人工配置的渠道模板。

【格式与字段】渠道、启用状态、模板、允许占位字段、重试次数、预览内容和脱敏状态；不允许凭据或任意敏感字段。

【作用】把重要事件及时送达责任人，同时避免重复、越权或泄露通知。

【数据体现】渠道配置、模板预览、发送/失败状态和重试摘要。

【当前操作】配置模板和渠道，先预览并检查脱敏结果；未配置真实渠道凭据时保持预览模式。

【自动化改进】严重事件自动生成草稿、合并重复告警、遵守静默时段和退避；真实发送须有渠道授权，发送后自动记录回执且不保存敏感正文。

## 十、结束前检查

每次业务操作完成后确认：

1. 数据来源、时间、口径和估算标记正确。
2. 任务成功、部分成功或失败状态已明确，不把运行中结果当成完成。
3. 数据质量没有新增未处理阻断问题。
4. 高风险写入具备预览、审核、幂等、独立执行、回读和审计。
5. 自动化失败有明确原因、影响范围和恢复步骤。
6. 日志、截图、导出、文档和聊天中没有任何凭据或 Token。
