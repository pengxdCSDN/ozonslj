# 前后端代码开发规范

## 1. 通用规范

- 业务命名遵循根目录 `CONTEXT.md`，中文文档与英文代码术语保持一一对应。
- 小步提交，每个提交只解决一个完整问题；推荐 Conventional Commits。
- 禁止提交 `.env`、数据库文件、密钥、访问令牌、真实客户数据和构建缓存。
- 新行为必须有相应测试；缺陷修复必须先有可复现的回归测试。
- 不允许为了通过检查而关闭类型、Lint 或安全规则。

建议提交类型：

```text
feat: 新功能
fix: 缺陷修复
docs: 文档
test: 测试
refactor: 不改变行为的重构
chore: 工具或依赖维护
```

分支建议：`feature/<主题>`、`fix/<主题>`、`docs/<主题>`。`main` 始终保持可运行。

## 2. Python 后端规范

### 2.1 版本与风格

- Python 3.12+，使用完整类型标注。
- Ruff 负责格式和静态规则，mypy 使用严格模式。
- 行长度不超过 100；导入按标准库、第三方、项目代码分组。
- 公共类、复杂业务函数和非直观决策使用简短 docstring。
- 禁止裸 `except:`、可变默认参数和无边界重试。

### 2.2 分层依赖

```text
API → 应用 → 领域
          ↘ 基础设施适配器
```

- `api`：HTTP 协议、参数校验、依赖注入、响应转换。
- `application`：用例、权限、事务和操作编排。
- `domain`：业务模型、规则和端口，不依赖 FastAPI/SQLite。
- `infrastructure`：SQLite、Ozon HTTP、加密和日志实现。
- API 路由不得直接执行 SQL；领域层不得导入基础设施模块。

### 2.3 FastAPI

- 路由必须声明请求与响应模型。
- 查询参数给出范围限制，外部输入不可直接拼接 SQL 或 URL。
- 依赖通过 `Depends` 注入，便于 Stub 和测试替换。
- 错误转换集中处理，不把 Ozon 原始错误或凭据返回前端。
- 长任务通过同步任务模型执行，不阻塞 HTTP 请求。

### 2.4 SQLite

- 使用参数化语句，禁止字符串拼接 SQL。
- 每个操作明确连接和事务边界。
- 开启外键；写操作尽量短，避免长期持有数据库锁。
- 金额不使用浮点数；标识符不强制转换为整数。
- 表结构变化同步修改 `database/schema.sql`、数据库文档和测试。

### 2.5 Ozon 集成

- 扩展代码中禁止出现 `Client-Id`、`Api-Key`。
- 请求统一处理超时、请求编号、分页、限流、重试和脱敏日志。
- Ozon 传输模型与领域模型分离，并进行运行时校验。
- 读取默认可按错误分类重试；重要写入必须预览、确认、幂等和审计。
- 不猜测上游路径、字段、枚举、配额或弃用时间。

## 3. React/TypeScript 前端规范

### 3.1 类型与组件

- 开启 TypeScript 严格模式，禁止无说明的 `any`。
- 组件使用函数组件；组件名称 PascalCase，函数和变量 camelCase。
- 每个组件聚焦一个职责，复杂状态提取为自定义 Hook。
- API 类型集中维护，不在多个组件复制响应结构。
- 服务端数据与纯 UI 状态分离。

### 3.2 状态与请求

- 每个请求必须处理加载、成功、空数据、失败和重试。
- 请求可取消，组件卸载后不得更新状态。
- 分页游标视为不透明字符串。
- 不在 `useEffect` 中制造重复请求；稳定依赖并处理 React 严格模式。
- 错误信息面向运营人员，调试细节只进入脱敏日志。

### 3.3 界面与可访问性

- 使用语义化 HTML，表单控件必须有可访问名称。
- 键盘可操作，焦点状态清晰；不只依赖颜色表达状态。
- 正文和交互元素满足可读对比度。
- 侧边栏适配窄宽度，不产生无必要横向滚动。
- 保持中文术语与需求文档一致。

### 3.4 Chrome 扩展

- 使用 Manifest V3 和最小权限。
- 页面、内容脚本、Service Worker 之间的消息必须校验类型和来源。
- 后端操作采用固定白名单，不接受任意 URL 或请求体透传。
- 不把密钥、客户隐私或敏感响应保存到 `chrome.storage`。
- 提交前检查生产包中的清单、Source Map 和权限。

## 4. 测试规范

| 层级 | 测试内容 | 依赖 |
|---|---|---|
| 单元测试 | 领域规则、映射、错误分类 | 无网络、无数据库 |
| 集成测试 | SQLite 持久化、约束和事务 | pytest 临时文件 |
| 契约测试 | Ozon 成功、认证失败、限流、超时、畸形响应 | Mock |
| API 测试 | 路由、权限、校验、分页和错误格式 | FastAPI TestClient |
| 前端测试 | 组件状态和用户交互 | Stub API |
| E2E | 加载扩展、切换工作区、浏览和刷新 | Playwright + Stub |

测试名称描述用户可观察行为，不测试私有方法。不得在自动测试中调用真实 Ozon 账户。

## 5. 合并检查

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1
```

该命令必须完成：

- pytest
- Ruff
- mypy
- TypeScript 类型检查
- Vite 生产构建

## 6. 代码评审清单

- 功能是否符合需求和统一领域语言。
- 是否泄露凭据、客户数据或敏感日志。
- 是否存在跨工作区访问风险。
- 是否正确处理分页、空数据、限流和失败。
- 是否引入不必要权限、依赖或复杂度。
- 文档、SQL、接口定义和测试是否同步。
- 是否能在无 Docker、无真实 Ozon 凭据条件下运行。
