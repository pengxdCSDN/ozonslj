## 1. 产品定位

ozonslj 最终定位为面向自有跨境运营团队的云端 Ozon 运营系统，首期服务单一组织，不提供公众注册、SaaS 多租户计费或客户自助开通。

系统采用两个前端入口：

- Web 控制台：完整的数据管理、用户权限、店铺接入、同步、异常待办、审计、智能体和审批入口。
- Chrome Manifest V3 扩展：独立侧边栏，提供工作区切换、快捷查询、提醒、智能体快捷问答和 Web 深链接；首期不读取、不注入 Ozon 网页内容。

当前本地 SQLite 模式继续用于开发、测试、演示和个人试用；生产目标为 Linux Docker Compose 单节点、PostgreSQL 和 Chroma。

## 2. 产品目标

- 统一管理多个 Ozon 俄罗斯站跨境卖家店铺。
- 建立商品、价格、库存、订单及 FBO/FBS 履约的可靠数据采集与同步闭环。
- 优先发现缺货、价格异常、履约停滞、同步失败和待审批操作。
- 支持安全、可审计的价格和 FBS 库存变更。
- 提供利润试算、真实利润核算、商品中俄翻译和关键词挖掘能力。
- 使用 LangChain、LangGraph 和 Chroma 建立有权限边界、有记忆管理和人工审批的智能运营助手。
- Ozon 凭据、客户隐私和业务写权限始终保留在可信后端。

## 3. 统一业务术语

| 术语 | 定义 |
|---|---|
| 组织 | 使用 ozonslj 的自有运营团队；首期系统只有一个组织实例 |
| 运营用户 | 登录 ozonslj 的团队成员，与 Ozon 卖家身份分离 |
| 卖家账户 | 一套 Ozon `Client-Id` 与 `Api-Key` 代表的外部卖家身份 |
| 店铺工作区 | 一套卖家凭据对应的业务、授权、同步、审计和智能体隔离边界 |
| 数据采集与同步 | 通过可信后端调用 Ozon Seller API 获取自有店铺数据并写入本地业务库；不代表公开页面爬虫 |
| 当前状态 | 商品、价格和库存最近一次成功同步后的可查询状态 |
| 变化事件 | 价格或库存值发生变化时追加的历史事实，不保存每次无变化同步快照 |
| 异常待办 | 由确定性规则或人工创建，可分派、跟踪和解决的运营事项 |
| 操作预览 | 业务写入前固定目标、前后值、风险和有效期的待确认方案 |
| 短期记忆 | 单个智能体会话线程中的最近消息和滚动摘要 |
| 长期记忆 | 经用户确认后保存的用户偏好、工作区事实或团队原则 |
| 翻译记忆 | 经审核的商品术语与中俄对应关系，不等同于智能体个人记忆 |
| 关键词项目 | ❓建议用于保存一组关键词研究的范围、输入、版本、结果和协作状态，尚待确认 |

## 4. 用户、角色与权限

### 4.1 角色

| 角色 | 默认能力 |
|---|---|
| 管理员 | 管理用户、工作区、Ozon 凭据、系统设置、团队原则、PII 权限及高风险审批 |
| 运营员 | 在被授权工作区查询、同步、处理待办、导出脱敏数据，并按风险规则执行或申请业务操作 |
| 观察员 | 在被授权工作区只读查看业务数据，不得查看完整 PII 或执行写操作 |

- 管理员可访问组织内全部工作区。
- 运营员和观察员必须按工作区明确授权。
- API、仓储、导出、RAG、记忆和智能体工具必须复用同一工作区授权边界。

### 4.2 登录与会话

- 首期采用账号密码登录，由管理员创建、禁用和重置账号，不开放公众注册。
- 会话最长 12 小时，管理员可以撤销用户全部会话。
- 查看完整 PII、管理 Ozon 凭据或批准高风险操作前必须重新输入密码。
- 首期不实现 MFA；高权限用户 MFA 列为上线后的高优先级安全改进。

## 6. 核心功能需求

### FR-001 双前端入口 — 🟡 部分完成

- Web 控制台承担完整管理和运营流程。
- Chrome 扩展承担快捷查询、提醒和智能体快捷入口。
- 两个入口共用同一云端 API、身份、权限、审批和审计体系。
- 扩展首期保持独立侧边栏，不申请读取或修改 Ozon 页面内容的权限。

当前仅扩展基础界面已完成，Web 控制台未实现。

### FR-002 卖家账户与工作区 — 🟡 部分完成

- 一套 Ozon 凭据对应一个店铺工作区。
- 只有管理员可以新增、轮换或停用凭据。
- Api-Key 提交后立即验证并加密，保存成功后永不回显原文。
- 凭据失效时暂停工作区自动同步并创建高优先级待办。
- 生产加密主密钥由宿主机高权限文件提供，只读挂载给 API 和 Worker。
- 主密钥不得进入数据库、镜像、Compose、仓库或日志。

当前工作区目录和商品隔离已实现；账户创建、凭据加密验证和权限尚未实现。

### FR-003 数据采集与同步 — 🟡 存储基础完成

> [!important] 范围边界
> “数据采集”统一指自有店铺 Seller API 数据采集与同步。本版本不建设 Ozon 公开页面爬虫、竞品采集或搜索结果采集。

首版覆盖：

- 商品与价格。
- 仓库库存。
- 客户订单。
- FBO/FBS 履约及商品明细。

同步规则：

- 新店铺首次导入最近 90 天订单与履约数据。
- 默认库存约每 15 分钟、订单与履约约每 10 分钟、商品与价格约每 60 分钟执行增量同步。
- 每天执行一次完整对账，并允许运营人员手动刷新。
- 页面默认读取 PostgreSQL，不在打开页面时直接依赖 Ozon 响应。
- 外部 HTTP 调用不得持有数据库事务，每页标准化数据使用短事务 UPSERT。
- 失败、部分成功和运行中的任务不得推进长期 checkpoint。
- 商品与库存只有在完整快照成功后才能软失效本轮未出现记录。
- 订单、履约和审计长期保留，不自动物理删除。
- 商品与库存保留当前状态；价格与库存仅在实际变化时追加变化事件。

具体 Ozon 端点、字段、状态、分页、配额和更新时间语义必须在实现各适配器前按官方 Seller API 文档重新核验。

### FR-004 异常与待办 — ⬜ 未完成

首页以异常和待办为主，关键指标摘要为辅。

- 待办支持待处理、处理中、已解决、忽略。
- 待办可分派给用户，并记录备注、处理人、创建时间和解决时间。
- 确定性异常恢复后系统自动标记已解决并保存恢复证据。
- 人工创建、人工忽略或需要业务判断的待办不得被系统静默改写。
- 首版提醒渠道为 Web 站内提醒、扩展徽标和浏览器通知，不接邮件或企业微信。

默认异常规则：

- 工作区默认低库存阈值为 5 件，商品允许单独覆盖；可用库存为 0 始终为缺货。
- 履约异常依据 Ozon 异常/取消状态、履约截止时间、同步错误和状态停滞判断。
- 活动订单或履约 24 小时没有更新时标记停滞；如果 Ozon 提供更早截止时间，则以截止时间优先。

### FR-005 价格监控 — ⬜ 未完成

价格监控只覆盖自有店铺商品，不采集竞品或类目市场价格。

- 保存商品价格变化事件、变化前后值、来源、发生时间和同步任务。
- 支持商品最低允许价和最高允许价。
- 检测价格缺失、零价、越界、短期大幅波动及调价后 Ozon 回写不一致。
- 默认当商品 24 小时内价格变化超过 5% 时生成异常待办。
- 商品可覆盖或关闭波动阈值。
- 正常变化历史与异常待办分离，避免任何变化都产生噪声告警。

### FR-006 受控价格与库存操作 — ⬜ 未完成

只读闭环稳定后，首批开放价格和 FBS 库存写入；履约推进和取消继续只读。

通用流程：预览 → 风险计算 → 明确确认/审批 → 执行 → Ozon 回读对账 → 审计。

- 操作预览有效期为 15 分钟。
- 执行前重新校验当前值、权限、目标集合和风险等级；基线变化则旧预览失效。
- 运营员调价自批上限：单次不超过 10 个商品，每项相对当前价变化不超过 ±5%。
- 运营员库存自批上限：单次不超过 10 个商品，每项增加不超过 20 件。
- 库存清零、超限或其他高风险操作转管理员审批。
- 批量操作逐项记录；部分成功时不自动补偿已成功项目，只对失败项生成新预览后重试。
- 人工界面与智能体必须调用同一业务命令和审批规则。

### FR-007 客户隐私 — ⬜ 未完成

- 保存业务所需的完整收件信息时必须字段级加密，界面默认掩码。
- 管理员和被单独授予 PII 权限的运营员可在授权工作区按需解密。
- 每次查看完整 PII 必须选择或填写用途并记录审计。
- 观察员不得查看完整 PII。
- 完整 PII 不得进入日志、Chroma、智能体长期记忆或外部模型上下文。
- 订单完成 180 天后不可逆匿名化姓名、电话和详细地址；订单业务事实与审计继续保留。

### FR-008 数据导出 — ⬜ 未完成

- 支持商品、库存、订单和履约的 CSV/XLSX 导出。
- 导出按当前筛选、工作区授权和行数限制生成。
- 默认排除完整 PII，不提供完整 PII 导出。
- 记录发起人、工作区、筛选范围、结果和下载时间。

### FR-009 利润计算器 — ⬜ 未完成

利润计算器同时支持场景试算和真实数据自动带入。

- 用户可从商品进入计算器，自动带入当前售价、已知 Ozon 费用和已维护成本。
- 用户可临时修改参数进行情景模拟，临时参数不得覆盖正式成本数据。
- 完整贡献利润包含：采购成本、头程、Ozon 佣金、平台物流、末端费用、税费、广告分摊、退货损耗及其他可配置成本。
- 展示收入、各成本项目、利润额和利润率，并标明预计值、实际值和缺失数据。
- 订单产生时按订单日汇率计算预计利润。
- Ozon 结算完成后按结算日汇率及实际平台费用生成实际利润。
- 预计利润和实际利润均保留，不相互覆盖。
- 每次正式计算保存公式版本、汇率来源、汇率日期和汇率值，保证可复算。
- 系统维护每日汇率，试算允许手工覆盖。
- 采购与头程成本支持标准 CSV/XLSX 批量导入和有权限用户人工维护。
- 成本记录保存版本、生效时间、币种、来源和审计。

Ozon 费用、结算和分析字段必须在财务适配器实现前按官方文档核验；缺失数据不得用模型虚构。

### FR-010 商品中俄翻译 — ⬜ 未完成

首版覆盖商品标题、描述、卖点和属性建议的中文与俄语互译，不包含客服聊天和系统界面国际化。

- 使用可配置的 OpenAI 兼容 LLM。
- 翻译结合品牌词、类目术语、禁用词和团队表达原则。
- 展示原文、译文、模型版本、术语命中和风险提示。
- 翻译结果默认是草稿，必须经人工确认。
- 保存原文、译文、语言、商品、模型版本、审核人和版本历史。
- 经确认的术语对可提议加入团队翻译记忆，管理员审核后复用。
- 翻译记忆与智能体个人长期记忆分开治理。
- 首版只支持复制和导出，不直接更新 Ozon 商品。
- 后期若开放发布，必须先核验 Ozon 商品编辑接口，并执行差异预览、审批和审计。

### FR-011 关键词挖掘 — ⬜ 未完成

首版数据来源：

- 自有商品标题、描述、属性和已批准翻译。
- 自有订单、销售和转化等可用业务表现。
- 经官方文档核验后，Ozon Seller API 确实能够提供的搜索或分析指标。
- 用户导入的 CSV/XLSX 种子词或补充词表。

本版本不采集 Ozon 公开搜索联想、竞品标题或搜索结果页，也不接入第三方关键词服务。

输出要求：

- 候选俄语关键词、标准化形式和来源。
- 按主题与搜索意图聚类。
- 分别展示语义相关性、自有商品覆盖、订单/转化贡献及官方可用热度指标。
- 缺失维度标记为“未知”，不得生成伪造的搜索量或虚假精确综合分。
- 建议适用商品，以及标题、卖点或描述中的推荐位置。
- 结果不得自动修改商品内容；后续可进入翻译或内容草案流程。

#### ❓待确认：关键词项目管理

建议按工作区、类目或商品组建立关键词项目，并保存：

- 种子词与数据来源。
- 运行时间、算法/模型版本和筛选条件。
- 候选词、评分证据和聚类。
- 待评估、已采用、已排除等状态。
- 负责人、备注和关联商品。
- CSV/XLSX 导出记录。

该建议尚未得到最终产品确认，不作为实施承诺。

## 7. 智能运营助手与 RAG

### FR-012 智能体工具 — ⬜ 未完成

- 智能体只能调用预定义、类型化、有权限边界的业务语义工具。
- 禁止模型生成或执行任意 SQL，禁止直接修改数据库，禁止透传任意 Ozon API 路径。
- 首版支持业务查询、汇总、异常解释、触发授权工作区同步以及生成价格/库存操作草案。
- 实际写入复用 FR-006 的风险分级、人工确认和审计。
- Web 提供完整会话、引用、记忆和审批；扩展提供快捷提问、异常解释和 Web 跳转。
- 外部模型只接收完成当前问题所需的最小化脱敏字段或聚合结果。

### FR-013 RAG 知识库 — ⬜ 未完成

- Chroma 保存 Ozon 官方文档、ozonslj 项目文档和内部运营 SOP。
- 实时商品、库存、订单、履约和财务事实只从 PostgreSQL 业务工具查询，不写入向量库。
- 文档先进入待审核区，管理员审核发布后才可检索。
- 保存来源、版本、更新时间、内容哈希、可见范围和回滚信息。
- 检索执行组织、工作区和权限过滤。
- 回答展示来源；资料过期、缺失或冲突时提示不确定性。

### FR-014 短期与长期记忆 — ⬜ 未完成

短期记忆：

- 每个对话线程独立保存最近消息和滚动摘要。
- 会话正文保留 90 天，之后删除。
- 新线程只加载有权访问的长期记忆，不自动拼接旧聊天。

长期记忆：

- 支持用户、工作区和团队三级范围。
- 类型至少包括用户偏好、工作区事实和团队原则。
- 智能体只能自动提出候选记忆，展示类型、规范化内容、范围和来源；用户确认后才能保存。
- 团队原则还需管理员确认。
- 团队原则高于工作区规则，工作区规则高于个人偏好。
- 事实按来源、证据和有效期判断；冲突无法自动解决时必须提示并请求确认。
- 用户可查看、更正、停用或删除自己有权管理的记忆。
- 凭据、完整 PII、临时数据及未经核实的模型推断禁止进入长期记忆。
- 工具调用、审批和脱敏审计摘要长期保留。

## 8. 云端部署与数据架构

### FR-015 Linux Docker Compose 单节点 — ⬜ 未完成

- 一台 Linux 服务器运行反向代理、Web/API、后台 Worker、PostgreSQL 和 Chroma。
- 外部连接使用 HTTPS 和应用身份认证。
- PostgreSQL、Chroma 和应用数据使用持久化卷。
- 服务提供健康检查、启动依赖、重启策略、日志限制、备份和升级回滚说明。
- 首期目标容量：不超过 20 名用户、20 个 Ozon 店铺和约 100 万条订单/履约记录。
- 云端 PostgreSQL 从空业务库开始，只迁移必要的非敏感配置。
- Ozon 凭据重新录入验证，业务数据从 Ozon 重建，Stub 数据不迁移。

### FR-016 备份与恢复 — ⬜ 未完成

- 每日创建服务器本地备份，保留最近 7 个日备份和 4 个周备份。
- 升级前额外创建手动备份。
- 定期执行可验证的恢复演练。
- 恢复目标为 RPO 24 小时、RTO 4 小时。
- 本地备份只能防误删、迁移失败和部分卷损坏，不能防服务器整机、系统盘或机房故障。
- 异机加密备份列为上线后的高优先级运维改进。

## 9. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-001 | 凭据安全 | Ozon 凭据不进入浏览器存储、扩展包、日志、URL、截图、测试数据或模型上下文 |
| NFR-002 | 工作区隔离 | API、数据库、导出、RAG、记忆和智能体工具全部显式校验工作区授权 |
| NFR-003 | PII 安全 | 完整 PII 字段级加密、默认掩码、按需解密、访问审计和180天匿名化 |
| NFR-004 | 可追溯性 | 同步、告警、导出、利润、翻译、关键词、智能体和业务写入均保存来源与版本 |
| NFR-005 | 模型安全 | 模型输出不是授权；外部模型只接收最小化脱敏数据；提示注入不能改变权限和审批 |
| NFR-006 | 金额精度 | 业务金额使用最小货币单位整数；汇率和计算精度可复算，不使用二进制浮点保存财务事实 |
| NFR-007 | 时间 | 数据库存 UTC；页面、日报、筛选和提醒默认使用 `Asia/Shanghai` |
| NFR-008 | 多币种 | 普通运营指标按原币种分别汇总；利润模块按已记录的每日汇率进行可追溯换算 |
| NFR-009 | 性能 | 所有列表分页；常规页面读取 PostgreSQL，不把 Ozon 实时响应置于用户请求主路径 |
| NFR-010 | 可靠性 | 读取请求按规则重试并遵守 `Retry-After`；业务写请求不在幂等语义不明时自动重试 |
| NFR-011 | 质量 | pytest、Ruff、mypy、Schema、TypeScript、Vite 和关键 E2E 检查通过 |
| NFR-012 | 中文化 | 项目说明、设计文档和运营界面使用简体中文；俄语用于商品内容与关键词业务数据 |

## 10. 里程碑

1. ✅ 当前基础：Chrome 扩展、健康检查、SQLite 商品报价、工作区选择与 Schema v3。
2. ⬜ 云端基础：Web 控制台、用户权限、PostgreSQL、Compose、凭据与 PII 安全。
3. ⬜ 真实只读闭环：商品、价格、库存、订单、履约同步及异常待办。
4. ⬜ 价格监控：变化事件、阈值、异常规则和回写对账。
5. ⬜ 受控写入：价格与 FBS 库存预览、风险审批、执行与审计。
6. ⬜ 运营工具：利润计算器、中俄翻译、关键词挖掘。
7. ⬜ 智能体：RAG、业务工具、短期记忆、长期记忆和人工审批。
8. 🔭 财务深化：Ozon 结算、费用、外部成本和实际利润分析。
9. 🔭 商品内容受控发布、MFA、异机备份及其他区域兼容。

## 11. 试运行验收

首个生产版本先连接 1 个低风险真实店铺连续试运行 7 天，通过条件：

- 无跨工作区越权、凭据泄露或 PII 泄露。
- 计划同步成功率不低于 99%。
- 抽样商品、库存、订单和履约数据与 Ozon 后台一致。
- 限流、超时、认证失败和部分失败可被识别并恢复。
- checkpoint 不因失败或部分成功错误推进。
- 异常待办能创建、分派、恢复和留痕。
- 本地备份恢复演练通过，并达到已声明的 RPO/RTO。
- 新增价格监控、利润、翻译和关键词功能必须分别通过数据来源、公式/模型版本和权限审计验收后才可标记完成。

## 12. 待确认事项

- Ozon Seller API 当前可提供的搜索分析、财务费用和商品编辑字段，需在实现前核验。
- 首期不实现 MFA、异机备份和高可用所形成的风险是否可以接受到生产扩店阶段。
