# 知识型混合 RAG 需求

> 状态：需求已确认，核心闭环已开发。本文仍是知识型混合 RAG 的专项需求基线；云端部署验收不等同于本地代码完成。

> 首期实施原则：当前系统为单用户开发云部署，优先交付知识接入、切片、混合检索、有引用回答和明确拒答。版本与治理边界用于防止未来返工，不代表首期建设企业级审批、多租户或独立运营平台；不直接支撑核心闭环的能力延后。

详细知识治理与生命周期见 [RAG 知识治理与数据模型设计](./RAG_GOVERNANCE_AND_DATA_MODEL.md)；查询、证据、评测和质量门槛见 [RAG 查询、检索、证据与质量设计](./RAG_RETRIEVAL_QUALITY.md)。

## 1. 已确认目标

首个 RAG 业务为“运营知识与数据口径问答助手”。它帮助运营人员查询规则、SOP、数据库字段语义和项目操作知识，为后续智能运营助手提供可信知识底座。

首期必须接入向量数据库，并采用 PostgreSQL 精确关键词检索与 Chroma 语义向量检索融合的知识型混合 RAG；不允许以单纯数据库注释查询或模型长上下文替代向量检索。

首期必须提供可复现、业务感知的 RAG 切片能力。切片策略按知识业务域和来源类型注册，不能使用一套固定字符参数处理所有资料；每个切片必须有足以支持过滤、引用、重建和生命周期管理的元数据。

知识摄取必须分为数据源、数据接入、数据清洗、文档切片、嵌入与索引五层。每层输出可验证的中间对象并记录处理版本；任何解析器、清洗器或切片器都不能绕过 PostgreSQL 知识目录直接写入当前可检索的 Chroma Collection。

首期检索链路必须包含查询重写和重排序精排。查询重写用于术语规范化、缩写展开和受控的多查询召回，不得改变原问题中的权限、时间、业务范围或确定性要求；精排必须在关键词与向量候选合并后执行，并只把通过来源与状态校验的证据交给回答模型。

意图识别是首期独立必备能力，必须先于查询重写和检索执行。系统需要区分知识问答、数据口径、操作导航、故障排查、实时经营事实、外部写入诉求、越权/敏感请求和无法识别的问题；不同意图使用不同知识域、检索策略、回答模板与拒答规则。

首期主意图固定为 `domain_term`、`data_definition`、`rule_or_sop`、`operation_guide`、`troubleshooting`、`realtime_business_data`、`restricted_action` 和 `unknown_or_mixed`。库存、广告、选品、Listing、数据库和部署等作为独立 `business_domain`，不继续扩张主意图枚举。

一句话包含多个诉求时必须拆分为多个意图片段并生成执行计划。每个片段分别保存原文范围、主意图、业务域、风险、置信度和路由结果；最终回答按片段逐项合并，不能用一个总体置信度掩盖局部拒答、失败或证据不足。

多意图采用局部阻断策略：危险或越界片段只阻断自身，能够安全分离的知识片段继续处理；只有输入无法安全分离、整体受到提示注入污染或权限边界不明确时才拒绝整个请求。

多意图中只有部分片段含糊时采用“部分回答 + 局部澄清”：明确且安全的片段立即处理，仅对含糊、指代不明或依赖缺失的片段提出一个最小澄清问题，不要求用户重复整轮问题。

系统采用失败关闭原则。意图无法识别、语义无法安全拆分、查询重写无法证明与原问题等价、检索没有足够证据或引用不能支持结论时，必须明确说明“不知道”“当前知识库没有可靠依据”或提出最小澄清问题，禁止猜测用户意图或补造答案。

首期不分析实时店铺数据。商品、库存、订单、销售、利润和广告等实时经营事实后续必须由参数化业务工具查询，不能复制到知识向量索引并冒充实时事实。

## 2. 已确认知识边界

首期只建设一个全局项目知识库，供当前系统内已登录运营人员共享。首期不支持工作区私有 SOP、个人知识、用户自行上传资料或按工作区定制的知识覆盖规则。全局知识仍必须经过来源确认、版本发布和状态过滤，不能因为共享而绕过知识治理。

允许进入知识库的候选来源：

- `CONTEXT.md` 中的统一领域语言；
- 当前权威需求、架构、API、数据库和开发运维文档；
- PostgreSQL 系统目录中经过校验的中文表与字段说明；
- 经人工确认并标明生效范围的内部 SOP；
- 经人工确认的 Ozon 官方资料和授权资料。

禁止进入知识库的内容：

- Seller、Performance、数据库或模型凭据；
- 买家姓名、联系方式、地址及其他个人信息；
- 未脱敏日志、完整上游响应和测试之外的真实客户数据；
- 未经确认的网页内容和模型自行生成但没有权威来源的文本；
- 需要实时查询的商品、库存、订单、销售和广告事实。

## 3. 已确认回答规则

- 每项业务结论必须绑定有效来源、来源版本和可定位片段。
- 没有可靠来源时必须明确拒答，不得使用常识补齐项目规则或 Ozon 政策。
- 来源冲突时并列展示冲突、版本和生效时间，并要求人工确认。
- 来源已过期或适用范围不明时不得输出确定结论。
- 涉及实时经营数据的问题必须说明当前知识助手不处理，并在后续转交参数化业务工具。
- 回答必须返回知识缺口、冲突和是否需要人工复核的结构化状态。

### 3.1 知识来源等级与冲突

- A 级是权威来源，包括当前权威项目文档、数据库正式中文口径和经过确认的 Ozon 官方资料；只有 reviewer/admin 可以授予或提升为 A 级。
- B 级是已确认内部知识，包括团队 SOP、排障手册和经过验证的运营流程。普通运营人员可以发布已被授予 B 级的版本，但不能自行把 C 级提升为 B/A 级。
- C 级是一般参考资料，包括运营经验、辅助说明和仍需长期验证的资料。普通运营人员创建的新来源默认是 C 级。
- 来源等级不替代版本、有效期和适用范围检查。较新的低等级来源不能自动覆盖仍有效的高等级来源。
- 在相同适用范围和时间内，A/B、B/C 冲突时优先采用较高等级，但必须记录被抑制冲突；同等级冲突不能自动择一，必须展示冲突并请求人工确认。
- 国家、FBO/FBS、系统版本、生效时间或其他适用范围不同的结论分别适用，不应误判为冲突。
- C 级来源可以辅助解释和召回，但不能单独支撑高风险操作、关键限制或确定性经营结论。
- 模型和 Agent 不能创建、提升、降低或根据语言流畅度推断来源等级。

## 4. 首期验收场景

1. 用户能够询问 FBO/FBS、工作区、同步任务、字段口径和项目操作流程，并获得带来源的回答。
2. 表名、字段名、规则编号和英文缩写能够精确命中；自然语言近义表达能够通过语义检索召回。
3. 每条结论均可定位到文档版本或 PostgreSQL 中文注释。
4. 无答案、过期资料和冲突资料不会被包装为确定答案。
5. 凭据、个人信息和禁止入库内容不会进入分块、向量、提示词或回答。
6. 跨组织、跨工作区或无权限的知识内容不会被召回。
7. 提示注入不能改变知识范围、权限、来源等级或拒答规则。
8. 同一知识版本重复索引不会生成重复切片；内容变化只重建受影响切片，撤回版本后对应切片不再被检索。
9. 新增知识在完整切片和索引成功前不可见；更新采用新版本发布和原子切换；删除或撤回后，PostgreSQL 与 Chroma 中的当前检索结果均不再返回相关切片。
10. 查询重写不能改变用户原意；精排结果必须保留关键词分数、向量分数、精排分数和最终入选原因，便于离线评测和问题复盘。
11. 意图识别错误不能导致访问实时事实、写接口或敏感知识；低置信度、多意图或越界请求必须澄清、拆分或拒答。
12. 多意图请求中的安全知识片段可以正常回答，受限片段单独拒绝；系统必须明确展示每个片段的处理状态，不能把部分成功报告为全部成功。
13. 任一模型组件不可用、超时或输出不符合 Schema 时必须执行确定性降级，并在响应中标明能力降级，不得静默伪装为完整混合 RAG。
14. 不知道就是有效终态；系统不得以回答覆盖率为目标强迫未知问题进入最相近意图或使用低相关切片生成答案。
15. 数据源新增、更新、删除和重新接入均能追溯到接入、清洗、切片、嵌入和索引版本；任一层失败不会污染当前已发布索引。
16. 中文问题能够召回语义相关的俄文和英文资料；引用保留原文及定位，必要的中文释义不能替代原始证据。
17. 表名、字段名、API 路径、规则编号、枚举和错误码保持原文，不因跨语言重写发生翻译或变形。
18. 跨语言证据的数字、日期、否定、限制条件和适用范围必须通过独立校验；无法可靠确认时明确说明不知道或要求人工复核。
19. 正常替换或过期版本的历史引用保留原文并标记历史状态；普通纠错撤回保留引用但必须显示可靠性警告和可用的替代版本。
20. 安全撤回、敏感信息或删除请求必须立即隐藏历史引用正文和原始文件，只保留非敏感审计墓碑；任何非当前版本都不得用于新问题检索。

## 5. 已确认基线与工程配置边界

- 已确认发布权限：普通运营人员可以提交并发布通过自动质量与安全门禁的普通知识；首期不强制提交人与发布人分离。
- 首期已确认支持仓库 Markdown、PostgreSQL 中文注释和 PDF；DOCX、网页归档不属于首期承诺，待独立确认。
- 各业务域使用注册、版本化切片策略；初始参数按本文和架构基线执行，后续变更通过评测与版本审计，不开放任意策略代码。
- 已确认混合检索和查询重写初始数量、超时与降级参数；具体模型由管理员供应商配置和用途级 `shadow` 评测确定，不在需求阶段绑定。
- 已确认意图初始门槛：`>=0.85` 可在规则一致时直接路由，`0.60–0.85` 需要规则/实体/业务域共同确认，`<0.60` 进入未知或澄清；风险规则优先。
- 已确认跨语言：首期支持中文问题检索中文、俄文和英文资料，并默认使用用户提问语言回答。
- 反馈闭环已确认：用户可以标记有用、错误、来源过期、答案缺失或引用不匹配，反馈不能自动改变知识或模型。
- 已确认首期质量门槛：安全硬门槛与状态完整性 100%，引用支持率 95%，精确问题 Recall@5 95%，综合 Recall@10 85%/Precision@5 70%，跨语言 Recall@10 80%，正确拒答率 95%。

## 6. 产品角色与责任

首期认证角色映射已确认：现有 `root` 用户映射为 `admin`；普通登录运营账号默认映射为 `operator`；`reviewer` 由 `admin` 显式授予和撤销；`reader` 按只读需要显式授予。角色变化由服务端保存并审计，客户端显示不能成为授权依据。

当前部署只有一名实际使用者，现有 `root/admin` 可以同时承担运营使用、知识维护、普通案例确认和试运行决策。系统仍按角色记录每次动作及当时权限，不虚构第二审核人，也不要求为满足流程创建无实际用途的账号。安全硬门槛、来源等级、提示注入、删除、引用和评测门禁不因单用户模式而放宽。

| 产品角色 | 主要目标 | 允许行为 | 明确禁止 |
|---|---|---|---|
| 知识使用者 | 获得可信运营知识和数据口径 | 提问、查看引用、继续澄清、提交反馈 | 修改知识、改变检索范围或绕过引用门禁 |
| 普通运营人员 | 维护团队日常知识 | 创建来源、上传版本、查看解析/切片预览、修正元数据，并发布通过自动门禁的普通知识 | 提升来源等级、修改策略、执行安全删除或全量重建 |
| 知识审核者 | 复核重要或有争议的资料 | 审核解析结果、切片、有效期、来源等级和发布记录 | 修改原始证据后继续沿用旧审核结果 |
| 知识管理员 | 维护策略和系统完整性 | 撤回、回滚、删除、重建索引、处理安全事件 | 通过管理操作绕过审计或保留规则 |
| 质量运营人员 | 发现知识和检索问题 | 查看脱敏追踪、分诊反馈、维护评测集 | 查看凭据、客户隐私或完整敏感模型上下文 |
| 系统管理员 | 维护受控模型供应商与用途绑定 | 配置供应商、写入/轮换密钥、连通性测试、停用配置、管理主备模型 | 回读完整密钥、跳过 `shadow` 门禁或把未审核模型直接用于线上 |

首期不强制提交人与发布人分离，普通运营人员可以发布自己提交的普通知识，但自动安全、解析、切片、索引和引用质量门禁不可跳过。提交人、可选审核人、发布人、理由、时间和版本必须分别记录。模型和 Agent 永远不能成为提交审批主体或发布人。

人工复核 SLA：普通知识争议和同等级来源冲突在2个工作日内处理；权限、安全或敏感高风险事项在4小时内首次响应、24小时内完成裁决；提示注入或危险文件误报申诉在1个工作日内处理。超时自动提醒 reviewer，高风险超时升级 admin。SLA 超时不能自动批准、发布、解除隔离或恢复内容，也不能降低证据和安全门槛。

## 7. 核心用户场景

### 7.1 术语与数据口径问答

用户询问表、字段、指标、FBO/FBS 术语或项目领域概念。系统应优先精确命中标识符，并使用来源说明补充自然语言解释。回答必须标注定义来自哪个版本、表或字段，不能把相似字段混为一谈。

### 7.2 SOP 与操作指导

用户询问如何完成某项已存在的项目操作。系统按步骤输出，并为关键前置条件、限制和异常分支分别引用。知识回答只解释操作，不自动执行写入动作。

### 7.3 故障排查

用户描述症状、错误码和环境。系统识别相关实体和条件，检索排障手册、架构和已验证故障记录，按“检查项—判断依据—下一步”组织答案。证据不足时列出已知范围并提出最小澄清问题，不能杜撰根因。

### 7.4 多意图复合问题

一句话同时包含定义、排障、实时数据或写操作时，系统拆成多个语义片段。知识片段正常回答；实时片段说明需要后续业务工具；写入或越界片段单独拒绝。最终响应逐项展示状态。

### 7.5 不知道、冲突和过期

没有证据时明确说明当前知识库不知道；多个有效来源冲突时展示冲突和适用范围；只有过期资料时不输出确定结论。三种结果都属于成功处理，不应被监控系统错误统计为服务异常。

### 7.6 知识接入与发布

普通运营人员提交资料后查看解析结构、切片和质量警告，并可发布通过自动门禁的普通知识。来源等级提升、敏感/争议资料或安全事件可以进入人工复核；系统完成非当前索引构建和验证后才能发布。任一阶段失败均不影响当前已发布知识。

### 7.7 错误反馈与修复

用户标记答案错误、来源过期或引用不匹配。质量运营人员定位根因，普通运营人员通过新版本修复并按同一门禁重新发布，随后将该问题加入回归评测。反馈不能自动训练或直接修改线上知识。

## 8. 功能需求

### FR-01 数据源治理

- 系统必须识别逻辑来源、版本、所有者、业务域、来源等级、语言、有效期和复核期限。
- 首期支持仓库 Markdown、PostgreSQL 中文注释和 PDF。
- 系统必须支持新增、暂停、恢复、替换、撤回、逻辑删除和受控物理清理。
- 相同内容重复接入必须幂等，不重复解析、切片和嵌入。

### FR-02 接入、解析与清洗

- 每种来源通过注册适配器输出统一中间对象。
- PDF 需要保留页码、阅读顺序、标题、段落、列表、表格、图片说明和版面节点。
- 首期只正式接收具有可用文本层的 PDF。扫描型 PDF 可以被检测和登记，但统一进入 `needs_review / unsupported_ocr`，不得进入清洗、切片、嵌入或发布；OCR 属于后续独立能力。
- 清洗只能规范化和标记，不得润色、猜测或补全原文。
- 凭据、个人信息、未脱敏日志、提示注入和禁止内容必须在切片前检测。

### FR-03 多策略切片

- 系统按业务域、来源类型、结构特征和检索用途路由策略。
- 支持策略发现、参数校验、预览、执行、质量检查和版本追踪。
- PDF 首期支持页级、段落级和版面块级切片，但只处理具有可用文本层的 PDF；未来 OCR 结果通过独立质量门槛后才可复用版面策略。
- 切片必须支持父子和邻接关系、页码、标题路径、原始范围、内容哈希和稳定 ID。
- 更新只重建受影响内容；撤回和删除使对应切片立即不可检索。

### FR-04 向量与关键词索引

- Chroma 向量索引是首期必需组件，PostgreSQL 提供精确/全文检索与治理过滤。
- 两种索引必须可独立诊断、融合和降级，不能隐藏某一路不可用。
- 索引必须支持幂等写入、删除、对账、版本切换和从 PostgreSQL 重建。
- 不同嵌入模型或维度不能混入同一索引版本。

### FR-05 查询理解

- 系统必须分别输出意图、实体、业务条件、风险和置信度。
- 多意图必须按原文范围拆分，并保存片段依赖。
- 指代不明、条件缺失或无法安全拆分时提出最小澄清问题。
- 意图无法识别时不得强制匹配最相近类别。
- 单一片段 `confidence >= 0.85` 且确定性规则、实体和风险结果不冲突时可以直接路由。
- `0.60 <= confidence < 0.85` 时，只有确定性规则、实体识别和业务域三者一致才能继续检索；否则提出最小澄清问题。
- `confidence < 0.60`、置信度缺失/非法或模型输出不符合 Schema 时，按识别失败处理为 `unknown_or_mixed`，不得猜测检索。
- 多意图逐片段应用门槛；只澄清低置信度片段，其他安全片段继续执行。实时事实、写操作、凭据、个人信息和提示注入规则始终覆盖模型置信度。
- 门槛是版本化服务端配置，不是领域硬编码。初始数值只用于 `shadow`，经冻结评测校准后形成进入 `pilot` 的策略版本。

### FR-06 查询重写

- 重写支持术语标准化、拼写修复、缩写展开、已审核别名和受控多查询。
- 重写不得改变权限、时间、业务模式、国家、否定、排除或确定性要求。
- 重写结果必须通过等价检查；失败时回退原问题，仍不明确则停止。
- 原始问题始终作为第一条查询保留。每个意图片段最多生成3条派生查询，整个多意图请求最多8条派生查询。
- 派生查询用途限定为术语/拼写规范化、已审核缩写/别名扩展，以及必要的中俄英跨语言表达。
- 在线重写初始超时3秒且不自动重试；失败但意图明确时仅使用原问题并标记 `rewrite_degraded`，意图不明确时不检索。
- 每条派生查询分别校验权限、时间、国家、履约模式、版本、否定、排除和确定性要求。等价性失败的查询直接丢弃，全部失败则按意图明确度决定回退或澄清。
- 表名、字段名、API路径、错误码、规则编号和枚举保持原文，不翻译、不变形。
- 数量、超时、等价规则和降级行为保存在 `query_rewrite_policy_version`；初始参数在 `shadow` 校准后才能进入 `pilot`。

### FR-06A 多轮上下文

- 对话历史只用于解析代词、省略和后续澄清，不能作为知识证据，也不能提高来源等级或证据支持状态。
- 后续问题只允许继承已经通过证据校验的实体、适用条件和 `claim_id`；模型生成但未获证据支持的文字不得成为下一轮事实。
- 每轮查询重新执行登录主体、权限、知识版本、生效期、撤回状态和风险检查，历史授权或历史引用不能替代当前校验。
- 首期默认最多使用当前会话最近6轮的脱敏结构化摘要；超出窗口、关键指代不明或店铺、国家、履约模式、时间范围不确定时，要求用户重新说明。
- 用户、工作区和会话之间严格隔离，不提供跨会话长期个人记忆。用户可明确重新开始以清空检索上下文，但不能删除依法或治理规则要求保留的脱敏审计事实。
- 历史回答只供当前用户查看，不能自动进入知识库，也不能因被重复提问、点赞或引用而转化为可信知识。

### FR-07 混合召回与精排

- 精确、全文和向量召回独立保留原始排名和分数。
- 融合不能直接相加不同尺度的分数，首期使用可解释、可复现的排名融合基线。
- 召回后必须重新验证来源状态、权限、有效期、业务域和版本。
- 系统必须执行去重、来源多样性、父子/邻接扩展和有限候选精排。
- 精排失败时使用确定性融合排序并明确降级。
- `shadow` 初始预算为：精确召回20条、全文召回30条、向量召回30条，合并去重后最多60条；RRF `k=60`。
- 完全匹配表名、字段名、API路径、错误码和规则编号时增加确定性精确信号，但不能覆盖权限、状态、有效期和来源规则。
- 相同内容哈希去重；同一父文档默认最多保留5条候选。融合后最多20条进入精排，精排后最多8条进入证据检查，并同时受上下文token预算限制。
- 多意图按片段分配候选预算，任何片段不能耗尽整个请求配额。精排降级时使用RRF顺序并将证据候选收紧到最多5条。
- 所有参数属于版本化 `retrieval_policy_version`，通过冻结评测校准后才能用于 `pilot`。

### FR-07A 受控多跳查询

- 只有问题确实存在证据依赖时才生成多跳计划；多个互不依赖的意图片段仍按并列多意图处理。
- 一个请求最多拆成3个可验证子问题，最大依赖深度2，最多执行3个检索步骤。
- 计划模型最多调用1次；若输出不符合Schema，只允许一次确定性格式修复，不能重新自由规划。
- 后续步骤只能使用前一步已经通过证据门禁的实体或结论；无证据、冲突或被拒绝结果不能作为后续事实。
- 全请求融合前候选总预算最多120条，进入精排最多30条，最终证据最多10条，并同时受上下文token和总时间预算限制。
- 达到任何预算时立即停止，返回已完成部分、未完成子问题和停止原因；不能为了形成完整答案继续无界调用。
- 参数和计划器版本保存在 `query_plan_policy_version`，先在 `shadow` 校准。

### FR-08 证据、回答与拒答

- 每条结论必须建立独立的“声明—证据”映射，并关联真正支持该声明的引用；禁止只在回答末尾堆放无法逐项对应的来源。
- 字段定义、标识符和数据口径至少需要一条 A/B 级直接证据及精确定位；数字、日期、枚举值、规则编号和限制条件必须能在原文中精确定位，禁止推算或补全。
- 操作流程和故障处理的前置条件、操作步骤与预期结果都必须有证据；组合多个来源时，各步骤分别引用。
- 权限、安全、删除等高风险结论必须有 A 级证据，或两份相互独立且一致的 B 级证据；C 级资料不能单独支撑高风险结论。
- 不设置跨供应商、跨模型通用的固定相似度阈值。相关性阈值按意图和实际模型在 `shadow` 阶段校准并版本化，同时始终执行结构化证据规则。
- 无证据、低相关、冲突、缺少适用条件、过期、越界或引用不支持时删除结论、拒答或请求确认；部分子问题有充分证据时只回答已证实部分，其余明确标记“不知道”或需要澄清。
- 回答必须展示逐意图片段状态、知识缺口、冲突和降级信息。
- 知识 RAG 不得查询实时店铺事实或执行写操作。

### FR-09 反馈和复盘

- 用户可以提交有用、错误、过期、缺失和引用不匹配反馈。
- 系统保存足够的脱敏查询链路，支持定位解析、切片、召回、精排或生成问题。
- 修复后的典型问题应进入冻结回归集。
- 反馈不能直接改变知识、权重、提示词或模型。
- 系统支持从已发布 A/B 级知识、数据库中文说明、API 契约、SOP 和已确认故障记录生成评测案例草稿。AI 可以生成问题、语言/拼写/多意图/攻击变体、意图、实体、适用条件、期望状态、候选声明、引用位置、禁止引用和拒答原因，但不能把草稿自行标记为正式案例。
- 每个草稿必须经过自动来源存在性、版本状态、引用定位、近重复和集合泄漏检查，再由有权限的人工确认。普通案例可由质量运营/业务人员确认；权限、安全和高风险案例需要 reviewer/admin 最终确认。
- 评测案例生成与执行均使用独立 `rag-worker` 离线任务、首期单并发和小批次，不在在线 API 请求内生成，不一次性加载全部案例。任务服从模型预算和服务器内存/CPU停止条件，可以暂停、续跑和幂等恢复。
- 首期至少维护400个已人工确认案例，其中160个用于校准、240个作为冻结验收集。冻结集按固定清单提供30例快速检查、120例标准回归和240例完整验收；每批最多10例，由单并发 `rag-worker` 串行执行。
- 快速、标准和完整集合都必须包含固定安全硬门槛案例。资源、预算、供应商熔断或在线服务健康不满足时暂停并保存游标；未执行、被跳过或执行错误的案例不得计为通过。

### FR-10 最小知识管理界面

- 首期必须提供知识来源列表，支持按状态、业务域和来源类型筛选，并显示当前发布版本、复核状态和最近任务结果。
- 普通运营人员可以通过界面接入仓库 Markdown、数据库中文说明和带文本层 PDF；界面必须在上传前后显示文件类型、大小、页数和文本层检测结果。
- 必须提供解析结构预览，包括页码、阅读顺序、标题、段落、列表、表格、图片说明和解析警告。
- 必须提供注册切片策略选择、参数说明、切片预览、标题路径、页码、token 长度、父子关系和质量警告；不能允许输入策略代码或任意类名。
- 发布前必须展示自动安全、解析、切片、嵌入和索引门禁结果。存在阻断项时禁用发布并说明原因，不能只用颜色表达状态。
- 必须支持普通知识的发布、版本替换、暂停和普通纠错撤回，并展示异步任务状态、失败原因、重试资格和当前有效版本。
- 普通运营人员必须能够查看自己的知识问答历史、引用当前状态和反馈处理状态。
- 所有异步页面状态覆盖加载、成功、空数据、失败、取消、重试和过期；窄侧边栏和 Web 宽屏均不得产生无必要横向滚动。

首期不建设全局查询追踪分析后台、自定义策略代码编辑器、OCR 人工校对工作台、工作区私有知识权限配置、互联网抓取管理和复杂多人审批流。全局脱敏追踪首期通过受控 API 提供给质量人员和管理员；模型配置仅提供管理员必需的供应商、密钥、连通性和用途绑定能力，不扩展为完整模型运营平台。

### FR-10A 管理员模型供应商配置界面

- 首期提供仅系统管理员可见的模型供应商列表、编辑页和用途绑定页，普通运营、知识审核和质量运营角色不得读取或修改模型配置。
- 支持新增、修改、停用 DeepSeek、MiniMax、GPT 等注册适配器配置；API 地址必须符合适配器白名单和 SSRF 防护规则，不能输入任意内网或本地地址。
- API Key 是只写字段，创建、轮换或清除时执行敏感操作再确认；读取只显示配置状态、末尾掩码和最后验证时间，不返回完整值。
- 连通性测试使用固定非敏感载荷，分别验证认证、网络、模型存在性和结构化响应能力；测试成功不等于通过质量门禁。
- 嵌入、意图/重写、精排和回答生成分别绑定主模型与可选备用模型。未完成对应能力 `shadow` 评测的配置不得绑定到 `pilot/internal`。
- 删除仍被用途绑定或保留审计引用的供应商配置时必须阻断；管理员应先解除绑定并停用。配置修改采用乐观并发、CSRF、防重放和完整审计。

### FR-11 分阶段内部试运行

- 首先执行影子验证，只运行摄取、检索、离线评测、撤回、重建、降级和敏感门禁，不向普通用户展示入口。
- 影子验证通过后，服务端按用户白名单向内部使用者开放。当前单用户部署可以只包含现有 `root/admin`，由同一人承担知识维护、实际业务试用和质量反馈，不强制增加虚拟试用账号。
- 小范围试用页面必须显示“试运行”状态，支持正常问答和反馈，但不接入实时经营工具或任何写操作。
- `pilot` 的开始、结束和持续时间由 `admin` 决定，不设置强制最短天数；管理员可以在1天后申请进入 `internal`。系统必须展示已运行时长、真实用户数、真实问题数、反馈与未解决风险，要求管理员填写晋级理由并确认样本不足的残余风险。
- 冻结评测集、安全、资源和故障恢复门槛全部通过后，才对所有已登录内部运营人员开放。
- 真实问题数量不是阻止管理员晋级的硬门槛；AI 增强样本不能伪装为真实样本，两者分别统计。安全硬门槛、严重问题为0、未解决高风险反馈为0以及完整240例冻结验收仍是不可绕过的晋级条件。
- 首期不允许匿名用户、未登录公网访问或外部客户使用 RAG。
- RAG 能力由服务端功能开关控制，客户端只能读取状态。关闭 RAG 不得影响现有登录、工作区和运营功能。
- 发生敏感泄露、撤回内容仍可召回、严重引用错误、持续 Swap/OOM 或治理事实不可用时，系统必须支持立即关闭 RAG 入口和新任务。

## 9. 非功能需求

### NFR-01 安全与隐私

- 任何凭据、个人信息、完整上游响应和未脱敏日志不得进入 Chroma、提示词、查询追踪或回答。
- 查询追踪明细保留 30 天，只允许质量运营人员和高权限管理员查看脱敏链路；普通运营人员只能查看自己的回答和反馈，不能浏览全局追踪。
- 逐查询明细到期后删除，只保留 180 天聚合指标；反馈保留至结案后 180 天；安全与发布审计保留 1 年且不保存知识正文。
- 安全与发布审计以 PostgreSQL 为在线权威，并每日导出只追加的压缩 JSONL 到不由 Nginx 暴露的私有审计卷；每日生成哈希清单检测归档篡改，首期不依赖外部日志平台。只有 `admin` 可通过受控接口查询归档。
- 180 天聚合指标仅保存计数、比率、延迟、资源、模型用量和费用等非正文数据，不保存问题、提示词、引用正文或用户标识。最小指标覆盖请求状态、意图/低置信度、各召回通道、引用/冲突/未知、模型/token/费用/预算/熔断及任务积压/失败/内存/Swap/磁盘。
- 文档内指令一律视为不可信数据，不能覆盖系统规则。
- 检索、引用和原始文件访问均执行服务端授权。
- 删除必须覆盖治理数据、向量、缓存、文件和可清理日志，并保留非敏感删除账本。
- 已确认允许调用经过审核的外部模型 API，并采用可配置多供应商注册机制，支持 DeepSeek、MiniMax、GPT 等适配器及后续兼容供应商；不得把供应商、模型名称或地址编译写死在业务代码中。
- 首期内置 DeepSeek、MiniMax、OpenAI/GPT 专用适配器，并提供受控 `openai_compatible` 通用适配器。专用适配器负责各厂商真实的认证、请求、响应、错误码和限流语义；非兼容供应商不得通过猜测字段强行接入。
- 每个适配器必须声明实际支持的 `embedding`、`structured_output`、`rerank`、`chat_generation` 能力，不支持的能力不能出现在用途绑定选项。管理员可显式填写模型 ID；远程模型发现只作辅助，发现失败不能覆盖已验证配置。
- `openai_compatible` 的 API 地址只允许 HTTPS 和服务端批准域名，解析与重定向全程执行 SSRF 防护，拒绝 localhost、环回、链路本地、私网、云元数据和解析后落入禁用网段的地址。
- 每个供应商配置包含稳定供应商 ID、适配器类型、受控 API 地址、可用模型、处理区域、数据保留/训练声明、超时、限流、预算、启用状态和不透明凭据引用。API Key 不加密、不进入 PostgreSQL，只以明文保存到宿主机专用受限凭据目录；读取接口只返回是否已配置、末尾掩码和最后验证时间。
- 凭据目录位于项目目录、镜像层、`.env`、普通日志与普通备份之外，目录权限 `0700`，凭据文件权限 `0600`，由 API 与 `rag-worker` 共用的专用服务 UID 持有。Nginx、PostgreSQL、Redis、Chroma 和现有业务 Worker 不得挂载该目录。
- PostgreSQL 只保存随机生成、不可预测且不含绝对路径的凭据引用、凭据版本、末尾掩码和审计元数据。API Key 采用同目录临时文件、权限校验、落盘同步和原子重命名完成创建/轮换，失败时保留旧版本；清除和替换后旧文件不再可访问。
- 凭据文件默认不进入自动备份；文件丢失或损坏时将配置标记不可用，由管理员重新录入。不得从数据库、日志、响应、历史任务或供应商调用记录反推或恢复 API Key。
- 灾难恢复只还原供应商非敏感配置、用途绑定和“凭据曾配置”审计状态，不还原 API Key。恢复后的所有相关供应商统一进入 `credential_missing` 且禁止调用；管理员重新录入、完成非敏感连通性测试并满足熔断恢复条件后才能重新启用。
- 嵌入、意图/重写、精排和回答生成按用途分别绑定主模型与可选备用模型；只发送完成当前用途所需的最小非敏感文本。切换前必须通过能力兼容、数据策略和 `shadow` 质量门禁，不能静默切换到未批准供应商。
- 供应商返回余额不足、token/额度耗尽、硬配额、限流或计费不可用时必须归一化为稳定原因代码，立即停止无效重试，并按供应商、账户、模型和用途触发带冷却期的熔断与告警。
- 意图/重写和回答生成可以切换到已预审且通过相应用途 `shadow` 门禁的备用模型；无合格备用时分别回退确定性规则/原问题，或返回已验证证据摘要与暂不可用状态。
- 首期每个模型用途只允许一个主模型和一个备用模型，单次请求最多自动切换一次；禁止继续遍历第三个供应商，以免形成无界延迟、重复计费和难以复盘的结果漂移。
- 精排不可用时回退可复现的 RRF 融合并收紧证据上限。查询时的嵌入模型不得直接切换到与当前 Chroma 索引不同的向量空间；没有同一嵌入配置的可用端点时，只执行 PostgreSQL 精确/全文检索并标记语义检索降级。
- 摄取阶段嵌入额度耗尽时任务进入可恢复等待/失败状态，不发布半索引；恢复原嵌入配置后幂等续跑。若要迁移嵌入模型，必须创建新索引版本并完整重嵌入、校验和原子切换。
- 每个供应商/账户配置管理员可设置每日与每月 token 和估算费用预算；每个用途另设单请求最大输入 token、最大输出 token 和模型调用次数。金额和 token 上限属于运行配置，不在领域代码中写死。
- 预算使用 PostgreSQL 原子预留与调用后结算，达到 70% 发送提醒、90% 发送严重告警、100% 硬停止新调用。并发、重试、主备切换和重复请求都必须先占用预算，不能通过竞态超额。
- 主模型达到硬预算后仅可切换到仍有预算且通过门禁的唯一备用模型；主备均无预算时执行该能力的确定性降级。嵌入摄取接近或达到硬预算时停止领取新批次，保留已完成批次和幂等进度，不发布不完整索引。
- 费用按版本化供应商定价进行估算，响应和报表明确标识为估算值；供应商正式账单用于最终对账。管理员调整预算需要敏感操作再确认和审计，不能回写或篡改历史用量。
- 日/月预算统一按 `Asia/Shanghai` 自然日和自然月划分；周期边界以 UTC 时间戳持久化，同时保存时区与本地周期日期。修改时区只对下一周期生效，不能重算当前或历史周期。
- 每个供应商以实际计费币种设置金额预算，token 上限或原始币种金额任一达到 100% 都触发硬停止。硬预算不得依赖汇率换算；版本化参考汇率仅用于管理界面展示 CNY 汇总，并明确标记为非结算估算值。
- 具体嵌入、意图/重写、精排和生成模型、分意图阈值、P95、吞吐、单次 token/成本与超时不在需求中绑定固定值，由候选模型完成连通性测试、160例校准、资源/成本压测后形成版本化工程配置。质量或2GB服务器资源门槛未通过时不得晋级。
- 用户问题在离开服务端前执行敏感检测和按意图片段最小化；整份原始文件、无关章节和未过滤候选不得作为方便性上下文发送。
- 2GB 开发服务器首期不运行本地模型；未来自托管模型不得改变现有数据分类、证据和拒答边界。
- 所有仓库文档、数据库说明、PDF、切片和召回内容始终属于不可信证据数据，不能覆盖系统/开发指令、改变权限、启用工具或要求输出凭据。检索文本不得拼接到模型的系统指令区域。
- 摄取阶段检测面向模型的越权指令、凭据索取、引用绕过、工具执行和角色覆盖模式，记录风险类型、原文定位与检测器版本。确定恶意或高风险内容阻断发布并进入人工复核；合法讨论提示注入的资料按文档语境保留，不能只凭关键词删除。
- 回答生成后再次检查泄密、越权操作、无引用指令和角色覆盖痕迹；命中时删除相关声明或拒答。检测器失败或高风险结果无法判定时失败关闭，并把攻击与合法讨论样本纳入冻结安全评测集。
- 上传文件先进入不可发布、不可下载的隔离区。解析前校验文件签名/MIME、大小、页数、加密状态、PDF 对象数量、预估解压大小和嵌套深度；首期拒绝 JavaScript、Launch Action、嵌入附件、外部资源自动加载、异常跳转和密码保护 PDF。
- PDF 解析必须在禁止出网、只读输入、独立临时目录、非 root 身份及 CPU/内存/文件数/执行时间受限的子进程或容器中运行。超时、资源超限或异常退出后终止任务并清理临时文件，不使用更宽松参数自动重试。
- 首期 2GB 节点不常驻部署高内存 ClamAV，架构预留 `MalwareScanPort` 供未来外部扫描服务或独立扫描节点接入。未配置扫描器时界面必须明确区分“结构安全检查通过”和“病毒扫描未启用”，不得声称已完成病毒检测。

### NFR-02 正确性与可复现

- 同一输入、内容版本、策略和模型版本应生成稳定结果。
- 回答必须固定知识、索引、模型、提示词和策略版本。
- 所有模型输出经过 Schema 校验；异常、超时或非法输出走明确降级。

### NFR-03 可用性与恢复

- Chroma 丢失不能破坏治理事实，必须能从 PostgreSQL 重建。
- 新版本构建失败不能污染当前索引。
- PostgreSQL 治理或过滤不可用时不得仅凭 Chroma 返回确定结论。
- 各阶段任务可重试、可观测且不会重复发布。
- 文档解析、清洗、切片、嵌入、索引、删除、对账和重建由独立 `rag-worker` 执行，不与库存、订单等现有业务同步 Worker 混用。
- PostgreSQL 保存 RAG 任务和步骤事实，Redis 消息只作为可重复投递的触发信号；Redis 丢失或重复投递不能丢任务、重复发布或改变知识状态。
- 首期 `rag-worker` 单并发，解析和嵌入阶段不得并行叠加内存峰值。RAG任务可暂停或延迟，不能挤占核心 API 和现有同步任务。
- `rag-worker` 不挂载 Seller、Performance 或数据库管理类凭据；`disabled` 模式仍允许安全撤回、删除和索引清理。
- 首期只缓存公开、非敏感且可重建的知识侧派生产物，例如已发布切片 embedding、token 数和确定性术语规范化结果；不缓存最终自然语言答案、完整用户问题、查询 embedding、意图/重写模型输出、完整提示词或供应商原始响应。
- 缓存键必须包含知识/索引版本、策略版本、模型或 `embedding_profile_id` 和权限范围。发布替换、撤回、安全删除、权限变化或策略/模型升级必须主动失效相关缓存，不能只依赖 TTL。
- 供应商 prompt cache 只有在其数据保留、训练和隔离政策通过审核后才能按用途启用，并照常进入 token/费用台账；缓存命中不能绕过预算、审计或证据校验。

### NFR-04 性能与资源

- 当前 2GB 开发服务器不进行镜像和模型本地构建。
- 离线解析、切片和嵌入与在线查询隔离并限制并发、内存和超时；后续 OCR 上线时必须使用独立资源预算，不得默认占用首期在线服务预算。
- 每次查询限制重写数、候选数、精排数、上下文和模型调用数。
- 持续 Swap、OOM 或明显影响核心 API 时阻止上线。
- 首期单个 PDF 最大 25 MiB、最大 300 页，一次请求只上传一个文件；同一用户最多同时运行一个 PDF 解析任务。
- 私有卷使用率达到 70% 告警，达到 85% 停止新上传；查询、撤回、安全删除和清理仍必须可用。
- 首期知识原文件私有卷目标配额10 GiB，审计归档卷目标配额2 GiB。部署检查可按实际可用磁盘下调知识卷，但不得低于5 GiB；低于该值阻止启用 PDF 接入，不能挤占 PostgreSQL、Redis 或系统盘安全空间。
- 当前有效版本原文件持续保留；正常替换、过期或普通纠错撤回后保留 30 天；安全撤回、敏感信息和删除请求立即进入高优先级清理。
- 普通删除在24小时内完成派生文件和索引清理。安全撤回、敏感信息或用户删除请求立即阻断检索，15分钟内清除在线缓存和向量，4小时内完成原文件及可清理日志物理删除；备份残留按删除账本传播，最迟随7个备份保留点到期消失。
- 私有卷每日备份一次并保留最近 7 个备份点；备份执行同等访问控制，并纳入安全删除账本。

### NFR-05 可维护性

- 领域层不依赖 FastAPI、Docling、PostgreSQL、Redis、Chroma 或具体模型 SDK。
- 每个数据、策略、模型和提示词版本可追踪。
- 新增代码、SQL 和字段必须有准确中文说明，供后续 SQL-RAG 和开发检索使用。

## 10. 明确非目标

首期不包含：

- 自然语言生成任意 SQL 或让模型直接访问业务数据库；
- 实时商品、库存、订单、销售、利润和广告事实问答；
- 自动执行价格、库存、广告或其他外部写入；
- 工作区私有知识、用户自由上传和公共互联网自动抓取；
- 模型自动生成、审核或发布知识；
- 完整质量诊断后台、模型成本分析/提示词编辑等高级运营后台、OCR 校对工作台和可执行切片策略编辑器；首期仅包含受控的管理员模型供应商配置页；
- 无上限 Agent 循环、自动工具发现或任意 MCP 调用；
- 用单纯长上下文替代向量数据库；
- 仅凭模型自评判断答案正确。
- 为单用户场景建设复杂组织、多租户、多人会签、工单流转、专职审核团队或企业级模型运营平台。

## 12. 定档前决策清单

以下问题会改变产品行为，确认前保持显式待定：

1. 已确认：普通运营人员可提交并发布通过自动门禁的普通知识；首期不强制职责分离。来源等级提升、策略变更、安全删除和全量重建仍由高权限角色负责。
2. 已确认：首期支持中文问题检索中文、俄文和英文资料；回答默认使用提问语言，引用保留原文。
3. 已确认存储与容量：私有持久化卷、单文件 25 MiB/300 页、单用户单解析任务、70% 告警/85% 停传、普通撤回保留 30 天、每日备份并保留 7 个点；总卷容量仍按服务器磁盘配置。
4. 已确认：首期只正式支持带可用文本层的 PDF；扫描型 PDF 进入人工复核且不可发布，OCR 留待后续独立阶段。
5. 已确认历史引用分级展示：正常替换/过期保留并标注，普通纠错撤回保留但警告，安全撤回立即隐藏正文，物理删除只留非敏感审计墓碑。
6. 已确认追踪与保留：脱敏查询明细 30 天、聚合指标 180 天、反馈结案后 180 天、安全与发布审计 1 年；普通运营人员仅查看自己的回答与反馈。
7. 已确认试运行范围：影子验证、小范围内部白名单、全体已登录内部运营人员三阶段开放；匿名和外部用户不开放。人工复核 SLA 已按普通2工作日、高风险4小时响应/24小时裁决、误报申诉1工作日定档。
8. 已确认模型处理边界：允许向审核过的外部模型 API 发送最小化的非敏感知识和问题片段；供应商采用可配置注册机制，可接入 DeepSeek、MiniMax、GPT 等 API，各用途独立绑定模型。API Key 不加密且只写入宿主机受限凭据文件；具体账户、区域、数据保留与训练策略仍需逐配置审核。
9. 已确认首期提供最小完整知识管理界面；高级全局追踪、模型配置、OCR 校对、策略代码和复杂审批界面不属于首期。
10. 已确认 A/B/C 三级来源及冲突规则：A 权威、B 已确认内部、C 一般参考；普通运营人员不能提升等级，同等级冲突必须人工确认。
11. 已确认 RAG 采用服务端功能开关和三阶段内部试运行；触发安全、引用、撤回或资源停止条件时可独立关闭。
12. 已确认进入 `pilot` 的质量门槛：安全、引用定位、多意图状态和降级标记硬门槛 100%；引用支持率 95%；精确 Recall@5 95%；综合 Recall@10 85%/Precision@5 70%；跨语言 Recall@10 80%；正确拒答率 95%。
13. 已确认使用独立单并发 `rag-worker`，与现有业务同步 Worker 隔离队列、凭据、资源和故障域；PostgreSQL 保存任务事实，Redis 只负责触发。
14. 已确认意图三段门槛和风险覆盖规则；初始 `0.85/0.60` 用于 `shadow`，校准后以版本化策略进入 `pilot`。
15. 已确认混合检索 `shadow` 基线：精确/全文/向量 20/30/30，去重后60，RRF `k=60`，20条精排、8条证据，精排降级最多5条。
16. 已确认查询重写 `shadow` 基线：原问题保留、每片段最多3条/全请求最多8条派生查询、3秒超时不重试、等价失败丢弃、意图明确才允许降级原问题。
17. 已确认受控多跳基线：最多3个子问题/3个检索步骤、深度2、计划模型1次加一次确定性Schema修复、120候选、30精排、10证据，预算耗尽时部分返回。
18. 已确认证据充分性策略：逐声明映射证据；字段/标识符需 A/B 级直接证据，高风险结论需 A 或两份独立一致的 B，数字与限制必须精确定位；不使用跨模型统一原始分数阈值，冲突或证据不全时部分回答并明确不知道。
19. 已确认多轮上下文策略：历史只辅助理解且不能作为证据；仅继承已验证实体、条件和声明，默认最近6轮脱敏结构化摘要，每轮重新鉴权和校验知识状态，跨用户/工作区/会话隔离且不形成长期个人记忆。
